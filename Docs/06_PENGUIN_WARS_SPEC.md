# 第6弾ミニゲーム：ペンギン大戦争 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第6弾ミニゲーム。にゃんこ大戦争風の横スクロール型タワーディフェンス。ペンギンを出撃させて敵の大群を押し返し、敵の城を落とす。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 横スクロール タワーディフェンス（にゃんこ大戦争風） |
| 視点 | 横から見た視点（Side View）・横画面固定 |
| グラフィック | 2Dピクセルアート（コードで生成するペンギン） |
| プレイ人数 | 1人（ステージ 3章18ステージ。§2.1・§8）/ 2人（オンライン1対1の城攻め。§10） |
| 味方キャラ | 全50体（ペンギンのバリエーション。§5）。ステージでは最初10体から、クリアで仲間が増える（§8.6） |
| 編成 | 10体（5体×2ページ） |
| 対象プラットフォーム | Android / iPhone（PCはマウス＋キーボードで確認用・ブラウザ版） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/06_PenguinWars/`。Sceneは他のゲームと同じく `Tools > MiniGame > Rebuild PenguinWars`（`PenguinWarsSceneBuilder`）でコードから生成する。キャラのデータとドット絵も同じメニューでまとめて作り直す（§11.3）。

### 1.1 モード

| モード | 編成の決め方 | 相手 | ゴール |
| --- | --- | --- | --- |
| ステージ（1人） | 解放済みのキャラから自分で10体（編成画面。§8.7） | 定義表どおりに湧く敵ペンギンと敵の城（§8） | 敵の城を落とす。★3つ（クリア・自城HP・タイム）を集める |
| オンライン対戦 | ドラフト（3体から1体選ぶ×10回） | 相手プレイヤー | 相手の城を先に落とす（最大5分） |

* オンライン対戦はステージの進み具合（解放）に関係なく、全50体からドラフトする（友達同士で進み具合の差を出さないため）

## 2. ルール・試合の流れ

### 2.0 タイトル

メニューからペンギン大戦争を選ぶと、まずゲーム固有のタイトル画面（`PenguinWarsTitlePanel`）が出る。

* 戦場の上に半透明の幕をかけ、ロゴ「ペンギン大戦争 / PENGUIN WARS」がふわふわ揺れる。その下でランダムな5体（全50体から重複なし・開くたびに選び直す）がぴょこぴょこ跳ねる
* パレードの下にステージの★の合計を小さく出す（`★ 32 / 54`。開くたびにセーブから数え直す）
* ボタンは「スタート」（→ モード選択）・「ずかん」・「あそびかた」・「設定」・「メニューに戻る」（→ 共通のタイトル画面）
* 「ずかん」は全キャラの紹介（`PenguinZukanPanel`）。8列のマスを縦スクロールで並べ、各マスのペンギンは歩きコマで足踏みする
  * 上の数値・特性の一覧（Dropdown）と順番ボタンで並べ替え・しぼりこみ（選択肢は `ZukanListOptions`）。開くたびに「コスト・小さい順・すべて」に戻す
    * 数値の一覧: コスト・攻撃・体力・射程・速度・再生産 から選ぶ。選んだ数値で並び、各マスの左上にその数値を出す
    * 順番ボタン: 小さい順 ⇔ 大きい順。同じ値どうしは No 順
    * 特性の一覧: すべて・能力8種・範囲・役割5種 から選ぶ（押して順に回すと14回かかるので一覧にする）。当てはまらないマスは隠す
  * ステージでまだ仲間になっていないキャラは、黒いシルエット＋名前「？？？」（左上の数値も「？？？」）にして、詳細を開けない（何が仲間になるかの楽しみを残すため）。並べ替えは本当の値で並ぶ。開くたびにセーブを読み直す
  * マスを押すと詳細（`ZukanDetailPanel`）。大きい絵が「歩く → 振りかぶる → 攻撃」を繰り返し、役割・単体/範囲・コスト・再生産・体力・攻撃力・射程・速度・能力を出す
  * 中身はすべて `PenguinUnitCatalog` から実行時に読む（ずかん専用のデータは持たない）。定義表を変えて `Rebuild PenguinWars` すればそのまま反映される
* 「あそびかた」は能力・仕組みの説明（`PenguinGuidePanel`）。タイトルの幕を閉じ、右上の説明カードと下のページ送りの間に見える**本物の戦場でデモを流す**
  * トピックは 出撃と勝ち方・さかなと働きペンギン・ステージ・★（ほし）・なかま・へんせい・壁と後ろの列・城の守り方・ペンギン砲・ふっとばす・止める・遅くする・ふんばる・城キラー・大型キラー・遠距離キラー・妨害キラー・ボス・なだれ の19個。基本 → ステージモードの遊び方 → 戦い方 → 能力 → ステージの仕掛けの順に並べる（最初のページで何をすれば勝ちかが分かるように）。説明文と出撃の台本は `GuideTopics`（コード）に1か所でまとめる
  * なだれのデモは本番（25〜60秒・中央）だと待ちきれず画面にも映らないので、短い間隔・画面に入る位置で起こす（`BattleRunner._demoAvalanche*`）
  * ボスのデモは「敵の城を叩くとボスが出る」を見せるため、戦場を短く（`_demoBossFieldLength` = 14）して敵の城を画面に入れ、城HPが `_demoBossCastleRatio`（98%）を下回るときょだいペンギンがボスとして出る。WARNING・カメラ寄り・警報も本番と同じものが毎ループ出る（`GuideTopic.WithBoss`）
  * デモ係（`GuideDemoDirector`）が台本どおり `BattleRunner.SpawnDemoUnit` でユニットを好きな位置に出し、10秒ごとに `InitializeDemo` で作り直してループする
  * デモは両方とも本物の城（HP は `BattleRunner._demoCastleHp`）で、確率の能力は毎回発動する（`BattleSettings.AlwaysProcAbilities`）。デモ中は `BattleRunner.World` が null を返すので出撃ボタン・さかな表示・キー操作は反応しない
  * 説明文の数値は手書き。能力の確率・倍率を変えたら `GuideTopics` の文も直す
* 「設定」は BGM ON/OFF・BGM音量・SE音量（`PenguinWarsSettingsPanel`）。値は共通の `AudioManager` が `PlayerPrefs` に保存するので、ポーズ画面のスライダーや次回の起動とも同じ値になる
* BGM ON/OFF は BGM だけを止める（SE は鳴る）。OFF 中は BGM 音量のスライダーを触れない
* タイトル〜モード選択〜ステージ選択〜ドラフト〜編成発表はタイトルBGM、START! からプレイ中はプレイBGMに切り替える（ボスがいる間はボスBGM。§9）
* ステージのリザルトから「つぎのステージ」「もういちど」「ステージ選択」を押したときは、タイトルを飛ばしてその続きから始める（§2.1）

### 2.1 ステージ（1人）

```text
モード選択（ステージ / 部屋を作る / コードで参加）
  ↓
ステージ選択（章ごとに6マス。「へんせい」で編成画面 §8.7）
  ↓ マスを押す
ステージ詳細（★の条件・ベスト・出てくる敵・特別ルール・今の編成）→「しゅつげき」
  ↓
編成発表（ステージ名・特別ルール・保存した編成10体・2.0秒）
  ↓
START!（1.0秒）
  ↓
プレイ（経過時間が増える。敵は定義表どおりに湧き、敵の城を叩くとボスが出るステージもある。§8）
  ├ 敵の城HP 0 → 城が崩れる演出（紙吹雪・勝利のジングル）→ ★判定・セーブ → リザルト（STAGE CLEAR!）
  └ 自城HP 0 → 城が崩れる演出 → リザルト（GAME OVER）
```

**ステージ選択（`StageSelectPanel` / `StageNode`）**

* 1章ずつ横一列に6マス並べ、左右のボタンで章を切り替える。章の見出しは「第2章 ゆきやまの奥」（章の名前は `StageLabels`）
* マスは番号（`1-3`）と★3つ。色で「クリア済み（青）・遊べる（オレンジ）・ロック（灰＋鍵）」を分け、ボスステージ（各章の6番目）は赤く1.2倍にする
* 遊べるのは最初のステージと「1つ前をクリアしたステージ」だけ（章をまたいでも同じ。★の数は関係ない）
* 開いたときは最後に遊んだステージの章を出す。遊べる最新のマスはふわふわ上下する
* マスはひな形から実行時に作る（ステージを足しても Scene を作り直さずに済むように）
* 「もどる」でモード選択へ

**ステージ詳細（`StageDetailPanel`）**

* ステージ名・説明・★の条件3行（取った★は光る）・ベストタイム（未クリアは `--:--`）
* 出てくる敵の顔（定義の行の順に重複なし・最大8種類。ボスは枠を赤く）
* 特別ルールの1行（`StageLabels.Rules`。例: 「なだれ ／ 働きペンギン Lv3まで ／ 大型禁止」。ギミックが無ければ空）
* 今の編成10体の小さいアイコン。押すと編成画面。編成制限に当たるキャラは暗くする（何を外せばよいか分かるように）
* 「しゅつげき」で編成発表へ。出撃した時点で「最後に遊んだステージ」を保存する

**編成発表（`DeckIntroPanel`）** は、保存した編成（`DeckRules.CurrentDeck`。§8.7）をコストの低い順（同コストは No 順）に並べて出し、上にステージ名と特別ルールを出す。編成制限に当たるキャラは暗くする。

**★（`StarRule`）**

| ★ | 条件 |
| --- | --- |
| ★1 | クリアする |
| ★2 | 自城HPの割合が `SafeHpRatio`（既定 50%）以上でクリア（ちょうど50%は取れる） |
| ★3 | 経過時間が `TargetSeconds`（ステージごとの目標タイム）以内でクリア（ちょうどは取れる） |

* 3つとも1回の結果から機械的に決まり、別の遊び方（守り切る・速攻）を促す
* セーブには「過去に取った★の OR」を残す（★3 を取った後で★1 でクリアしても★3 のまま。別々の回で★2 と★3 を取ったら両方残る）
* ★は記録と見せびらかしだけで、ステージの解放には使わない（★集めを必須にすると詰まる人が出るため）

**リザルト（`StageResultPanel`）**

* クリア: タイトル `STAGE CLEAR!`。★を左から0.3秒ごとにポンと出し、今回新しく取った★は光って跳ねる。ベストタイム更新なら `NEW RECORD!` が揺れる。詳細は「ステージ名 / クリア mm:ss / 撃破 N体 / 新しい★（条件の文）」
* 初クリアで仲間が増えたら、★を出し終えた後に「なかまになった！」のカード（`UnlockRevealPanel`）を1体ずつ出す（歩きコマで足踏み・押すと次へ）。閉じた後もリザルトの右側に仲間の絵と名前を並べておく（最大4体）
* 失敗: タイトル `GAME OVER`、詳細は「ステージ名 / 撃破 N体」。★の行は出さない
* ボタン: 「つぎのステージ」（クリアして次がある時だけ）/「もういちど」/「ステージ選択」。どれもシーンを読み直し、行き先だけ static（`s_restartStageId` / `s_openStageSelect`）で渡す（試合の後片付けを書かずに済むため）。「もういちど」「つぎのステージ」は編成発表から始まる
* 共通の `ResultDialog` はボタンが2つしかないので、ステージは専用のパネルを使う（Common は変えない）

### 2.2 オンライン対戦

```text
モード選択 → 部屋を作る / コードで参加 → 接続
  ↓
ドラフト（§6。10ラウンド）
  ↓
ステージ抽選（ホストが3つから1つ。§3.4）
  ↓
編成確認（上に自分・下に相手の10体ずつ・ステージ名・3.0秒）
  ↓
START!（1.0秒）
  ↓
プレイ（残り時間が減る。最大5分）
  ├ どちらかの城HP 0 → 城が崩れる演出 → リザルト
  └ 残り0秒 → TIME UP!（1.5秒）→ 城の残りHP割合が多い方の勝ち（同じなら引き分け）→ リザルト
```

* ホストは左（青ペンギン）、ゲストは右（赤ペンギン）。各自の画面では自分が左・青、相手が右・赤に来るよう反転表示する（§10.3）
* オンライン中のポーズは試合を止めず、ダイアログだけ出す（サッカーと同じ）

### 2.3 勝敗

| 結果 | リザルトのタイトル | 詳細 |
| --- | --- | --- |
| ステージをクリア | STAGE CLEAR! | ★・クリア mm:ss・撃破 N体・新しい★・仲間（§2.1）。ベスト更新時は `NEW RECORD!` |
| ステージで失敗 | GAME OVER | 撃破 N体 |
| 対戦で勝ち | VICTORY! | 勝利！ |
| 対戦で負け | GAME OVER | 敗北... |
| 対戦で引き分け | DRAW | 引き分け |
| 相手の切断 | VICTORY! | 相手が切断しました |

* 対戦のスコア欄は「自分の名前 72% - 40% 相手の名前」（城の残りHP割合。名前は `SeatNames`）
* `DRAW` は共通の `BaseMiniGameManager.FinishGame` が対応していないので、`PenguinWarsGameManager.FinishAsDraw` で同じ手順を自前で踏む

ステージのリザルトは専用パネル（§2.1 のボタン3つ）。対戦のリザルトは共通のリザルトで、リトライ（モード選択へ）またはタイトルへ戻れる。
クリア時は城が崩れ始めたときに勝利のジングルを鳴らすので、共通の `SeId.GameClear` は鳴らさない（失敗の `GameOver` は鳴らす）。

## 3. 戦場

### 3.1 レーン

* 地面は1本の横レーン（にゃんこと同じく上下移動なし）。ユニットはX座標だけで管理する
* 戦場の長さ `FieldLength = 30`（ワールド単位）。左城 X=0、右城 X=30。一人用のステージ（18〜30。§8.1）とオンライン対戦のステージ（§3.4）は、ステージごとに短くなる
* 物理演算（Rigidbody2D / Collider）は使わず、X座標の比較だけで当たり判定・射程判定をする（オンラインで結果がずれず、処理も軽いため）
* 戦闘の時間は固定ステップ 1/30 秒（1フレーム最大5ステップ）。`Time.deltaTime` で進めるのでポーズで止まる

### 3.2 カメラ（`BattleCamera`）

* 画面に映るのは横16単位（戦場の約半分）。高さは画面比から逆算する
* ドラッグで横スクロール。PCは ←→ キーでも動く（15単位/秒）。UI の上のドラッグはスクロールしない
* 開始時は自城側を映す。城が崩れるときはその城へカメラを移す

### 3.3 城

| 項目 | 値 | 場所 |
| --- | --- | --- |
| 城HP（対戦・両者） | 5000 | `PenguinWarsBalance` |
| 城HP（一人用のステージ） | 自城・敵の城ともステージごと（§8.1） | `StageDefinitions` |

城もユニットと同じく「X座標を持つ攻撃対象」として扱う。一人用の敵の城も普通に攻撃でき、HP 0 で崩れてクリアになる。城は攻撃しない（攻撃手段は §4.4 のペンギン砲のみ）。ペンギン砲は城には当たらない。

### 3.4 対戦のステージ（オンライン対戦のみ）

ドラフト後にホストが3つから1つを抽選し、編成と一緒にゲストへ送る（`pw.deck`）。中央で押し合って城に届かないまま終わる試合を減らすため、ステージごとに「城までの近さ」「守りの強さ」を変える。あそびかたのデモは従来の戦場（長さ30・Balance の値）のまま。一人用のステージ（§8）はこれとは別の定義表を使う（なだれの仕組みは共通）。

| ステージ | 長さ | 城HP | ペンギン砲の範囲 | 特徴 |
| --- | --- | --- | --- | --- |
| こおりの小道 | 18 | 4000 | 60% | 狭く、開始すぐ押し合いになる |
| ゆきやま | 24 | 5000 | 40% | 砲が届きにくく、攻めが通りやすい |
| なだれの谷 | 28 | 4500 | 60% | 60秒ごとに中央になだれ |

* 長さは 30（Balance の `FieldLength`）より長くしない。地面・山の絵は 30＋余白までしか敷いていないため
* 数値は 1ステージ1アセット（`Data/Stages/Stage_0N_*.asset`・`PenguinStageData`）。Rebuild で無ければ作られ、既にあれば上書きしない。並び順が抽選の番号になるので、両者のビルドで揃える
* シーンは長さ30で作り、試合開始時に `BattleRunner` が右の城を動かし、山と地面に色（`Tint`）を付ける。カメラの動ける範囲も編成確認の時に合わせ直す
* なだれ（`BattleWorld.Avalanche`）
  * 戦場の 40〜60% にいるユニット全員（敵味方とも）に 150 ダメージ＋ノックバック1回。ふんばるは飛ばない。城には当たらない
  * なだれで倒れた分は撃破報酬・撃破数を誰にも入れない（巻き込まれただけで相手が得をしないように）
  * 5秒前に画面上部へ「なだれ注意！」。起きたら範囲に煙を並べ、画面揺れ・城崩れの音（専用の絵・音は作らず流用）
  * 間隔・予告・範囲・ダメージはステージのアセットで変えられる。間隔 0 ならなし
  * 一人用のステージでは間隔だけを定義表で決める（`AvalancheInterval`。範囲・予告・ダメージは `BattleSettings` の既定値＝上と同じ）

## 4. お金・生産・ペンギン砲

数値はすべて `Data/PenguinWarsBalance.asset`（`PenguinWarsBalance`）にあり、Inspector で調整できる。アセットは Rebuild で無ければ作られ、既にあれば上書きしない。

### 4.1 お金（さかな）

ペンギンらしく通貨は「さかな」。

* 開始時は 0（最初の出撃〔ペンギン 75〕まで約2.5秒）。一人用では最初から持っているステージがある（§8.4 開始さかな）
* 時間で自動的に増える ＋ 敵を倒すと増える（敵のコストの 50%）
* 上限と増える速さは「働きペンギン」のレベルで決まる

### 4.2 働きペンギン（財布レベル）

画面左下のボタン。さかなを払うとレベルが上がり、上限と増える速さが上がる（本家の「働きネコ」）。

| レベル | 上限 | 増える速さ（/秒） | 次のレベルに必要 |
| --- | --- | --- | --- |
| 1 | 600 | 30 | 80 |
| 2 | 1000 | 40 | 160 |
| 3 | 1400 | 50 | 240 |
| 4 | 1800 | 60 | 320 |
| 5 | 2200 | 70 | 400 |
| 6 | 2700 | 80 | 480 |
| 7 | 3200 | 90 | 560 |
| 8（最大） | 4000 | 100 | — |

* 最大レベルの上限は、全キャラの最高コスト（大型 3500）より大きくする（上限より高いキャラは一生出せなくなるため）
* 一人用では働きペンギンの上限レベルを決めたステージがある（§8.4）。上限に着いたらボタンは「MAX」

### 4.3 出撃

* キャラボタンをタップ → さかなが足りて再生産時間が終わっていれば、自城の前（城の中心から 1.5）に出撃
* 出せるかどうかの判定は戦闘ロジック側（`BattleWorld.CanSpawn`）にあり、ボタンの暗さと実際の出撃で同じ判定を使う（オンラインでゲストの出撃もホストが判定するため）
* 出撃後、そのキャラは再生産時間（クールダウン）中は出せない。ボタンに残り時間ゲージを表示
* 場に出せるユニットの上限は陣営ごとに 30体（スマホの処理負荷対策）。上限を超えた出撃は無視する

### 4.4 ペンギン砲

画面右下のボタン。チャージ式の城の必殺技（本家の「にゃんこ砲」）。

| 項目 | 値 |
| --- | --- |
| チャージ時間 | 40秒（開始時は0から） |
| 効果範囲 | 自城から戦場の 60% までの敵ユニット全員（城には当たらない） |
| 効果 | ダメージ 100 ＋ ノックバック1回分（§5.4。ふんばる持ちは飛ばない） |

* チャージ完了時にボタンがオレンジに光る
* オンラインでは両者が持つ。一人用の敵の城は、ステージの定義で「敵のペンギン砲」があるときだけ撃つ（§8.4）

## 5. ユニット

### 5.1 データの持ち方

数値は **定義表＋計算式** で決め、アセットに書き出す。

```text
UnitDefinitions（全50体の定義表：No・名前・役割・コスト・単体/範囲・能力・個別倍率）
  ＋ UnitStatFormula（役割ごとの基準値から体力・攻撃力・射程…を計算）
  ＋ UnitLooks（見た目パーツ。Editor）
        ↓ Rebuild PenguinWars
Data/Units/Unit_001〜050.asset（PenguinUnitData）＋ Data/PenguinUnitCatalog.asset
```

* 定義表と計算式は純C#の `Scripts/Battle/` にある（EditMode テストで「50体の数値が正」などを確かめるため）
* 生成メニューは **既存アセットも毎回上書き** する。調整は定義表で行う（アセットを Inspector で直しても次の生成・Rebuild で戻る）。スプライトの参照は触らない
* 見た目は `Editor/UnitLooks.cs` に分けている（数値と見た目のファイルが分かれ、2人で別々に触ってもぶつからないため）

| `PenguinUnitData` の項目 | 内容 |
| --- | --- |
| `No` / `DisplayName` / `Role` | 識別子 / 表示名 / 役割 |
| `Cost` | 出撃に必要なさかな |
| `Cooldown` | 再生産時間（秒） |
| `MaxHp` | 体力 |
| `Attack` | 1回の攻撃力 |
| `Range` | 射程（自分の位置から前方） |
| `AttackInterval` | 攻撃間隔（秒） |
| `Windup` | 攻撃発生までの時間（秒）。本家の「攻撃発生」 |
| `MoveSpeed` | 移動速度 |
| `IsAreaAttack` | 範囲攻撃（射程内の全員）か単体攻撃（一番前の1体）か |
| `KnockbackCount` | 倒れるまでにノックバックする回数（§5.4） |
| `Abilities` | 特殊能力（§5.3。複数可） |
| `Look` | 見た目パーツ指定（§7.2） |
| `LeftSprites` / `RightSprites` | 陣営ごとのコマ（生成メニューが書き込む） |

### 5.2 行動

```text
前進
  ↓ 射程内に敵ユニット or 敵城が入った
攻撃（Windup 待ち → ダメージ → AttackInterval 待ち）を繰り返す
  ↓ 射程内に敵がいなくなった
前進に戻る
```

* 射程は「前方距離 0〜Range」。後ろに回り込んだ敵は狙わない
* 単体攻撃の対象は「射程内で一番こちら側に近い敵」。敵ユニットと城が同じ距離ならユニットを優先
* 範囲攻撃は射程内なら城にも当たる
* 攻撃中にノックバックされたら攻撃はキャンセル

### 5.3 特殊能力（8種）

| 能力 | 効果 | 数値（`UnitDefinitions` の定数） |
| --- | --- | --- |
| ふっとばす | 攻撃が当たると確率で相手をノックバックさせる | 妨害 50% / アタッカー・大型 30% |
| 止める | 攻撃が当たると確率で相手の動き・攻撃を一定時間止める（攻撃発生待ち・硬直のタイマーも止まる） | 40%・2秒（かみさまは 25%） |
| 遅くする | 攻撃が当たると確率で相手の移動速度を一定時間半分にする | 50%・3秒 |
| 城キラー | 城へのダメージが3倍 | — |
| ふんばる | ノックバックしない（HPしきい値・ふっとばす・ペンギン砲のすべてで飛ばない） | — |
| 大型キラー / 遠距離キラー / 妨害キラー（役割キラー） | その役割のユニットへのダメージが3倍。ほかの役割・城へはふつう | — |

* 状態異常の時間はノックバック中も減る
* 遅くするの倍率（0.5）・城キラーの倍率（3）・役割キラーの倍率（3）は `PenguinWarsBalance`
* 役割キラーは、知っている同士の対戦で編成が硬直しないよう「強いキャラにも合わせれば勝てる相手」を作るためのもの。壁・アタッカーは狙う意味が薄いのでキラーなし
* 持っているのは6体（各2体。新キャラではなく既存の能力なしキャラに付けた）: 大型キラー＝おの・スナイパー、遠距離キラー＝ながあし・ゆきなげ、妨害キラー＝ハンマー・ブーメラン。遠距離・妨害は壁の後ろにいて単体攻撃では届かないので、そのキラーは範囲攻撃のキャラにする。ただし相手の遠距離は自分の射程ぶん後ろに立つので、壁が残っている間は範囲攻撃でもまず届かない（壁を崩すか、ながあしのように前へ詰めたときに効く）

> 本家の「打たれ強い」「めっぽう強い」は敵の属性（赤い敵・浮いてる敵など）が前提の能力。このゲームは敵も同じペンギン（属性なし）なので、代わりに属性がなくても意味を持つ「城キラー」「ふんばる」にした。

### 5.4 ノックバック

* 体力が「最大HP ÷ KnockbackCount」減るごとに1回ノックバックする。1回の攻撃で複数のしきい値をまたいでも1回だけ
* 0.5秒かけて後ろに 1.5 戻され、その間は動けない（ロジックは X を等速で戻すだけ。跳ねる放物線は表示側〔`UnitView`〕で付ける）
* 飛ばされている最中の追加ノックバックは無視。自城より後ろには下がらない
* 「ふっとばす」・ペンギン砲でも同じノックバックが起きる
* HP 0 ではノックバックせず、その場で倒れる（魂が昇る演出 → 削除）

### 5.5 キャラ一覧（50体）

役割ごとに分け、コスト帯で強さを揃える。数値は全キャラ共通の計算式（`UnitStatFormula`）で出し、個性は個別倍率（`StatTweak`：体力・攻撃・射程・速度・再生産）で付ける。

**役割ごとの基準値（`UnitStatFormula.Profiles`）**

| 役割 | 体数 | コスト帯 | 再生産（秒） | 体力/コスト | 火力(DPS)/コスト | 射程 | 速度 | 攻撃間隔 | 発生 | ノックバック回数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 壁 | 10 | 50〜150 | 2〜4 | 2.0 | 0.08 | 1.4 | 1.0 | 1.2 | 0.3 | 3 |
| アタッカー | 12 | 200〜600 | 6〜10 | 0.7 | 0.09 | 1.5 | 1.1 | 1.3 | 0.4 | 3 |
| 遠距離 | 10 | 400〜1200 | 8〜20 | 0.3 | 0.03 | 3.5〜5.0 | 0.8 | 2.5 | 0.6 | 2 |
| 妨害 | 10 | 300〜900 | 8〜16 | 0.6 | 0.03 | 2.2〜3.0 | 1.0 | 2.0 | 0.4 | 3 |
| 大型 | 8 | 1500〜3500 | 40〜80 | 0.8 | 0.04 | 2.0〜3.0 | 0.6 | 3.0 | 1.0 | 2 |

* 再生産・射程は「役割のコスト帯の中でどの位置か」で補間する（同じ役割なら高いほど再生産が長く射程が長い）
* 体力 = コスト × 体力/コスト（10単位で丸め）。攻撃力 = コスト × 火力/コスト × 攻撃間隔
* 範囲攻撃は火力 ×0.75、能力1つごとに体力・火力 ×0.9

**各キャラの値**

キャラごとの値はこの仕様書には書かない（定義表と二重管理になってずれるため）。正は次のコード／アセットで、ゲーム内の「ずかん」（§2.0）でも確認できる。

* 名前・役割・コスト・単体/範囲・能力・個別倍率: `Scripts/Battle/UnitDefinitions.cs`
* 計算後の数値（再生産・体力・攻撃・射程・速度…）: `Data/Units/Unit_001〜050.asset`（`Rebuild PenguinWars` で生成）
* 見た目: `Editor/UnitLooks.cs`

* 攻撃間隔・発生・ノックバック回数は役割ごとに共通（上の基準値の表）
* 大型は拡大率2（きょだいペンギンだけ3）

## 6. ドラフト（オンラインのみ）

```text
ラウンド1〜10:
  各プレイヤーに、全50体からランダムな3体を提示（自分が既に取ったキャラは出ない）
  両者が同時に1体を選ぶ（制限時間15秒。過ぎたら3体からランダム）
  両者が選び終わったら、待ち時間なしで次のラウンドへ
```

* 提示はプレイヤーごとに別々。相手と同じキャラを取っても構わない（被りあり）
* 候補は「自分が取ったキャラを除く全キャラ」から純ランダム。ランダム編成のような「壁を最低2体」の制約は付けない
* 抽選・時間計測はホストだけが行い、ゲストに提示内容を送る（乱数のずれを防ぐため）。ゲストの残り秒表示は、届いたラウンド開始を基準に自分で減らす
* 相手が何を取ったかはドラフト中は見えない。終了後の「編成確認」でお互いの10体を公開する
* 取った10体は、ドラフト終了後にステージの編成と同じくコストの低い順に並べ直して編成にする（同コストは No 順。ホストが並べてゲストへ送る）
* 候補はステージの進み具合（解放）に関係なく全50体から出す（友達同士で進み具合の差を出さないため。§8.6）
* 画面: 中央に3枚のカード（見た目・名前・コスト・役割・範囲/単体・能力）、上にラウンド数と残り秒、下に取ったキャラの一覧。選んだ後は「相手を待っています...」
* 選ぶのはクリック / タップのみ（キーボードでの選択はない）
* 提示数（3）・制限時間（15秒）は `PenguinWarsBalance`

### 7.2 ペンギンの見た目

ドット絵はコードで生成する（他のゲームと同じ方式。`Editor/Art/`）。50体を手描きせず、**基本ペンギン＋パーツの組み合わせ**で作る。1キャラに付けられるのは頭・手・背中が1つずつ。

| パーツ | ID |
| --- | --- |
| 体の形 | `basic` / `wide`（横長）/ `tall`（縦長）/ `round`（まんまる）/ `small`（ひな）/ `tower`（3段重ね）/ `robot`（四角いメカ） |
| 体の色 | `standard`（黒白）/ `ice`（水色）/ `gray` / `aurora`（紫） |
| 頭 | `helmet` / `box` / `chonmage` / `hood` / `wizard_hat` / `nightcap` / `ribbon` / `crown` / `halo` / `drill` / `slime` |
| 手に持つもの | `axe` / `glove` / `bow` / `big_snowball` / `snowball_throw` / `fish_sword` / `hammer` / `katana` / `sword_shield` / `muscle_arm` / `fishing_rod` / `cannon` / `staff` / `sniper_rifle` / `boomerang` / `fan` / `harisen` / `mic` / `balloon` |
| 背中・体のまわり | `freezer` / `rocket` / `cape_blue` / `cape_red` / `wings` / `futon` / `mawashi` / `snow_aura` / `kamakura` / `iceberg` / `aurora` |
| 乗り物・足 | `bike` / `long_legs` / `octopus_legs` / `tank` / `whale` |
| 拡大率 | 1〜3（PNG は 32x32 のまま Pixels Per Unit を 16/拡大率 にして大きく見せる） |

* 体のまわりの表現（雪・布団・まわし・かまくら）や足（ながあし・タコあし）は、背中スロットのパーツとして作っている
* パーツを足すときは `PenguinPartPatterns`（部位ごとの partial）/ `PenguinBodyPatterns` に1項目、見た目の指定は `UnitLooks` に1行足して `Rebuild PenguinWars`
* 敵（ステージの敵、対戦の相手）は同じ見た目でチーム色を赤系にした色違い（右向きは flipX）。味方は青系。虹など陣営で変わらない色もある

* 状態異常は絵に色を掛けて表す（止まる＝水色・遅い＝灰色。両方なら止まるを優先）

### 7.3 城・背景

## 8. ステージモード（1人）

画面の流れ・★・リザルトは §2.1。ここではステージの中身（定義表・敵の出方・ボス・ギミック）と、仲間の解放・編成・セーブ・検証ツールを書く。

### 8.1 ステージの定義表

ステージは純C#の定義表（`Scripts/Battle/StageDefinitions.Chapter1〜3.cs`、1章1ファイル）。アセットは作らない（キャラの `UnitDefinitions` と同じ方式。テスト・検証ツールから直接読め、2人で別の章を触ってもぶつからないため）。

* 3章 × 6ステージ = 18。各章の6番目はボスステージ（`StageDefinition.StagesPerChapter`）
* `StageDefinitions.All` の並び順が遊ぶ順。`Find(id)` / `Next(id)` / `ChapterCount` / `InChapter(chapter)`
* 1行は `new StageDefinition { ... }`（オブジェクト初期化子）で書く。キャラ No は `StageDefinitions.Units.cs` の名前付き定数（`BoxerPenguin` など）で書く
* 章の名前（こおりの海岸 / ゆきやまの奥 / オーロラ要塞）は表示だけなので `StageLabels` に置く

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `Id` / `Chapter` / `Index` / `Name` / `Description` | なし | `"1-3"`（章-番号）。セーブはこの ID で記録する（並び替えで壊れないように） |
| `FieldLength` | 30 | 戦場の長さ。30 より長くしない（地面の絵） |
| `PlayerCastleHp` / `EnemyCastleHp` | 3000 / 3000 | 自城・敵の城のHP |
| `Entries` | 空 | 敵の出方（§8.2） |
| `TargetSeconds` | 0 | ★3 の目標タイム |
| `SafeHpRatio` | 0.5 | ★2 に必要な自城HPの割合 |
| `UnlockNos` | 空 | 初クリアで仲間になるキャラ（§8.6） |
| `TintHex` | null（白） | 山と地面の色 `"#RRGGBB"`（Battle は `Color` を持てないので文字列。読めなければ白＋警告） |
| ギミックの項目 | なし | §8.4 |

### 8.2 敵の出方（`EnemySpawnEntry` / `EnemyScriptDirector`）

敵の出方は「行」の並び。1行は「条件を満たしてから `StartTime` 秒後に1体、その後 `Interval` 秒ごとに、`Count` 体まで（0 なら出し続ける）」。

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `UnitNo` | — | 出すキャラ |
| `StartTime` / `Interval` / `Count` | 0 / — / 0 | 最初の1体までの秒数 / 間隔 / 数（0 = 無限） |
| `StatMultiplier` | 1 | 体力・攻撃の倍率（出現時に1回だけかける） |
| `TriggerCastleHpRatio` | 1 | 敵の城HPの割合がこれ以下になったら始まる（1 = 最初から。にゃんこの「城を叩くと出てくる」） |
| `IsBoss` | false | ボスの行（§8.3） |

* 定義表ではヘルパーで1行に書く: `Stream(no, start, interval, mult)`（最初から出し続ける）/ `OnCastle(no, castleRatio, interval, mult, count)`（城を叩くと出る）/ `Boss(no, castleRatio, mult)`（城を叩くと1体だけ出るボス）
* 条件は一方通行（一度満たしたら戻らない）
* 1ステップ（1/30秒）に出すのは1行1体まで（間隔 0 の行で無限に湧かないように）
* 敵は味方と同じ `PenguinUnitData` を使い、さかな・再生産を気にせず湧く（`BattleSettings.RightSpawnsFree`）
* 場の上限30体を超えた湧きは捨てる（溜めない）。ただしボスの行は上限を無視して必ず出す（捨てると山場が来ないため）
* `EnemyScriptDirector` は `BattleWorld` を持たず、敵の城HPの割合だけを受け取る（テストで単体で動かすため）
* 難しさは倍率より「出てくる敵の顔ぶれ」で上げている（敵はお金を使わず湧くので、高い敵を高い倍率で出すとこちらの収入を大きく上回って誰も勝てないため）。倍率の実際: 1章 1.0〜1.3（ボスの取り巻き 2.0）/ 2章 1.0〜1.6 / 3章 0.6〜1.05

### 8.3 ボス

* `IsBoss` の行の最初の1体が出たとき `BattleEventType.BossAppeared`（`Amount` = キャラNo）が1回出る。最終ボス（3-6）のようにボスの行が複数あれば、それぞれで出る
* ボスは表示を1.3倍にし、画面上部にHPバーを出す（§7.1）
* ボス登場の演出・音は §9（WARNING の帯・カメラ寄り・画面揺れ・警報・ボスBGM）

### 8.4 ギミック

`StageDefinition` の項目で、既定値のままならギミックなし。ステージ詳細と編成発表に特別ルールとして出す（`StageLabels.Rules`。色は遊べば分かるので出さない）。

| ギミック | 項目 | 内容 |
| --- | --- | --- |
| なだれ | `AvalancheInterval`（0 = なし） | 対戦の「なだれの谷」と同じ仕組み（§3.4） |
| 開始さかな | `StartingFish`（0 = なし） | 最初から持っているさかな。上限を超えてよい（超えている間は増えず、撃破報酬も入らない。使って下回ったらまた増える） |
| 働きペンギンの上限 | `MaxWalletLevel`（0 = なし） | これより上げられない。上限でボタンは「MAX」 |
| 敵のペンギン砲 | `EnemyCannon`（null = 撃たない） | 敵の城が砲を撃つ（§4.4 と同じ効果）。下の表 |
| 編成制限: コスト | `MaxUnitCost`（0 = なし） | これより高いコストのキャラは出せない |
| 編成制限: 役割 | `BannedRoles`（空 = なし） | この役割のキャラは出せない（例: 大型禁止） |

* 開始さかな・上限レベルは `BattleSettings` で両陣営にかかる（ステージの敵はさかなを使わないので影響なし。対戦は 0 のまま）
* 編成制限は左陣営（プレイヤー）だけにかかる。保存した編成は書き換えず、そのステージだけ当たるキャラのボタンを暗くして出せなくする（`BattleWorld.IsAllowedByRules`。`CanSpawn` も同じ判定を使い、ボタンの暗さと実際の出撃をそろえる）。判定は `DeckRules.IsAllowed`（定義表のコスト・役割で判定）
* 編成画面（§8.7）は制限を知らない（どのステージ用でもない編成のため）。ステージ詳細の編成の帯と編成発表で暗く出すので、出撃前に気づける

**敵のペンギン砲（`EnemyCannonSettings` / `EnemyCannonAi`）**

| 項目 | 既定値 | 意味 |
| --- | --- | --- |
| `ChargeTime` | 30 | チャージ秒（開始時は0から） |
| `RangeRatio` | 0.5 | 敵の城から戦場のこの割合まで届く |
| `Damage` | 150 | ダメージ（＋ノックバック1回。ふんばるは飛ばない） |
| `MinTargets` | 3 | 範囲内にこの数以上の味方がいたら撃つ |
| `DangerRatio` | 0.15 | 敵の城からこの割合以内に味方が1体でもいたら撃つ（張り付かれたら撃つ） |

* 撃つのはチャージ完了かつ上の2つのどちらかを満たしたとき。実際のステージは弱め（ダメージ100・`MinTargets` 5。2-6 だけ4）にしている（コストの低いキャラは HP が 80〜190 で、強い砲だと一撃で全滅して城に届かないため）

### 8.5 撃破報酬

敵を倒すと、そのキャラのコストの 50% のさかなが入る（倍率はかけない。上限で止まる）。

### 8.6 なかま（キャラ解放。`CampaignUnlocks`）

* 最初に使えるのは10体: No 1 ペンギン / 3 ゆきだま / 6 ひな（壁3）/ 11 おの / 12 さかなけん / 17 にんじゃ（アタッカー3）/ 23 ゆみ / 25 つりざお（遠距離2）/ 37 ねばねば / 38 ハリセン（妨害2）。大型は含めない
* ステージを初めてクリアしたとき、そのステージの `UnlockNos` が仲間になる。通常ステージ2体・ボス3〜4体。大型8体はすべてボスの報酬
* 初期10体＋全ステージの `UnlockNos` で、No 1〜50 がちょうど1回ずつになる（EditMode テストで確かめる）
* 解放状態はセーブに持たず、クリア状況から毎回計算する（`IsUnlocked(progress, no)`）。定義表で解放先を変えても矛盾しないため
* リザルトの「なかまになった！」は §2.1。1ステージで5体以上を解放するとリザルト右側の一覧が4体で切れるので、割り振りは4体までにする
* ずかんでは未解放をシルエットにする（§2.0）。オンラインのドラフトには影響させない（§6）

### 8.7 編成画面（`DeckEditPanel` / `DeckRules`）

* ステージ選択の「へんせい」、またはステージ詳細の編成の帯から開く
* 上に10枠（出撃ボタンと同じ5×2・コストの低い順に詰める）、下に解放済みキャラの一覧（ずかんと同じマス `ZukanCell`・6列。並べ替えのドロップダウンだけ）。未解放は出さない
* 一覧を押すと空いている枠へ入る（もう一度押すと外す）、枠を押すと外す
* 10体そろうまで「けってい」できない。「けってい」で保存、「もどる」は変更を捨てる（途中の9体編成が保存されて、次の出撃で勝手に補完されるのを避けるため）
* 出撃に使う編成は `DeckRules.CurrentDeck(progress)`: 保存した編成から未解放・重複・定義表に無い No を外し、解放済みからコストの低い順に補って10体にする（`FillDefault`）。まだ決めていなければ初期10体そのまま
* 編成の人数は `DeckRules.DeckSize`（10）。`PenguinWarsBalance.DeckSize` はドラフト用（同じ値にしておく）

### 8.8 セーブ（`CampaignProgress` / `CampaignSave`）

* `PlayerPrefs` のキー `PenguinWars.Campaign` に JSON 1本。保存のたびに `PlayerPrefs.Save()`（アプリが落ちても失わないため）
* 形: `{"version":1,"lastPlayed":"1-2","stages":{"1-1":{"stars":7,"best":83.5}},"deck":[1,3,...],"revealed":["1-2"]}`
  * `stars` は `StarFlags` の数値（Clear=1 / Safe=2 / Fast=4 の OR）、`best` はベストタイム（秒）
  * `deck` は最後に決めた編成、`revealed` はステージ選択で鍵が外れる演出を見せたステージ（同じ演出を2回出さないため）
* Battle は `noEngineReferences` で `JsonUtility` が使えないので、自前の小さな `MiniJson` で読み書きする
* 読めない・壊れた JSON は空で始める。知らない項目・定義表から消えたステージ ID は読み飛ばす（古いセーブもそのまま読める）
* 「最後に遊んだステージ」は出撃した時点で保存し、ステージ選択はその章から開く
* セーブを消すときは `Edit > Clear All PlayerPrefs`（他のゲームの設定も消える）

### 8.9 検証ツール（`Tools > MiniGame > PenguinWars > Simulate Stages`）

画面なしで全ステージを bot に自動プレイさせ、難しさを表にする。ステージの数値を変えたらこれで確かめる。

* 全ステージ × bot 2段階（ふつう / うまい）× シード5回を回し、表を Console と `Temp/PenguinStageSim.md` に出す。打ち切りは600秒（時間切れは「（時間切れN）」と添える）
* 列: 勝率・平均秒（ふつう / うまい）、勝った回の自城HP、★3目標、★3目安（うまい平均秒 × 0.9）。末尾にかかった秒数（.NET 上で18ステージ約3.5秒）
* bot（`SimpleBot` / `BotSkill`）
  * 生きている壁が3体未満なら一番安い壁、それ以外は壁以外で今出せる一番高いキャラ。砲は範囲に敵が3体以上で撃つ
  * ふつう: 判断1.5秒ごと・働きLv3まで。うまい: 0.5秒ごと・Lv7まで、出せる見込みのある大型がいれば壁以外を出さずにさかなを貯める
  * 判断間隔をシードで ±25% 揺らす（揺らさないと5回がほぼ同じ結果になるため）
* 編成（`SimDeckPicker`）: そのステージを遊ぶ時点で解放されているキャラから、壁3・アタッカー3・遠距離2・妨害/大型2 を目安に高い順。編成制限に当たるキャラは選ばない
* 調整の目安: 各章の1〜2番目はふつうが 5/5、3〜5番目はふつう 3/5 以上・うまい 5/5、ボスはうまい 3/5 以上。3章は「ふつう」が大型を出さず勝ちにくいので、うまいで通常 5/5・ボス 4/5 に合わせた。★3 の目標タイムは「★3目安」を入れる
* 表の組み立ては Battle 側（`StageSimReport`）にあり、Unity を開かずに `StageSimReport.Build(StageSimulator.CreateDefault(), ...)` で同じ表を出せる
* bot は「人間が工夫すれば勝てるか」は測れない。★2（自城HP）は bot だとほぼ全ステージ100%になるので、手で遊んで確かめる

## 10. オンライン対戦

### 10.1 方針

サッカー・卓球と同じく、参加コードを共有して離れた2人が1対1で対戦する。接続部分（`OnlineSession` / `ModeSelectPanel`）は `Assets/_Project/Common/Scripts/Online/` の共通処理を使う。

```text
モード選択
 ├ ステージ → ステージ選択 → 詳細 → 編成発表 → プレイ（§2.1）
 ├ 部屋を作る → 参加コード表示 → 相手の参加待ち → ドラフト → 編成確認 → 対戦（ホスト・左・青）
 └ コードで参加 → 接続 → ドラフト → 編成確認 → 対戦（ゲスト・右・赤）
```

### 10.2 同期の考え方

サッカーと同じく **ホストだけが戦闘を計算し、ゲストは操作を送って表示するだけ** にする。

```text
ゲスト：ボタン操作（出撃・働きペンギン・ペンギン砲）を送る
  ↓
ホスト：両者のお金・出撃・ユニットの移動・攻撃・ノックバック・城HP・時間をすべて計算（BattleWorld）
  ↓
ホスト：全ユニットの状態と両者のお金・城HPを毎秒約15回送る（BattleSnapshot）
  ↓
ゲスト：届いた状態へ滑らかに寄せて表示（GuestWorldMirror）
```

| メッセージ | 向き | 配信 | 中身 |
| --- | --- | --- | --- |
| `pw.ready` | ゲスト → ホスト | 再送あり | なし。ゲストがハンドラ登録を終えた合図 |
| `pw.draft` | ホスト → ゲスト | 再送あり | ラウンド（0始まり）/ ゲストの候補 / ゲストがここまでに取ったキャラ（時間切れでホストが決めた分も出すため毎回全部） |
| `pw.pick` | ゲスト → ホスト | 再送あり | ラウンド / 候補の何番目か。ラウンドが今と違えば捨てる |
| `pw.deck` | ホスト → ゲスト | 再送あり | ホスト左の編成No / ホスト右の編成No / ステージ番号（§3.4）。ドラフト完了の合図を兼ねる |
| `pw.snap` | ホスト → ゲスト | 再送なし（古いものは捨てる）約15回/秒 | 全ユニットの ID・キャラNo・陣営・X座標・HP割合・状態、両者のさかな・財布Lv・城HP・砲チャージ・再生産残り、残り時間 |
| `pw.evt` | ホスト → ゲスト | 再送あり | 1フレーム分の `BattleEvent`（出撃・ヒット・撃破・砲発射・試合終了など。演出用） |
| `pw.cmd` | ゲスト → ホスト | 再送あり | コマンド種類 / 枠番号。陣営はホストが右に付け直す（取りこぼすと操作が効かないため再送あり） |

* NetworkObjectは使わず、名前付きメッセージだけで送る（サッカーと同じ理由。`PenguinWarsOnlineLink`）
* ユニットは横1列で動きが単純なので、サッカーより送信回数を減らしても違和感が少ない
* ゲストのコマンドは `BattleRunner.Enqueue` が `ICommandSink`（= Link）に回すので、UI・キー入力は一人用と同じコードのまま
* ユニットIDは下位16ビットだけ送る（場にいる間の見分けにしか使わないため）

### 10.3 視点

ゲストの画面は左右を反転して表示し、自分の城が常に左に来るようにする（操作の感覚を揃えるため）。計算上の座標はホスト基準のまま。

* ゲストは「表示用の `BattleWorld`（Step しない）」を持ち、届いた状態を陣営入れ替え＋X 裏返しで書き込む（`SideMirror`）。これでゲストの自分も `Side.Left` になり、UI・`UnitView`・`BattleEventPresenter`・勝敗判定が一人用と同じコードで動く
* そのためゲストの自分の絵も青、相手が赤になる（§7.2）

### 10.4 その他のルール

* 相手が切断したら（ドラフト中も含む）「相手が切断しました」を表示してリザルト（勝ち扱い）へ

## 11. フォルダ・クラス構成

### 11.1 設計の考え方

戦闘はすべて純C#の `BattleWorld` が計算し、MonoBehaviour は「入力を渡す」「状態を描く」だけにする。

```text
入力（ボタン / キー / ステージの敵の出方・敵の砲 / オンラインのゲスト）
   │  BattleCommand（出撃・働きペンギン・ペンギン砲）
   ▼
BattleWorld.Step(1/30秒)       ← 純C#。ユニット・城・お金・砲をすべて持つ
   │  状態（UnitState のリスト等）＋ BattleEvent（出撃・ヒット・撃破…）
   ▼
View（UnitView / CastleView / HUD / 音・演出）
```

* オンラインではホストだけが `BattleWorld` を動かし、ゲストは届いた状態を View に流すだけ（§10）
* ステージモードも、敵の出方・ボスの条件・★の判定・解放・編成のきまり・セーブの中身はすべて Battle（純C#）に置き、EditMode テストで確かめる。MonoBehaviour は「ステージを選ぶ・結果を見せる・PlayerPrefs に書く」だけ

```text
StageDefinitions（純C#の定義表。1章1ファイル）
   │  StageDefinition（戦場・城HP・敵の出方・★条件・解放キャラ・ギミック）
   ▼
BattleRunner.InitializeStage(stage, deckNos)
   │  stage.ApplyTo(BattleSettings) ＋ EnemyScriptDirector を BattleWorld に渡す
   ▼
BattleWorld.Step … 敵の出現・ボスの条件・敵の砲はここで進む
   ▼
PenguinWarsGameManager.Stage … 勝敗 → StageResult → StarRule（★）→ CampaignProgress に記録 → CampaignSave → リザルト
```
* `Battle` は独立した asmdef（`noEngineReferences`）。ScriptableObject は参照せず、SO → `UnitStats` に変換して渡す。乱数は `System.Random`（シード指定可能）
* 共通基盤（`Assets/_Project/Common/`）への変更はタイトル登録・画面向き（横）・シーン名と、`AudioManager` の BGM だけ OFF（`IsBgmOff`）・`UIDialogBuilder.CreateVolumeSlider` の公開だけ

## 12. 既知の制限

* ゲストの撃破数は同期していない（対戦のリザルトでは使わない）
* ゲストには攻撃の残り時間を送っていないので、ゲスト側の攻撃コマ・ノックバックの跳ねは簡略化される（位置は同期される）
* ノックバックのコマは全キャラ「立ち姿を90度倒す」なので、かまくら・戦車・クジラは乗り物ごと倒れる
* 働きペンギンのレベルアップに音・演出はない
* 状態異常（止まる・遅い）は色だけで、専用の演出はない
* BGM・SE ともに仮の生成音（素材を置けば差し替わる。§9）。ボス専用のドット絵はない（既存キャラを1.3倍にしているだけ）
* ドラフトにキーボード操作はない
* 試合の途中セーブ・再接続はしない（ステージの進み具合はクリア・出撃の時点で保存する）
* 鍵の演出の記録（`revealed`）が入る前のセーブがある人は、初めてステージ選択を開いたときに遊べる全ステージの鍵の演出がまとめて出る（今開いている章の分だけ見える。一度だけ）
* 1ステージで5体以上を解放すると、リザルト右側の仲間の一覧は4体で切れる（今の割り振りは最大4体）
* ステージ詳細の敵の顔は8種類まで
* bot（検証ツール）は★2（自城HP）を測れない（ほぼ全ステージで100%になる）。★2 の難しさは手で遊んで確かめる
* 1-5・2-4・2-5・3-6 は bot の「うまい」でも3〜7分かかる。長すぎると感じたら、敵の城HPより先に敵の湧き間隔を広げるほうが効く
* あそびかたのボスのデモは、ループごとに WARNING・警報が鳴る
