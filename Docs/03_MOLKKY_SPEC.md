# 第4弾ミニゲーム：2Dモルックゲーム 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第4弾ミニゲーム。モルック（木の棒）を投げて1〜12の数字が書かれたピン（スキットル）を倒し、**ちょうど50点** を目指す。投げる人の背後からピンを見る擬似3Dで、1台での交代プレイ（NPC混成可）とオンライン対戦（2〜4人）を遊べる。

最大の特徴は、**「高得点を狙うか、ちょうど50点に合わせるか」という点数計算の駆け引きを、フリック1回の簡単な操作で楽しめる** こと。卓球（§02）の擬似3D表現とフリック入力の考え方を流用している。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 2Dモルック |
| 視点 | 投げる人の背後から奥のピンを見る擬似3D・縦画面 |
| グラフィック | 2Dドット絵＋擬似3D表現 |
| プレイ人数 | 2〜4人（1台での交代プレイ。人間とNPCを自由に組み合わせ）/ オンライン2〜4人（§9） |
| 試合形式 | 50点ちょうどを先に取った人の勝ち・1ゲームのみ |
| 対象プラットフォーム | Android / iPhone（PCはマウスで同じ操作ができる） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/03_Molkky/`。Sceneは `Tools > MiniGame > Rebuild Molkky`（`MolkkySceneBuilder`）でコードから生成する（素材も同時に描き直す）。

本物の3D物理の再現は目的にしない。地面の平面だけを2D物理で計算し、「狙って倒せる」「たまに予想外に散らばる」バランスを優先する。

## 2. ルール・試合の流れ

### 2.1 試合の流れ

```text
モード選択（1台で遊ぶ / 部屋を作る / コードで参加）
  ↓
人数・人間/NPCの設定（1台で遊ぶときのみ。§7.1）
  ↓
キャラ選択（§8.4。オンラインは自分のキャラだけ）
  ↓
「○○の番」表示
  ↓
狙う（左右移動・投げ方の切り替え）→ フリックで投げる
  ↓
棒とピンが止まる → 得点表示（1.2秒。50点ちょうどは2.2秒）
  ├ 50点ちょうど / 残り1人 → 勝利演出（§8.5）→ リザルト
  └ それ以外 → 倒れたピンを立て直す（0.5秒）→ 次のプレイヤーの番へ
```

### 2.2 ピンと初期配置

1〜12の数字が書かれたピンを12本使う。投擲ラインから奥へ `pinSetDistance`（3.5）の位置を手前の列として、以下の形に密集させて立てる（六角形に詰めた配置。隣り合うピンの中心間は `pinSpacing`）。

```text
（奥）
      ⑦ ⑨ ⑧
    ⑤ ⑪ ⑫ ⑥
      ③ ⑩ ④
        ① ②
（手前・投擲ライン側）
```

ピンは Prefab にせず `PinRack` がコードで生成する。

### 2.3 得点

| 倒れた本数 | 得点 |
| --- | --- |
| 0本 | 0点（ミス） |
| 1本 | そのピンの数字 |
| 2本以上 | 倒れた本数 |

得点ルールは物理と無関係な純粋クラス `MolkkyRules` にまとめ、EditModeテスト（`MolkkyRulesTests`）で検証している。

### 2.4 勝敗・超過・失格

* 合計が **ちょうど50点** になったプレイヤーの勝ち
* 合計が50点を超えたら **25点に戻る**
* 0点の投擲が **3回連続** したプレイヤーは失格となり、以降の手番は飛ばされる。1点以上取るとミス回数は0に戻る
* 失格者が出て残り1人になったら、その1人の勝ち
* リザルトは共通の `ResultDialog`。タイトルは VICTORY! / GAME OVER で、詳細は「P1 パワー型 の勝ち」＋「50点ちょうど！」/「他のプレイヤーが失格」
* VICTORY! / GAME OVER の出し分けは、1台で遊ぶときは人間が勝てば VICTORY!・NPCが勝てば GAME OVER、オンラインは自分が勝ったかどうか

### 2.5 ピンの立て直し

投擲ごとに、倒れたピンを **倒れた場所で立て直す**。ゲームが進むほどピンが散らばり、狙いが難しくなる。

* 倒れたピンの止まった位置に立てる。フィールド（`fieldBounds`）の外へ出たピンは、フィールド端に寄せて立てる
* 立て直したピン同士が重なる場合は、重ならない位置まで引き離す（次の投擲開始時に物理の押し出しで勝手に動かないようにするため）
* 立て直しの前に棒を投擲ラインへ戻す（ピンの間に残った棒が立て直したピンを押さないようにするため）

### 2.6 手番

* P1（オンラインはホスト）から席順に1人1投ずつ投げる
* 失格者は飛ばす

### 2.7 ゲーム状態

進行は共通基盤の `MiniGameState`（`BaseMiniGameManager`）を使い、モルック固有の区切りを `MolkkyPhase` で持つ（`MolkkyGameManager`）。

| MolkkyPhase | 意味 |
| --- | --- |
| PlayerSetup | 人数・人間/NPCの設定中 |
| CharacterSelect | キャラ選択中（オンラインは全員の選択待ちも含む） |
| TurnStart | 「○○の番」表示中 |
| Aiming | 狙い中（位置移動・フリック待ち。NPCは自動で投げる） |
| Throwing | 棒とピンが動いている |
| Scoring | 得点表示・50点/超過/失格の判定 |
| PinReset | 倒れたピンの立て直し |
| GameSet | 勝利演出・リザルト |

## 3. 画面・ビジュアル

### 3.1 視点と擬似3D

縦画面で、投擲ラインと棒が画面下、ピンが画面上の奥に来る。

```text
┌──────────────────┐
│ P1 32  P2 45  ...│ ← スコア
│                  │
│       ⑦⑨⑧        │
│      ⑤⑪⑫⑥       │ ← 奥（小さく表示）
│       ③⑩④        │
│        ①②         │
│                  │
│  ─────[棒]─────  │ ← 投擲ライン（手前・大きく表示）
│    (キャラの背中)   │
└──────────────────┘
```

卓球と同じく、**ゲームロジックは地面の平面座標で計算し、表示だけを擬似3Dに変換する**。変換は `DepthProjector` の1か所に集約し、ピン・棒・影・地面・キャラが同じ変換を使う。

```text
ロジック上の座標
X：左右位置
Z：奥行き（投擲ラインが Z=0）
H：高さ（投げた棒の見た目用。当たり判定には使わない）

表示への変換（消失点へ縮む透視投影）
画面X   ＝ X × その奥行きの縮小率
画面Y   ＝ Z が大きいほど地平線へ近づく（＋ H ぶん上へ）
表示サイズ ＝ Z が大きいほど小さく
描画順   ＝ Z が大きいものほど奥（sortingOrder を Z から決める）
```

| 値 | 初期値 | 意味 |
| --- | --- | --- |
| nearScale | 1.5 | 投擲ラインで地面1単位が画面上の何ワールド単位になるか |
| cameraDistance | 9 | 視点から投擲ラインまでの距離。小さいほど奥行きが強調される |
| nearBaseY / horizonY | -3.5 / 6.5 | 投擲ライン・地平線の画面上のY座標 |

`MolkkyCameraFitter` が端末のアスペクト比に合わせて `orthographicSize` を調整し、縦長の端末でも投擲ラインの左右端（幅5.4）が画面に収まるようにする。

### 3.2 表示物と素材

素材はエディタ拡張 `MolkkyArtGenerator` がコードから生成するドット絵（PPU 32、`Tools > MiniGame > Rebuild Molkky` で毎回描き直す）。同名のPNGを置き換えれば手描き素材へ差し替えられる。

| 対象 | 内容 |
| --- | --- |
| 地面 | 芝生の台形（奥ほど狭い）と白い投擲ライン。`GroundView` がメッシュで描き、奥行き方向に刈り目の縞を入れて遠近感を出す |
| 背景 | 空と木立（`BackdropView`）。地面の奥に置き、それより奥の芝を隠す |
| ピン | 木の色の縦長スプライト＋数字（`PinView`）。前の列に隠れても読めるよう、数字は上寄りに置く |
| 倒れたピン | 横倒しスプライトに切り替え、赤みを乗せて一目で分かるようにする。左右どちらに倒れたかで向きを変える。数字は常に正立させて読めるようにする |
| 立て直し | 背の低い状態から伸びて少し行き過ぎて戻る、0.3秒の起き上がりアニメーション |
| モルック（棒） | 木の色の横長スプライト（`StickView`）。棒の両端を別々に投影して間に張るので、奥を向いた棒は短く見える |
| 影 | 棒の真下の地面に置く。棒が高く飛ぶほど薄くして、高さを読み取れるようにする |
| キャラ | 投擲ラインの手前に手番のキャラの背中を表示する（§8.3） |

### 3.3 UI

| 要素 | 内容 |
| --- | --- |
| スコアボード | 画面上部（PAUSEボタンの下）に全プレイヤーの枠を並べる（`ScoreBoardView`）。枠は「名前・点数・ミス」を縦に積み、点数を一番大きく見せる |
| 手番 | 手番の人の枠をプレイヤー色で明るく少し大きく、名前に「▶」を付ける。他の人の枠は暗くする |
| ミス回数 | 「×」の数で示す（例：`××`）。2回連続ミス中は赤く表示する |
| 失格 | 枠をグレーにして「失格」と表示する |
| 点数の変化 | 数字をカウントアップ/ダウンさせ、何点動いたか（特に25点に戻ったこと）を目で追えるようにする |
| あと○点 | 手番のプレイヤーの「あと○点」を大きく出す。2回連続ミス中は「失格注意!」を添える |
| 投げ方ボタン | 画面右下に「縦投げ/横投げ」、その上に「低め/山なり」。人間の構え中だけ表示する（§4.3 / §4.4） |

プレイヤー色は P1赤・P2青・P3黄・P4緑（`MolkkyPlayerColors`）。スコアボード・手番表示・キャラ選択・勝利演出で共通に使う。スコアやボタンは SafeArea 内に置く。

### 3.4 得点演出

1投ごとに、ピンと投擲ラインの間の空いた芝の上に得点ポップアップを出す（`ScorePopupView`）。結果ごとに色を変え、ポンと弾む登場にする。

| 結果 | 表示 | 演出 |
| --- | --- | --- |
| 1本倒した | `⑫  +12` | 得点音 |
| 複数本倒した | `3本  +3` | 得点音 |
| ミス | `ミス ×` | ミス音 |
| 50点ちょうど | `50! WIN!` | 大きく表示して脈打たせ続ける。勝利音 |
| 超過 | `オーバー！ 25点に` | スコア枠を揺らす。音程が下がる音 |
| 3回ミス | `失格…` | スコア枠を揺らす。ブザー音 |

### 3.5 サウンド

モルック固有のSEは `MolkkyAudio` がプログラムで生成して鳴らす。Inspector のクリップ欄に素材を差し込めばそのまま置き換わる。

| 音 | 鳴るとき |
| --- | --- |
| 風切り音 | 投げた瞬間。強く投げるほど高くする |
| 棒が当たる音 | 投げた棒が何かに当たったとき。衝突が強いほど大きい |
| ピンが倒れる音 | ピンが倒れるたび。1本ずつ音の高さを変え、連鎖で「カラカラ」と聞こえるようにする |
| 立て直しの音 | 倒れたピンを立て直すとき |
| 結果の音 | 得点・ミス・50点・超過・失格（§3.4） |
| 勝利音 | 勝利演出でキャラが登場したとき（50点の勝利音を高いピッチで） |

一斉に倒れたときに音が割れないよう、同じ音は0.04秒以上間隔を空ける。

## 4. 操作

```text
    ↑ フリックで投げる
    │
 ←─[棒]─→  横ドラッグで位置移動
```

入力はタッチ（主タッチのみ）を優先し、PCではマウスを使う。UIの上から始めた操作は拾わない。

### 4.1 投擲位置の移動

* 画面のどこでもよいので、横にドラッグすると棒が投擲ライン上を移動する（指の絶対位置ではなく移動量で動かす。棒の真上を触らなくてよいので、指で棒が隠れない）
* 指と棒が画面上で同じだけ動く（`_moveSensitivity` = 1）
* 移動範囲は `throwLineHalfWidth`（±1.5）
* 横向きの動きが勝るフレームだけ移動に使う。上フリックの途中で狙いがずれないようにするため

### 4.2 フリックによる投擲

指を離したときに、離す直前0.1秒の動きから **方向と強さ** を決める。

| フリックの要素 | 結果 |
| --- | --- |
| 角度（左右） | 投げる方向（±25°にクランプ） |
| 速度 | 初速（飛距離・ピンを倒す勢い） |

* フリック速度（画面高さ/秒）0.8〜4.0 を、初速 `minThrowSpeed`〜`maxThrowSpeed`（3〜11）に対応させる
* 以下は投擲として扱わない（キャンセル）
  * 下向きのフリック
  * 遅すぎる（0.8 未満）・短すぎる（画面高さの4%未満）フリック。指を止めてから離した場合もここで弾かれる
  * 最大角度の2倍（50°）を超える横向きのフリック
* 弱すぎると手前で止まり、強すぎるとピンが大きく散らばる。この「強さのさじ加減」が面白さの中心

### 4.3 縦投げ／横投げ

画面右下のボタンで、棒の向きを切り替える。

| 投げ方 | 真上から見た棒の向き | 狙い |
| --- | --- | --- |
| 縦投げ | 進行方向と平行 | 当たり幅が細い。離れた1本を狙う |
| 横投げ（初期） | 進行方向に対して横向き | 当たり幅が広い。密集をまとめて倒す |

### 4.4 低め／山なり

縦横ボタンの上のボタンで、軌道を切り替える。向きと軌道は独立していて、「縦×山なり」のように組み合わせて使える。

| 軌道 | 挙動 | 狙い |
| --- | --- | --- |
| 低め（初期） | 少しだけ浮いて、すぐ滑りながらピンに当たる | 手前から当てて弾く |
| 山なり | 高く浮いている間は当たり判定なし。着地で大きく減速し、落ちた近くで止まる | 手前のピンを飛び越えて奥を狙う |

* 飛距離は低めと同じくフリックの強さで決まる
* 向き・軌道とも、手番の開始時に毎回「横投げ・低め」に戻す（前の人の設定を引き継いで気づかず投げるのを防ぐため）
* 切り替えられるのは構え中だけ

### 4.5 入力とゲームロジックの分離

```text
ThrowInput（ドラッグ・フリック）   NpcThrower（狙い決め）
          ↓                          ↓
     ThrowRequest（位置X・角度・初速・向き・軌道）
          ↓
     StickThrower（棒に初速を与える）
```

人間とNPCが同じ `ThrowRequest` を作ることで、投擲処理を共通化する。オンラインでもこの `ThrowRequest` をそのまま送る（§9.2）。

## 5. 投擲・物理

### 5.1 方針

**地面の平面（X/Z）を Rigidbody2D で計算する**。本物の3D物理は使わない。

```text
Unity 2D物理のXY平面 ＝ ゲームの地面（X＝左右、Y＝奥行きZ）
重力は0（真上から見た平面として扱う）
```

見た目の高さは当たり判定に入れない。空中の高さまで判定に入れると調整が重くなり、「転がって・滑ってピンに当たる」挙動だけで十分モルックらしくなるため。

### 5.2 モルック（棒）

* 形状は CapsuleCollider2D（長さ `stickLength` × 太さ `stickThickness`）。向きは §4.3 の縦投げ/横投げで決まる
* 速い棒がピンをすり抜けないよう、衝突判定は Continuous
* 狙っている間は Kinematic にして、ピンに押されないようにする
* 投擲時に `ThrowRequest` の方向・初速を与え、`linearDamping`（`stickDamping`）で自然に止まる
* 高さ H は見た目用の放物線。低めは滞空 `stickAirTime`、最高点は `stickPeakHeight` を強さに比例させる

**山なり** は以下のように動かす。

* 初速に `lobSpeedRatio` を掛ける（空中で減速しない分、低めと同じ強さで遠くへ飛びすぎないようにする）
* `lobAirTime` の間は当たり判定を切り、減速もさせない。見た目の最高点は強さによらず `lobPeakHeight`
* 着地で当たり判定と減速を戻し、速度に `lobLandingSpeedRatio` を掛けて落ちた場所の近くで止める
* 着地のタイミングは物理ステップ数で数える（時間で測るとオンラインの再生で着地点がずれるため）

### 5.3 ピンと転倒判定

* 形状は CircleCollider2D（半径 `pinRadius`）。回転は固定
* 立っている間は重く止まりやすく、倒れたら軽く滑りやすくする（倒れたピンが他のピンを巻き込む連鎖を起こしやすくするため）
* 跳ね返り（`bounciness`）は棒・ピン共通。0だとピン同士の連鎖が起きにくい

立っているピンは、投擲中に以下のどちらかを満たしたら **倒れた** とする。

```text
・衝突時の相対速度が fallImpactThreshold 以上
・投擲開始時の位置から fallMoveThreshold 以上動いた
```

* 倒れる向きは、当たった点の反対側（移動で倒れた場合は動いた向き）
* 倒れたらその投擲中は立ち上がらない
* 転倒判定は投擲中だけ行う（立て直し直後の押し合いで「倒れた」扱いにしないため）

### 5.4 静止判定

以下のどちらかで投擲終了とし、得点計算へ進む（`ThrowSettleWatcher`）。

```text
・棒と全ピンの速度が settleSpeedThreshold 以下の状態が settleDuration 続いた
・投擲から maxThrowDuration 経過した（止まらない場合の保険）
```

### 5.5 調整用パラメータ

ScriptableObject `MolkkyPhysicsSettings`（`Data/MolkkyPhysicsSettings.asset`）にまとめる。Scene生成時に無ければ初期値で作り、既にあれば調整済みの値を残す。

| パラメータ | 初期値 | 意味 |
| --- | --- | --- |
| pinSetDistance | 3.5 | 投擲ラインから初期配置の手前の列までの距離 |
| pinSpacing | 0.42 | 初期配置で隣り合うピンの中心間距離（直径より少し広くして、置いた瞬間に押し合わないようにする） |
| pinRadius | 0.2 | ピンの半径 |
| throwLineHalfWidth | 1.5 | 投擲位置の左右移動範囲 |
| fieldBounds | x -3〜3 / z 1.5〜9.5 | 立て直し時にピンを寄せる範囲 |
| minThrowSpeed / maxThrowSpeed | 3 / 11 | 初速の範囲 |
| maxThrowAngle | 25 | 投擲方向の最大角度（左右・度） |
| stickLength / stickThickness | 0.9 / 0.22 | 棒の長さ・太さ |
| stickMass | 1 | 棒の質量 |
| stickDamping / stickAngularDamping | 0.9 / 2 | 棒の減速・回転の減速 |
| stickAirTime / stickPeakHeight | 0.7 / 1.2 | 低めの見た目上の滞空時間・最高点（最大の強さのとき） |
| lobAirTime / lobPeakHeight | 1.1 / 2.5 | 山なりの滞空時間・見た目上の最高点 |
| lobSpeedRatio | 0.6 | 山なりの初速に掛ける割合 |
| lobLandingSpeedRatio | 0.5 | 山なり着地時に残す速度の割合 |
| pinMassStanding / pinMassFallen | 1.5 / 1.2 | 立っている／倒れたピンの質量 |
| pinDampingStanding / pinDampingFallen | 3 / 0.9 | 立っている／倒れたピンの減速 |
| bounciness | 0.55 | 跳ね返り |
| fallImpactThreshold | 1.2 | 転倒とみなす衝突速度 |
| fallMoveThreshold | 0.25 | 転倒とみなす移動距離 |
| settleSpeedThreshold / settleDuration | 0.05 / 0.4 | 静止判定の速度・継続時間 |
| maxThrowDuration | 5 | 投擲の最大時間（秒） |

## 6. NPC

### 6.1 方針

NPCは「狙うピンを決める → そこへ届く `ThrowRequest` を作る → ブレを加える」だけのシンプルな仕組み（`NpcThrower`）。軌道は常に低めで投げる。

### 6.2 狙いの決め方

```text
① 残り点数（50 − 現在の点数）を計算
② 残り点数と同じ数字の立っているピンがあれば、それを1本狙う
③ ②で狙うピンの周りが混んでいて複数本倒しそうなら、残り点数より小さい数字で
   周りにピンがない（孤立した）ピンのうち、一番大きい数字に切り替える
④ ②③で狙えるピンがなければ、ピンが最も密集している場所を狙って複数本倒す
```

* 「混んでいる」＝半径0.6以内に他の立っているピンがある
* 密集地は、周りに立っているピンが最も多いピン（同数なら手前）を狙う

### 6.3 投げ方の決め方

* 投擲位置X：狙うピンのX（投擲ラインの範囲にクランプ）
* 方向：投擲位置から狙うピンへの角度
* 強さ：狙うピンの少し先まで届く初速（初速 ≒ 減速率 ×（距離 ＋ 越える距離））。越える距離は1本狙いで0.4、密集地で1.5
* 向き：1本狙いは縦投げ、密集地は横投げ

### 6.4 難易度（3段階）

ScriptableObject `MolkkyNpcDifficulty`（`Data/MolkkyNpc_Weak / Normal / Strong.asset`）で定義する。ブレは ±の範囲でランダムに加える。

| 難易度 | 方向のブレ | 強さのブレ | ②ちょうどのピン | ③超過の回避 |
| --- | --- | --- | --- | --- |
| よわい | ±9° | ±30% | 使わない（常に密集地） | 使わない |
| ふつう | ±4° | ±15% | 使う | 使わない |
| つよい | ±1.5° | ±6% | 使う | 使う |

### 6.5 NPCの手番

* 「○○の番」表示は0.8秒で自動で閉じる（タップ不要）
* 投げる前に0.8秒の間を置く（考えている感じを出す）

## 7. プレイヤー設定・手番交代

### 7.1 試合前の設定（1台で遊ぶとき）

```text
人数選択（2〜4人）
 ↓
各プレイヤーを「人間」か「NPC（よわい／ふつう／つよい）」に設定
 ↓
キャラ選択（§8.4）
 ↓
試合開始
```

* 種別はボタンをタップするたびに 人間 → NPC よわい → NPC ふつう → NPC つよい と切り替わる（`PlayerSetupPanel`）
* 初期状態は「2人・P1人間・他はNPC ふつう」（すぐに人間1人 vs NPC1人で遊べるようにするため）
* 全員NPCは不可（最低1人は人間）
* プレイヤー名は「P1 パワー型」のように席番号＋キャラ名（同じキャラを複数人が選べるため）

### 7.2 手番交代

1台を回して遊ぶため、人間の手番では「P2 パワー型 の番」を画面全体に出し、タップで開始する（`TurnBannerView`）。前の人の指がそのまま投擲にならないようにするため。

* 背景を手番の人の色に寄せ、端末を渡された人が自分の番だと一目で分かるようにする
* NPCの手番とオンラインの手番は0.8秒で自動で閉じる

## 8. キャラクター

### 8.1 方針

| 項目 | 内容 |
| --- | --- |
| キャラの差 | 見た目＋能力倍率（卓球の `CharacterData` / `LoadoutCatalog` と同じ形） |
| キャラ数 | 4体（バランス型／パワー型／精密型／ロング棒） |
| 同じキャラの重複選択 | 可。席の色で区別できる |
| 追加演出 | キャラ別の勝利演出（立ち絵＋セリフ） |

* 能力は **倍率（バランス型＝1.0）** で持ち、`MolkkyPhysicsSettings` の基準値は変えない
* 1キャラ＝1アセット（`Data/Characters/MolkkyChar_xxx.asset`）、一覧は `MolkkyCharacterCatalog`。2人で同時に数値調整してもコンフリクトしないようにするため
* `PlayerSlot` にはアセットではなく **カタログの番号（`CharacterIndex`）** だけを持たせる。オンラインで番号だけ送れば全端末で同じキャラになる
* アセットとカタログは `MolkkyCharacterGenerator` が生成する（`Tools > MiniGame > Rebuild Molkky` 実行時に未生成なら自動で作る。既にあれば調整済みの値を残す）

### 8.2 能力とキャラ

| 能力 | 倍率の意味 | 反映先 |
| --- | --- | --- |
| パワー | 最大初速（`maxThrowSpeed`）の倍率。高いと遠くまで届き、ピンが派手に散らばる | `ThrowInput`（フリック→初速）/ `NpcThrower`（初速の上限） |
| コントロール | 最大の強さになるフリック速度の倍率。高いと強さのさじ加減がしやすい。NPCはブレ（方向・強さ）をこの値で割る | `ThrowInput` / `NpcThrower` |
| 棒の長さ | `stickLength` の倍率。長いと当たり幅が広く、まとめて倒しやすい | `StickThrower`（当たり判定）。見た目は `StickView` が `StickThrower.Length` を参照する |

| キャラ | パワー | コントロール | 棒の長さ | 特徴 | 勝利セリフ |
| --- | --- | --- | --- | --- | --- |
| バランス型 | 1.0 | 1.0 | 1.0 | 基準。初期選択 | ぴったり50点！ |
| パワー型 | 1.2 | 0.8 | 1.0 | 遠くまで届くが強さの調整がシビア | 力こそパワー！ |
| 精密型 | 0.95 | 1.15 | 0.9 | 狙った強さで投げやすいが、少し奥に届きにくい | 計算どおり！ |
| ロング棒 | 0.9 | 1.0 | 1.3 | まとめて倒しやすいが、1本狙いが難しい | まとめていただき！ |

`MolkkyGameManager` は手番開始時に手番のキャラを `ThrowerView` / `StickThrower` / `ThrowInput` に渡すだけで、能力の反映はそれぞれが行う。

### 8.3 投擲ラインの表示

* 手番のキャラの背中を投擲ラインの手前に表示し、棒の左右位置に追従する（`ThrowerView`）。棒の少し左に立ち、右手に棒を持っているように見せる
* 投げた後は投げた場所に残す（棒を追いかけてピンの方へ歩いていかないように）
* 地面のすぐ上の描画順にして、棒やピンの見え方を邪魔しない
* 人間・NPC・オンラインの相手のどの手番でも、手番開始時に手番のキャラを適用する。棒の長さは当たり判定なので、相手の手番でも揃えておかないと再生で倒れるピンがずれる

### 8.4 キャラ選択画面

```text
PlayerSetup（人数・人間/NPC）
 ↓
CharacterSelect（P1 → P2 → … の順に1人ずつ）
 │  ┌─────────────────┐
 │  │   P2 のキャラを選んでね   │ ← 席の色で表示
 │  │  ◀   [正面の立ち絵]   ▶  │
 │  │       パワー型            │
 │  │  パワー     ■■■■□    │
 │  │  コントロール ■■□□□    │
 │  │  棒の長さ   ■■■□□    │
 │  │     [ 決定 ]  [ 戻る ]     │
 │  └─────────────────┘
 ↓  全員決まったら
TurnStart
```

* 人間は基準のバランス型から始める
* NPCはランダムで選ばれた状態で表示し（タイトルに「（NPC）」を付ける）、そのまま決定しても ◀▶ で人間が代わりに変えてもよい
* 能力バーは倍率 0.8〜1.3 を 1〜5マスに変換して表示する（数値そのものは見せない。最低でも1マスは塗る）
* 「戻る」で1人前へ戻れる（P1で戻ると人数設定へ）

### 8.5 勝利演出

```text
50点ちょうど（または残り1人）
 ↓
「50! WIN!」ポップアップ（2.2秒）
 ↓
勝利演出（約2秒。タップで飛ばせる。VictoryShowView）
  ・背景を勝者の席の色で暗転
  ・正面の立ち絵が下からスライドイン＋2回ジャンプ
  ・吹き出しでセリフ
  ・勝利音
 ↓
ResultDialog（共通）「P1 パワー型 の勝ち」
```

* キャラ別のセリフは50点ちょうどで勝ったときだけ。他のプレイヤーの失格で勝ったときは共通の「最後まで残った！」
* 勝利演出は消さずに結果画面の裏に残す（勝者が見えたまま結果を出す）

## 9. オンライン対戦

### 9.1 方針

離れた2〜4人が参加コードを共有して対戦する（人間のみ。NPCは参加しない）。

```text
Netcode for GameObjects（NGO）＋ Unity Multiplayer Services（Relay）
```

接続部分（`OnlineSession` / `ModeSelectPanel`）は他のミニゲームと共通で `Assets/_Project/Common/Scripts/Online/` にある。

```text
ホストが「部屋を作る」（定員4人）
 ↓
参加コードで1〜3人が入る（ホストの画面に「参加者 N/4人」）
 ↓
ホストが「開始」を押す（2人以上で押せる）
 ↓
参加順に席番号を配る（ホスト=0＝先攻、以降は参加順）
 ↓
各端末で自分のキャラだけ選ぶ（「戻る」は出さない）
 ↓  決定 → 全席のキャラが揃うまで「他のプレイヤーを待っています」
TurnStart
```

* 席番号＝手番の順。手番の進め方（失格者を飛ばす）は `MolkkyRules` で全端末同じ計算になるので、手番そのものは送らない
* 名前は自分が「あなた パワー型」、他は「P2 精密型」のように表示する（表示にしか使わないので端末ごとに違ってよい）
* 「○○の番」表示はタップ待ちにせず0.8秒で自動で閉じる（端末を回さないため）
* 開始後に入ってきた人は切断する。開始前に誰かが抜けた場合は人数が減るだけ。ホストが抜けたら参加者はキャンセルからやり直す

### 9.2 同期の考え方

ターン制なのでリアルタイム同期は不要。ただし **2D物理は端末ごとに結果がずれる** ため、得点は投げた側の端末の結果で決める（`MolkkyOnlineLink`）。

```text
投げる側の端末で物理を計算（判定の権限を持つ）
 ↓
ThrowRequest ＋ 投げる直前の全ピンの状態を送信
 ↓
相手端末は届いたピン状態に揃えてから、同じ ThrowRequest で物理を再生して見せる
 ↓
投げる側が静止したら、全ピンの最終状態（位置・倒れたか・倒れた向き）を送信し、自分の画面もその状態で止める
 ↓
相手端末は物理の静止を待たずに、届いた状態でピンを上書きして採点する
```

| 送る内容 | メッセージ |
| --- | --- |
| 投擲（位置X・角度・初速・向き・軌道＋投げる直前の全ピンの状態） | `molkky.throw` |
| 結果（全ピンの最終状態） | `molkky.result` |
| キャラ（席番号・キャラ番号） | `molkky.character` |

* 得点は送らない。`MolkkyRules` は純粋関数なので、同じピン状態を渡せば全端末で同じ点数になる
* 投げる直前のピン状態も送るのは、手番の合間に端末ごとにピン位置が少しずつずれ、再生で倒れるピンが投げた側と食い違うのを防ぐため（`MolkkyOnlineSyncTests` で確認）
* パワー・コントロールは `ThrowRequest` の初速に焼き込まれるので追加の同期は不要。棒の長さは全端末で手番のキャラを適用する（§8.3）
* すべて順序保証あり（`ReliableSequenced`）で送る。投擲と結果の順番が入れ替わらないようにするため
* 届いた投擲・結果はキューに溜め、相手の手番の処理で古い順に取り出す（3人以上だと、自分の画面の演出中に次の人の投擲まで届くことがあるため）
* NGOではクライアント同士が直接送れないため **ホスト中継**：クライアントはホストへ送り、ホストは送り主以外の全員へ転送する
* NetworkObject は使わず、名前付きメッセージだけで送る
* 範囲外のキャラ番号が届いたらクランプする。範囲外の席番号は無視する

### 9.3 視点

全端末とも同じ背後視点（ピンの配置も同じ向き）。反転は不要。

### 9.4 その他のルール

* PAUSE：相手の端末は止まらないため、時間は止めずに自分の投擲受付だけ止める
* 試合中（キャラ選択・待機中を含む）に誰か1人でも接続が切れたら、全員その時点で試合終了（リザルトは GAME OVER・「他のプレイヤーとの接続が切れました」）

## 11. 既知の制限

* 公式ルールの「他のピンや棒にもたれかかったピンは倒れていない扱い」はない（倒れたか立っているかの2択）
* フィールド外へ出たピンは、フィールド端に寄せて立てる（簡略化）
* 1台で遊ぶときの先攻は常にP1
* プレイヤー名は入力できない（席番号＋キャラ名）
* NPCは山なりを使わない
* オンラインで相手が投げている間、自分の画面の倒れ方は再生であり、最終的なピン配置・得点だけが全端末で一致する（再生と結果が違う場合は、結果が届いた時点でピンが置き換わる）
* 切断からの再接続はしない。途中で抜けた人を飛ばして試合を続けることもしない
* SEは仮の生成音
