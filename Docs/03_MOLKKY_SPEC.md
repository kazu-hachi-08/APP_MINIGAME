# 第4弾ミニゲーム：2Dモルックゲーム 仕様書

## 1. 概要

本ゲームは、「週末2人開発 2Dミニゲームプロジェクト」における第4弾ミニゲームとして開発する。

モルックは、木の棒（モルック）を投げて1〜12の数字が書かれたピン（スキットル）を倒し、**ちょうど50点**を目指すフィンランド発祥のスポーツである。

本ゲームでは、卓球（§02）で作った**擬似3D表現**と**フリック入力**の考え方を流用し、投げる人の背後から見た視点でピンを狙う。

特に本ゲームの主要な特徴として、**「高得点を狙うか、ちょうど50点に合わせるか」という点数計算の駆け引き**を、フリック1回の簡単な操作で楽しめるようにする。

# 3. MVP方針

最初から本格的なモルックを目指さず、**モルックとして成立する最小限の機能**を実装する。

本ゲームでは、特に「フリックで棒を投げ、ピンがバラバラと倒れ、点数計算で一喜一憂する」という体験をMVPの中心とする。

## MVP必須機能

```text
✓ 投げる人の背後視点
✓ 擬似3Dによる地面・ピン表現
✓ モルック（投げる棒）
✓ ピン12本（初期配置）
✓ 投擲ライン上での左右移動
✓ フリックによる投擲（方向・強さ）
✓ ピンの転倒判定
✓ 倒れたピンの立て直し（倒れた場所に立てる）
✓ 得点計算（1本＝数字／複数本＝本数）
✓ 50点ちょうどで勝利
✓ 50点超過で25点に戻る
✓ 3回連続ミスで失格
✓ 2〜4人の交代プレイ
✓ NPC（3段階の難易度）
✓ 手番交代表示（「○○の番」→タップで開始）
✓ スコア表示
✓ Android動作
✓ iPhone動作
```

## MVP対象外

以下は原則として実装対象外とする。

```text
△ オンライン対戦（MVP後に追加。§19）
△ チーム戦
△ 必殺技などの独自要素
△ 地形・ステージの違い
△ 投げ方の種類（転がし／山なり）
△ 横回転・カーブ
△ ピンが他のピンにもたれかかる判定
△ 複数ゲーム制・目標点数の変更
△ キャラクター選択
△ リプレイ
△ 詳細な3D物理シミュレーション
```

必要性が確認できた場合のみ、MVP完成後に追加する。

# 4. 画面・視点

## 4.1 視点

**投げる人の背後から、奥のピンを見る視点**とする。画面は縦持ちを想定する。

```text
┌──────────────────┐
│ P1 32  P2 45  ...│ ← スコア
│                  │
│       ⑦⑨⑧        │
│      ⑤⑪⑫⑥       │ ← 奥（小さく表示）
│       ③⑩④        │
│        ①②         │
│                  │
│                  │
│                  │
│  ─────[棒]─────  │ ← 投擲ライン（手前・大きく表示）
│                  │
└──────────────────┘
```

## 4.2 擬似3D表現

卓球と同じく、**ゲームロジックは地面の平面座標で計算し、表示だけを擬似3Dに変換する**。

```text
ロジック上の座標

X：左右位置
Z：奥行き（投擲ラインからの距離）
H：高さ（投げた棒の見た目用。当たり判定には使わない）
```

```text
表示への変換

画面X ＝ 消失点に向かって X を縮める
画面Y ＝ Z が大きいほど上へ（＋ H ぶん上へ）
表示サイズ ＝ Z が大きいほど小さく
描画順 ＝ Z が大きいものほど奥（sortingOrder を Z から決める）
```

これにより、2D物理で安定して計算しつつ、「奥のピンに向かって投げる」見た目を作る。

# 6. ルール（公式ルール準拠）

## 6.1 ピン

1〜12の数字が書かれたピンを12本使う。

## 6.2 初期配置

投擲ラインから奥へ一定距離（`pinSetDistance`）の位置に、以下の形で密集させて立てる。

```text
（奥）
      ⑦ ⑨ ⑧
    ⑤ ⑪ ⑫ ⑥
      ③ ⑩ ④
        ① ②
（手前・投擲ライン側）
```

## 6.3 得点

| 倒れた本数 | 得点        |
| ----- | --------- |
| 0本    | 0点（ミス）    |
| 1本    | そのピンの数字   |
| 2本以上  | 倒れた本数     |

## 6.4 50点ちょうどで勝利

合計がちょうど50点になったプレイヤーが勝利する。

## 6.5 50点超過

合計が50点を超えた場合、**25点に戻る**。

## 6.6 3回連続ミスで失格

0点の投擲が3回連続したプレイヤーは失格となり、以降の手番は飛ばされる。

・1点以上取るとミス回数は0に戻る
・ミス回数はスコア表示に「×」で見せる（例：`××`）
・2回連続ミス中は警告表示する

## 6.7 残り1人

失格者が出て残り1人になった場合、その1人の勝利とする。

## 6.8 ピンの立て直し

投擲ごとに、倒れたピンを**倒れた場所で立て直す**。

・ロジック上は、倒れたピンの「止まった位置」に立てる
・フィールド外へ出たピンは、フィールド端に寄せて立てる（簡略化）

これにより、ゲームが進むほどピンが散らばり、狙いが難しくなる。

## 6.9 手番順

・プレイヤー1から順に投げる
・全員が1投ずつで1巡
・失格者は飛ばす

# 7. プレイヤー操作

## 7.1 基本操作

```text
① 投擲ラインの上で棒を左右にドラッグ → 投げる位置を決める
② 上方向にフリック → 投げる
```

## 7.2 投擲位置の移動

・棒をタッチしたまま左右にドラッグすると、投擲ライン上を移動する
・移動範囲は `throwLineHalfWidth` の範囲に制限する
・ドラッグの動きが主に横方向なら「移動」、上方向なら「フリック」と判定する

## 7.3 フリックによる投擲

フリックで決めるのは**方向と強さのみ**とする。

| フリックの要素 | 結果                   |
| ------- | -------------------- |
| 角度（左右）  | 投げる方向               |
| 速度      | 飛距離・ピンを倒す勢い         |

```text
     ↖   ↑   ↗
      左  まっすぐ 右
          ●
        （棒）
```

・フリック速度は最小値・最大値でクランプする
・下方向・極端に横向きのフリックは投擲として扱わない（キャンセル）
・弱すぎると手前で止まり、強すぎるとピンが大きく散らばる。この「強さのさじ加減」を面白さの中心にする

## 7.4 入力とゲームロジックの分離

卓球と同様、入力とロジックを分ける。

```text
┌──────────────┐
│ 入力処理      │ マウス（PC確認）／タッチ
└──────┬───────┘
       ↓  ThrowRequest（位置X・方向・強さ）
┌──────────────┐
│ ゲームロジック │ 投擲・転倒・得点
└──────────────┘
```

NPCも同じ `ThrowRequest` を生成して投げる。これにより、プレイヤーとNPCで投擲処理を共通化する。

# 8. 投擲・物理

## 8.1 基本方針

**地面の平面（X/Z）を Rigidbody2D で計算する**。本物の3D物理は使わない。

```text
Unity 2D物理のXY平面 ＝ ゲームの地面（X＝左右、Y＝奥行きZ）
重力は0（真上から見た平面として扱う）
```

表示は §4.2 の変換で擬似3Dにする。

## 8.2 モルック（棒）

・形状：CapsuleCollider2D（投げる方向に対して横向き）
・投擲時に、フリックの方向・強さから初速を与える
・摩擦は `linearDamping` で表現し、自然に止まるようにする
・高さ H は見た目用の放物線で、当たり判定には影響させない

```text
理由：
空中の高さまで当たり判定に入れると調整が重くなる。
「転がって・滑ってピンに当たる」挙動だけで十分モルックらしくなる。
```

## 8.3 ピン

・形状：CircleCollider2D
・立っている間は動きにくく（重め）、倒れたら滑るようにする
・倒れたピンも他のピンに当たって倒す（連鎖）

## 8.4 転倒判定

立っているピンは、以下のどちらかを満たしたら**倒れた**とする。

```text
・衝突時の相対速度が fallImpactThreshold 以上
・立っていた位置から fallMoveThreshold 以上動いた
```

倒れたら：
・見た目を横倒しスプライトに切り替える（衝突方向へ倒れる向き）
・その投擲中は立ち上がらない

※ 公式ルールの「他のピンや棒にもたれかかったピンは倒れていない扱い」はMVPでは扱わない。

## 8.5 静止判定

以下のどちらかで投擲終了とし、得点計算へ進む。

```text
・棒と全ピンの速度が settleSpeedThreshold 以下の状態が settleDuration 続いた
・投擲から maxThrowDuration 経過した（止まらない場合の保険）
```

## 8.6 調整用パラメータ

マジックナンバーを避け、ScriptableObject（`MolkkyPhysicsSettings`）にまとめる。

| パラメータ               | 意味                    |
| ------------------- | --------------------- |
| pinSetDistance      | 投擲ラインから初期配置までの距離       |
| throwLineHalfWidth  | 投擲位置の左右移動範囲            |
| minThrowSpeed / maxThrowSpeed | 初速の範囲         |
| maxThrowAngle       | 投擲方向の最大角度（左右）         |
| stickDamping        | 棒の減速                  |
| pinDampingStanding / pinDampingFallen | 立っている／倒れたピンの減速 |
| fallImpactThreshold | 転倒とみなす衝突速度             |
| fallMoveThreshold   | 転倒とみなす移動距離             |
| settleSpeedThreshold / settleDuration | 静止判定  |
| maxThrowDuration    | 投擲の最大時間                |
| fieldBounds         | フィールドの範囲               |

# 9. NPC

## 9.1 基本方針

NPCは「狙うピンを決める → そこへ投げる `ThrowRequest` を作る → ブレを加える」だけのシンプルな仕組みにする。

## 9.2 狙いの決め方

```text
① 残り点数（50 − 現在の点数）を計算
② 残り点数と同じ数字の立っているピンがあれば、それを1本狙う
③ なければ、ピンが密集している場所を狙って複数本倒す
④ 25点に戻るリスクが高い場合は、小さい数字のピンを1本狙う
```

## 9.3 投げ方の決め方

・投擲位置X：狙うピンのXに近い位置
・方向：投擲位置から狙うピンへの角度
・強さ：狙うピンまでの距離から決める（距離→初速の対応は定数テーブルか簡単な式）

## 9.4 難易度（3段階）

| 難易度 | 方向のブレ | 強さのブレ | 狙いの賢さ                   |
| --- | ----- | ----- | ----------------------- |
| よわい | 大     | 大     | ②〜④を使わず、常に密集地を狙う         |
| ふつう | 中     | 中     | ②③を使う                   |
| つよい | 小     | 小     | ②③④をすべて使う                |

難易度は ScriptableObject（`MolkkyNpcDifficulty`）で定義する。

## 9.5 NPCの手番

・「○○の番」表示は短く出して自動で進める（タップ不要）
・投げる前に少し間を置く（考えている感じを出す）

# 19. オンライン対戦（Phase 10：MVP後の追加）

## 19.1 方針

卓球と同じく、参加コードを共有して離れた相手と対戦できるようにする。

```text
Netcode for GameObjects（NGO）
＋ Unity Multiplayer Services（Relay）
```

・MVP後の最初は **1対1のみ**（2〜4人オンラインはさらに後で検討）
・既存の `Common/Scripts/Online/` を使う

## 19.2 同期の考え方（卓球との違い）

モルックはターン制のため、リアルタイム同期は不要。ただし**2D物理は端末ごとに結果がずれる**ため、「投げた条件」だけ送って相手端末で再計算する方式は使わない。

```text
投げる側の端末で物理を計算（判定の権限を持つ）
 ↓
ThrowRequest を即送信 → 相手端末は棒が飛ぶ演出だけ再生
 ↓
静止後、全ピンの最終位置・倒れたかどうか・得点を送信
 ↓
相手端末はその結果でピン配置とスコアを上書き
```

こうする理由：
・物理のずれでピン配置・得点が食い違わない
・ターン制なので、結果の到着が少し遅れても問題にならない

## 19.3 視点

両端末とも同じ背後視点（ピンの配置も同じ向き）。反転は不要。

## 19.4 その他のルール

・先攻はホスト（部屋を作った側）
・PAUSE：相手の端末は止まらないため、自分の投擲受付だけ止める
・試合中に接続が切れたら、その時点で試合終了

## 19.5 既知の制限

・相手の投擲中、相手端末のピンの倒れ方と自分の画面の演出は一致しない（最終結果のみ一致）
・切断からの再接続はしない

## 19.6 完了条件

```text
[ ] 部屋を作ると参加コードが表示される
[ ] 別の端末でコードを入力して参加できる
[ ] 交互に投げられる
[ ] ピン配置・得点が両端末で一致する
[ ] 50点ちょうどで両端末に勝敗が出る
[ ] 切断時に試合が終了する
[ ] Android / iPhone 間で対戦できる
```
