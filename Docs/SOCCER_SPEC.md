# 第1弾ミニゲーム：2Dサッカーゲーム 仕様書

## 1. 概要

本ゲームは、「週末2人開発 2Dミニゲームプロジェクト」における第1弾ミニゲームとして開発する。

プロジェクト全体として複数のミニゲームを開発する方針であり、本ゲームはそのうちの1タイトルとして位置付ける。

# 3. MVP方針

最初から本格的なサッカーゲームを目指さず、**ゲームとして成立する最小限の機能**を実装する。

## MVP必須機能

```text
✓ 11 vs 11
✓ 見下ろし2D
✓ 人型の選手表示
✓ 選手移動
✓ ボール
✓ パス
✓ シュート
✓ ゴール
✓ 得点
✓ 簡易AI
✓ 選手自動切り替え
```


# 4. 画面・視点

## 4.1 視点

見下ろし視点（Top-down View）とする。

```text
┌─────────────────────────┐
│                         │
│         サッカー場       │
│                         │
│    ○ ○       ● ●        │
│                         │
│          ⚽             │
│                         │
│    ○ ○       ● ●        │
│                         │
└─────────────────────────┘
```

## 4.2 ビジュアル方針

2Dピクセルアートで統一する。選手は丸や記号ではなく **人型（頭・胴・手足が分かるキャラクター）** として描く。

```text
方針
  ・ドット絵（低解像度・Point フィルタ）
  ・はっきりした輪郭と彩度の高い色
  ・青チーム vs 赤チーム
  ・コート外に観客席を敷いてスタジアムらしさを出す

やらないこと
  ・横視点やアップのキャラクター表現
  ・細かい群衆表現
  ・高解像度イラスト
```

見下ろし視点は変更しない。

---

## 4.3 選手の見せ方

見下ろし視点で人型に見せるため、**やや斜め上から見たキャラクター** として描く。真上からの完全な俯瞰（頭と肩だけ）にはしない。

```text
    ○     頭
   ╱█╲    胴（チームカラーのユニフォーム）
    ╹╹    足
   ____   影（楕円・半透明）
```

| 項目    | 内容                                                      |
| ----- | ------------------------------------------------------- |
| スプライト | 1体 16 x 16 px                                           |
| PPU   | 16（1ワールド単位 = 16px）                                      |
| 表示サイズ | 1.0 x 1.0 ワールド単位（コートは 22 x 12 単位）                        |
| 原点    | 足元（下から1.5px）。足の位置とコライダー中心を合わせるため                        |
| 向き    | 4方向（上 / 下 / 左 / 右）。左右は右向きを `flipX` で反転するので画像は3方向分       |
| アニメ   | 待機 1枚 + 走り 2枚のコマ切り替えのみ（`PlayerSpriteAnimator`）          |
| 影     | スプライトの最下行に描き込む（GameObjectを増やさない）                        |
| 描画順   | Y座標が小さいほど手前（`YSortRenderer`）                            |

選手は回転させない。1枚絵を回転させると人が横倒しになるため、向きの表現はスプライトの差し替えだけで行う（`FacingDirection` はキック方向の計算にのみ使う）。

### チーム識別

| 対象          | 色                      |
| ----------- | ---------------------- |
| 自チーム（HOME）  | 青                      |
| 相手チーム（AWAY） | 赤                      |
| GK          | 緑（両チーム共通）              |
| 操作中の選手      | 足元に敷く黄色い楕円リング          |

ユニフォームは **同じ人型スプライトの色違い** で作り、素材の枚数を増やさない。

背番号はMVPでは描かない。22人が小さく表示されるため判別できず、素材数だけが増えるため。識別はチームカラーと操作マーカーで行う。

## 4.4 コート

見下ろしのサッカーコートとして描く。

```text
┌─────────────────────────┐
│┌──┐          │         ┌──┐│
││  │        ( ● )       │  ││
│└──┘          │         └──┘│
└─────────────────────────┘
  ペナルティエリア / センターサークル / センターライン
```

| 要素   | 内容                                             |
| ---- | ---------------------------------------------- |
| 芝    | 緑の横縞（明 / 暗の2色帯）                                |
| ライン  | 白・2px相当                                        |
| 描く内容 | 外周ライン / センターライン / センターサークル / ペナルティエリア / ゴールエリア / コーナーアーク |
| 実装   | コート全体を **1枚のスプライト**（352 x 192 px = 22 x 12 単位）として用意する |

ライン1本ずつをGameObjectにしない。1枚絵にすればSceneが軽くなり、2人開発でのコンフリクトも減る。

## 4.5 ゴール

ゴールは「ポスト + ネット」のスプライトで表現する。

| 要素   | 内容                                                  |
| ---- | --------------------------------------------------- |
| 見た目  | 白いポストとネット。ゴールラインの外側に配置                              |
| サイズ  | 14 x 68 px（縦4ワールド単位 = `GoalHalfHeight = 2f`）           |
| 左右   | 左ゴールの絵だけを用意し、右ゴールは `flipX` で反転して使う                  |
| 描画順  | コートより手前、選手より奥（固定値）                                  |
| 当たり判定 | 既存の `GoalTrigger` と壁コライダーをそのまま使い、見た目だけ差し替える          |

## 4.7 素材の扱い

素材は **エディタ拡張（`SoccerArtGenerator`）がコードから生成する**。外部素材の用意を待たずに絵を作り直せるようにするため。

* 生成先は `Assets/_Project/Games/01_Soccer/Sprites/`（通常のPNGアセット）
* 生成は `Tools > MiniGame > Generate Soccer Art`。`Build Soccer Scene` 実行時も未生成なら自動で作られる
* Import設定も生成時に自動で入る（`Filter Mode = Point` / `Compression = None` / `Pixels Per Unit = 16`）
* 選手のドット絵は1文字1ピクセルの文字列で定義してあるので、色や形はその文字列を直せば変えられる
* 後から手描きやAI生成のPNGへ差し替えてもよい。その場合は同名ファイルを置き換えるだけで済む

# 6. プレイヤー操作

## 6.1 基本操作

以下の操作を実装する。

* 移動
* パス
* シュート
* 選手切り替え
* スライディングタックル（簡易ディフェンス）

### スライディングタックル

操作中の選手が向いている方向へ短時間突進し、ボールに触れたら弾き飛ばす。ファウル判定・成否判定・イエローカード等は持たない（3章のMVP対象外方針を維持するため）。突進後は一定時間だけ移動速度が落ちる硬直を挟み、連発を防ぐことをリスクとする（実装: `SlidingTackle`）。

タックルが成立した瞬間、ボールに最も近かった相手選手を「奪われた側」としてよろけさせる。新規ドット絵は用意せず、既存スプライトを一瞬だけ回転・圧縮して転倒しているように見せ、その間は移動・キックができなくなる（実装: `TackleReaction`）。4.3節の「選手は回転させない」は向き表現についての方針であり、この演出はその副作用（回転させると横倒しに見える）をあえて利用したものなので、通常の向き変更ロジックには適用しない。

## 6.2 入力システム

Unity Input Systemを使用し、ゲームロジックと入力方法を分離する。

```text
             Input System
             /          \
            /            \
      キーボード        タッチ操作
           │                │
           └──────┬─────────┘
                  ↓
          Player Controller
                  ↓
               Player
```

開発初期はPCのキーボードで操作し、後からスマートフォン向けタッチ操作を追加する。

### キー割り当て（PC確認用）

`InputManager`（`Assets/_Project/Common/Scripts/Input/InputManager.cs`）が定義する対応表。同じ操作に複数キーを割り当てているものは、そのいずれかを押せばよい。

| 操作             | キーボード             | タッチ（仮想UI）  |
| -------------- | ----------------- | ----------- |
| 移動             | W/A/S/D または 矢印キー   | 左：仮想ジョイスティック |
| パス（弱いキック）      | J / Z / Space      | PASSボタン     |
| シュート（強いキック）    | K / X              | SHOOTボタン    |
| 選手切り替え（手動）     | L / C              | SWITCHボタン   |
| スライディングタックル    | 左Shift             | TACKLEボタン   |
| ポーズ            | Esc / P            | （画面内のPAUSEボタン） |

# 7. ボール

## 7.1 基本機能

* ボールの移動
* 選手との接触
* パス
* シュート
* ゴール判定

## 7.2 MVP時の簡略化

最初は複雑なボール物理を実装しない。

### パス

選手が向いている方向へ一定の速度でボールを蹴る。

### シュート

パスより強い速度でボールを蹴る。

```text
パス
  ↓
弱い速度

シュート
  ↓
強い速度
```

### ドリブル（キープ方式）

操作中の選手がボールに触れると「保持」状態になり、ボールは足元の少し前（向いている方向）について来る。物理の押し合いで運ぶ方式はボールが体に弾かれて離れてしまい「少し蹴るだけ」に見えたため、保持中は位置を直接追従させる（実装: `PlayerController` / `Ball.Hold`）。

```text
ボールに触れる（ボールが遅いときのみ）
  ↓
保持（足元に追従。保持者とボールの衝突は無効）
  ↓
以下のいずれかで保持解除
  ・パス / シュート
  ・タックルを受けた（よろけ）
  ・相手選手がボールに接触した（奪われた）
  ・選手切り替え / ゴール後リセット
```

* 手放した直後の短時間は保持し直さない（奪われた瞬間に奪い返す往復を防ぐ）
* 相手が近くにいるボールは保持できない。奪い返すにはスライディングタックルを使う
* AIのドリブルはMVP対象外。AIは従来どおりボールへ寄ってパス / シュートする

# 11. NPC / AI

操作対象以外の選手は簡易AIで制御する。

## 11.1 ポジション維持

各選手に基準ポジションを設定する。

```text
基準ポジション
      ↓
現在位置との差を計算
      ↓
基準位置へ移動
```

## 11.2 ボール追従（役割別の追従ウェイト）

現状の課題: 実装（`AIPlayerController.ComputeTargetPosition`）は「チーム内でボールに一番近い1人だけがボール座標を目標にし、それ以外は基準ポジションに固定（自チーム攻撃中のみ一律X軸シフト）」という挙動になっている。そのため、キック圏内に入れる1人以外は基準ポジションに棒立ちのまま見え、サッカーらしい流動感が出ない。

改善方針: 基準ポジションからボール方向へ、役割ごとの「追従ウェイト」を掛けた分だけ目標位置をずらす。ボールが動くたびに全員が少しずつ引っ張られるので、1人だけが突出して動くのではなく、チーム全体が流動的に見える。

```text
目標位置 = 基準ポジション + (ボール座標 - 基準ポジション) × 追従ウェイト
```

| 役割 | 追従ウェイト目安 | 補足                    |
| -- | -------- | --------------------- |
| FW | 0.5      | 一番ボールに反応してよい           |
| MF | 0.35     | ほどほどに反応                |
| DF | 0.2      | 守備ラインを大きく崩さない          |
| GK | 0（追従しない） | ゴール前に留まる。専用ロジックは11.3参照 |

キック可否の判定（チーム内で自分が最もボールに近いか）は変更しない。見た目の位置取りだけを変える改修とし、既存のパス/シュートロジックには影響させない。

## 11.3 GK（ゴールキーパー）専用ロジック

現状の課題: シーン生成時（`SoccerSceneBuilder`）にGKかどうかを判定するフラグ自体は存在するが、ユニフォーム色と初期位置に使われるだけで`AIPlayerController`には渡っていない。そのためGKもフィールドプレイヤーと全く同じAIロジックで動き、ボールが最も近づいた瞬間しか反応しない＝実質棒立ちになりやすい。

改善方針: GKは11.2のボール追従（役割別ウェイト）の対象から外し、専用のターゲット計算にする。

```text
GKの目標位置
  ↓
ゴールライン付近のX座標（固定、自陣ゴール前から動かさない）
  +
ボールのY座標に合わせて上下にスライド
  （可動範囲はゴール幅＝GoalHalfHeight相当に制限する）
```

ゴールエリアの外へ出て、フィールドプレイヤーのようにボールを追いかけることはしない。

## 11.4 攻撃・守備

自チームの攻撃・守備状況に応じて、基準位置を簡易的に変更する。

```text
自チームが攻撃
    ↓
少し前へ移動

相手チームが攻撃
    ↓
自分のポジションへ戻る
```

高度な戦術AIはMVPの対象外とする。
