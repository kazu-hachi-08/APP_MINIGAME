# ペンギン大戦争 じぶんペンギン（自作キャラ） 実装計画（INDEX）

オンライン対戦の10体目に、プレイヤーが自分で作ったキャラ「じぶんペンギン」を出せるようにするための **一時的な** 計画書。全フェーズ完了後にフォルダごと削除する（Phase 6）。

仕様書 `Docs/100_PENGUIN_WARS_SPEC.md` にはまだ書かれていない。じぶんペンギンの仕様は **この計画書が正** とし、Phase 6 で仕様書に反映する。

---

## AIへの指示（「じぶんペンギン計画のフェーズN進めて」と言われたら）

1. このINDEXを読み、下の「進捗」表で **フェーズNの前のフェーズがすべて完了** になっているか確認する。なっていなければ実装せずユーザーに伝える
2. `phaseNN_*.md`（対象フェーズのファイル）**だけ** を読む。他のフェーズのファイルは読まない（コンテキスト節約）
   * ただし直前フェーズの「引き継ぎメモ」は読む
3. フェーズファイルの「読むもの」に挙がった既存コード・仕様書の節だけを読む
4. 「作るもの」を実装する。「やらないこと」には手を出さない
5. 終わったら:
   * フェーズファイルの「引き継ぎメモ」を埋める（作ったファイル・公開API・計画から変えた点・次フェーズへの注意）
   * 下の「進捗」表を **完了** に更新する
   * ユーザーにフェーズファイルの「ユーザー確認手順」を伝える（AIはUnityエディタを操作できないので、Rebuild・再生確認はユーザーが行う）
6. ブランチ・コミット・PRはユーザーに言われたときだけ行う

計画と実装で食い違いが出たら、勝手に大きく変えずユーザーに確認する。小さな変更（クラス名・数値など）は引き継ぎメモに書けばよい。

## 決めた前提（変えたい場合は Phase 1 を始める前にユーザーと決め直す）

| 項目 | 決めたこと | 理由 |
| --- | --- | --- |
| 名前 | 「じぶんペンギン」。タイトルのボタン名も同じ | にゃんこ風の言い方でひらがな中心にそろえる |
| 使える場所 | **オンライン対戦だけ**。ステージ（1人）・ずかん・あそびかたには出さない | ステージの難しさの調整を崩さないため |
| 対戦での入り方 | ドラフトを **9回** にして、10体目にじぶんペンギンを入れる。編成は10体（5×2）のまま | 出撃ボタン・編成確認の枠を変えずに済む |
| 持ち込むプリセット | 作成画面に3枠。**ドラフトが終わった後に3枠から1つ選ぶ**（制限時間あり） | 相手の顔ぶれを見る前に、自分のドラフト結果に合わせて選べる駆け引き |
| 強さの決め方 | **役割＋コスト＋強化ポイント**。役割とコストで既存の計算式（`UnitStatFormula`）が基準値を出し、コストの段階で「触れる数値・強化ポイント・能力枠・範囲攻撃」が増える | 50体と同じ式なので、コストと強さがずれにくい |
| 見た目 | 既存パーツ（体の形・体色・頭・手・背中）から自由に選ぶ。**見た目は強さに影響しない**。拡大率は大型だけ自動で2倍 | パーツごとの効果表とバランス調整を作らずに済む |
| 絵の作り方 | 既存のドット絵合成（`PenguinFrameComposer` ほか）を実行時に動くよう `Scripts/` へ移し、作成画面と対戦開始時に `Texture2D` で作る | パーツの組み合わせを全部 PNG にするのは不可能なため |
| セーブ | `PlayerPrefs` のキー `PenguinWars.CustomUnits` に JSON 1本（ステージのセーブとは別キー） | ステージのセーブと独立して壊れない・2人で触る場所が分かれる |
| きまりの数値 | 純C#の `CustomUnitRules` の定数に置く（`PenguinWarsBalance` には置かない） | ホストとゲストで同じ値でないと検証結果がずれる。アセットは Rebuild で上書きされず端末ごとに違い得る |
| 不正・食い違い対策 | ホストがゲストのじぶんペンギンを **きまりに合わせて直してから**（`Sanitize`）使い、直した結果をゲストへ送り返す | 友達同士でも、古いビルドとの食い違いで片方だけ強くなるのを防ぐ |

## 仕様（このフェーズ群で作るもの）

### じぶんペンギンの中身（`CustomUnitDefinition`）

| 項目 | 内容 |
| --- | --- |
| `Name` | 名前。最大8文字（編成確認・出撃ボタンで切れないように） |
| `Role` | 役割5種（壁・アタッカー・遠距離・妨害・大型）。基準値（体力/コスト・火力/コスト・攻撃間隔・発生・ノックバック回数）が決まる |
| `Cost` | 役割のコスト帯の中（壁 50〜150 は10刻み、ほかは50刻み） |
| `Levels` | 強化レベル（体力・攻撃・射程・速度・再生産の5つ。各 -2〜+2。+3 まで許すと強すぎたため Phase 1 で +2 に決めた） |
| `IsAreaAttack` | 範囲攻撃にするか（段階3のみ） |
| `Abilities` | 能力（8種から、能力枠の数まで・重複なし） |
| `Look` | 体の形・体色・頭・手・背中の ID（既存パーツ） |

### コストの段階（触れる数値はコストで決まる）

段階は「役割のコスト帯の中でどの位置か（t = 0〜1）」で決める（役割ごとにコスト帯の幅が違うため）。

| 段階 | 帯の位置 t | 強化ポイント | 触れる数値 | 能力枠 | 範囲攻撃 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 〜 1/3 未満 | 2 | 体力・攻撃 | 0 | × |
| 2 | 1/3 〜 2/3 未満 | 3 | ＋速度・再生産 | 1 | × |
| 3 | 2/3 〜 1 | 4 | ＋射程 | 2 | ○ |

* 強化レベル1つで、その数値が **10%** 良くなる（再生産は 10% 短くなる）。-1 で 10% 悪くなる
* レベルを上げると強化ポイントを1使い、下げると1戻る（「体力を下げて速度に回す」のような個性づけができる）。合計はポイント以内
* 触れない数値のレベルは 0 に固定
* 最終の数値は `UnitStatFormula.Calculate` にそのまま通す（強化レベル → `StatTweak` の倍率）。能力1つにつき体力・火力 ×0.9、範囲攻撃は火力 ×0.75 も既存のまま効く（能力・範囲はタダではない）
* 能力の確率・時間は既存キャラと同じ（ふっとばす: 妨害 50%・ほか 30% / 止める 40%・2秒 / 遅くする 50%・3秒）
* 攻撃間隔・発生・ノックバック回数は役割ごとに固定（変えられない）
* コストを下げて段階が下がったら: 触れなくなった数値のレベルを 0 に戻し、枠を超えた能力を後ろから外し、範囲攻撃を切る。それでもポイントを超えていたら全レベルを 0 に戻す（`CustomUnitRules.Sanitize`。画面でも同じ関数を使う）

### プリセット（3枠）

* 最初から3枠ともお手本が入っている（空の枠を作らない。初めてでも対戦で選べるように）

| 枠 | 名前 | 役割・コスト | 強さ | 見た目 |
| --- | --- | --- | --- | --- |
| 1 | じぶんナイト | アタッカー 400（段階2） | 体力+1・攻撃+1・速度+1 / ふっとばす | basic・standard・helmet・sword_shield・cape_blue |
| 2 | じぶんアーチャー | 遠距離 800（段階2） | 攻撃+2・再生産+1 / 遠距離キラー | tall・ice・hood・bow・なし |
| 3 | じぶんまじん | 大型 3000（段階3） | 体力+2・攻撃+1・射程+1・範囲 / ふんばる | round・aurora・crown・staff・aurora |

### 対戦の流れ（変更後）

```text
部屋を作る / コードで参加 → 接続
  ↓
ドラフト（9ラウンド）
  ↓
じぶんペンギン選択（3枠から1つ・15秒。時間切れは前回選んだ枠）
  ↓ ゲスト → ホストへ定義を送る（pw.custom）
ステージ抽選（ホスト）
  ↓ ホスト → ゲストへ 編成＋ステージ＋両者のじぶんペンギン（pw.deck を拡張）
編成確認（10体ずつ。じぶんペンギンには「じぶん」の印）
  ↓
START! → プレイ
```

* じぶんペンギンのキャラ No はホスト側が `91`、ゲスト側が `92`（`CustomUnitRules.LeftNo / RightNo`。スナップショットはキャラNoを byte で送るので 255 以下にし、既存の 1〜50 と離す）
* ゲストの画面は左右反転されるが、No は入れ替えない。ゲストの画面では No 92（自分）が左・青、No 91（相手）が右・赤で描かれる

## 全体設計（全フェーズ共通）

```text
CustomUnitDefinition（純C#。名前・役割・コスト・強化レベル・能力・見た目ID）
   │  CustomUnitRules.Sanitize / ToUnitDefinition(no)
   ▼
UnitStatFormula.Calculate → UnitStats（戦闘はこれだけ見る。既存キャラと区別しない）
   │
   │  見た目ID → PenguinLook → RuntimeUnitSprites.Build（実行時に Texture2D で5コマ×2陣営）
   ▼
PenguinUnitData（ScriptableObject.CreateInstance）を PenguinUnitCatalog に「実行時の登録」として足す
   → 出撃ボタン・ユニットの絵・編成確認は catalog.Get(no) のまま動く
```

* カタログに実行時登録しておけば、`catalog.Get(no)` を使っている UI（`UnitButtonBar` / `UnitViewPool` / `DeckRevealPanel` など）を書き換えずに済む
* カタログはアセットなので、実行時の登録は **シリアライズしない辞書** に持ち、試合の初期化のたびに消す（エディタで再生を繰り返しても残らないように）

### 規約（既存計画と同じ）

* SceneBuilder は `partial class` で分割
* 1ファイル300行を目安に、超えそうなら役割で分ける
* 数値は定数・`[SerializeField]` に置く（マジックナンバー禁止）。きまりの数値は `CustomUnitRules`
* 共通基盤（`Assets/_Project/Common/`）は変更しない。必要になったらユーザーに確認する
