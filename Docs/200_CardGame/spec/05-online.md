# 05. オンライン対戦

> ステータス: ドラフト v0.1 / 最終更新: 2026-09-21
> 実装はフェーズ4。ただし Core の設計(コマンド/決定論)はフェーズ2から従う。

## 方針

- **サーバーレス**: Unity Gaming Services の **Relay** で 2 端末を直結、**Lobby** は使わず Relay の Join Code(6 文字)を部屋コードとしてそのまま使う
- **ホスト権威 + 決定論ロックステップ**:
  - 部屋を作った側がホスト。ホストが乱数シードを決めて共有
  - 両端末が同じ Core を持ち、同じコマンド列を同じ順序で適用すれば同じ状態になる
  - ゲスト側の操作は「コマンド」としてホストに送り、ホストが検証して両者に配信する
- **不正対策はしない**: 友人間の対戦なので、相手の手札がメモリ上に見える等は許容する(ADR-0002)

## 通信ライブラリ

- **Netcode for GameObjects (NGO)** + **Unity Transport** + **Relay**
- UGS の無料枠(Relay: 同時接続数ベース)で友人規模は十分
- UGS のプロジェクト作成には Unity アカウントでのダッシュボード操作が必要。フェーズ4開始時にオーナーに依頼する(オーナー作業)

## コマンド(Core 側の定義)

プレイヤーの操作は全てこの型で表現する。ローカル対戦・AI・オンラインで共通。

| コマンド | パラメータ | 備考 |
|---|---|---|
| `Mulligan` | 戻すカードの手札インデックス配列 | |
| `PlayCard` | 手札インデックス, 場の挿入位置, 対象(任意) | |
| `Attack` | 攻撃フォロワー, 対象 | |
| `EndTurn` | — | |
| `Surrender` | — | |

Core は `Apply(command)` で状態を進め、発生した **イベント列**(Draw, Damage, Destroy, …)を返す。Unity はイベントを見て演出する。

## 接続フロー

```
ホスト                                  ゲスト
  │ Relay 割当 → JoinCode 表示             │
  │                                        │ JoinCode 入力 → Relay 接続
  │ ←──────── 接続完了 ───────────────────│
  │ デッキ・シード・先攻後攻を送信 ───────→│
  │ 両者 Core を初期化(同一状態)          │
  │ ←──── コマンド ──── / ──── コマンド ──→│   (手番のプレイヤーだけ送れる)
  │ ホストが検証・採番してブロードキャスト   │
```

## 切断・再接続

- 切断検知から **60 秒**は再接続待ち。Relay の再接続で復帰したらホストがコマンド履歴を再送し、ゲストは Core を再構築する
- 60 秒を超えたら切断側の敗北
- **初期実装では再接続を省略し、切断 = 切断側の敗北**とする。再接続はフェーズ5以降の検討事項

## ターン制限
- 1 ターン 90 秒。ホスト側のタイマーが正。超過で `EndTurn` を自動発行
- 残り 10 秒で警告表示

## 将来の検討
- 観戦(3 人目が読み取り専用で接続)
- リプレイ(コマンド列 + シードを保存すれば再生できる。Core の設計上ほぼ無料で実現可能)

## 実装メモ(フェーズ4 実装時に確定)

- Netcode for GameObjects の **NamedMessage だけ**を使う(NetworkObject / プレハブは使わない)。メッセージ:
  `hello`(ゲスト→ホスト: デッキ)/ `start`(ホスト→ゲスト: シード・先攻・両デッキ)/
  `req`(ゲスト→ホスト: コマンド)/ `cmd`(ホスト→ゲスト: 確定コマンド)/ `rej`(拒否理由)
- **ゲストは自分の操作もホストの echo を待ってから適用する**。これで両端末のコマンド順が必ず一致する
- マリガンは両者同時に行える(順序はホストが決める)
- WebGL(ブラウザ)は Unity Transport の WebSocket + Relay の `wss` エンドポイント。Android/Windows は `dtls`
- ブラウザ版の部屋コード入力は `window.prompt`(Unity の InputField はスマホ Safari でキーボードが開かないため)
- 部屋コードは Relay の Join Code(6 文字英数字)。Relay 割当は接続が無いまま約 10 秒で失効するため、
  ホストは「部屋を作る」を押してから相手が来るまで画面を閉じない
- UGS の Project ID は `ProjectSettings/ProjectSettings.asset` の `cloudProjectId`。組織 `jiantailangdasen6`

## デッキの送り方(2026-09-23、ドラフト対応)

- プリセットのデッキは**名前**だけを送る(両端末が同じプリセットを持っているため)
- ドラフトなど、相手の端末に無いデッキは**中身ごと**送る: `deck:<クラス>|<デッキ名>|<カードID>,<カードID>,…`(`Core` の `DeckCodec`)
- 受け取った側はデッキ構築ルール(01-rules.md / 07-draft.md)で検証し、不正なら接続を切る
- 30 枚で 200 バイト程度なので、既存のメッセージ(`hello` / `start`)にそのまま載せる

## ドラフトの部屋(2026-09-23、07-draft.md の案 2)

- ドラフトの部屋では、`hello` のデッキの代わりに印 `@draft` を送る。ホストとゲストの両方が `@draft` なら、ホストがシードを決めて
  `draft`(ホスト→ゲスト: シード)を送り、2 人が同じシードでドラフトを始める。片方だけが `@draft` なら `fmt`(形式違い)を送って切断する
- `prog`(双方向: 何回選んだか)で相手の進み具合を表示する
- 選び終えた側はデッキを中身ごと送る(ゲストは `hello` をもう一度、ホストは自分の分を保持)。両方揃ったらホストが `start` を送る

## 招待リンクとコピー / 貼り付け(2026-09-23、オーナー決定)

コード入力の手間を省く。サーバーの追加設定は不要(リンクは Relay の部屋コードを URL に載せるだけ)。

- **招待リンク**: `https://jiantailangdasen6-rgb.github.io/cardgame-web/?room=<コード>`(ドラフトの部屋は `&mode=draft` を付ける)
  - ブラウザ版はいま開いている URL を元に作る。Android / Windows 版は上の公開 URL を使う
  - 添える文: 「THE CHAOS Ⅱ で対戦しよう!(ドラフト)/ 部屋コード: XXXXXX」+ リンク。リンクを開けない相手もコードを読める
- **ホスト**: 部屋を作ると「招待リンクを送る」「コードをコピー」を出す
  - 「招待リンクを送る」: スマホのブラウザは共有画面(LINE などを選べる)、それ以外はクリップボードへコピー。
    どちらも使えないブラウザでは、リンクを表示するダイアログを出して手でコピーしてもらう
- **ゲスト(リンクを開いた)**: 起動時に URL の `room` を読み、URL からは消す(再読み込みで入り直さない)。
  - 通常の部屋: オンライン対戦のデッキ選択へ直行(「招待された部屋に入ります」と表示、ドラフトは選べない)→ 決定で自動参加
  - ドラフトの部屋: 部屋の画面へ直行して自動参加
  - 「← 戻る」を押したら招待は捨てる
- **ゲスト(貼り付け)**: 部屋コード欄の横の「貼り付け」で、クリップボードからコードを取り出してそのまま参加する。
  取り出せるのは リンク(`room=`)・招待文(「コード:」の後)・コードだけ のどれでも。
  クリップボードを読めないブラウザでは入力ダイアログを出す(長押しで貼り付けられる)
- フレンド機能・部屋一覧は採らない(名前登録やサーバー側の設定が要り、友人に配る規模には重い)
