# 第1弾ミニゲーム：2Dサッカーゲーム 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第1弾ミニゲーム。見下ろし視点の11 vs 11サッカーで、CPU戦とオンライン1対1を遊べる。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 2Dサッカー |
| 視点 | 見下ろし視点（Top-down View）・横画面固定 |
| グラフィック | 2Dピクセルアート（選手は人型スプライト） |
| プレイ人数 | 1人（CPU戦）/ 2人（オンライン1対1。§9） |
| チーム人数 | 11 vs 11 |
| 試合時間 | 2分（`SoccerGameManager._matchDurationSeconds = 120`） |
| 対象プラットフォーム | Android / iPhone（PCはキーボードで確認用） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/01_Soccer/`。Sceneは `Tools > MiniGame > Rebuild Soccer`（`SoccerSceneBuilder`）でコードから生成する（ドット絵素材も同時に描き直す）。

## 2. ルール・試合の流れ

### 2.1 試合の流れ

```text
モード選択（CPUと対戦 / 部屋を作る / コードで参加）
  ↓
KICK OFF!（笛・1.0秒）   ← AIはフォーメーションを維持
  ↓
プレイ（残り時間が減る）
  ├ ゴール → GOAL! (HOME/AWAY)（1.5秒）→ 全員とボールを初期位置へ → KICK OFF!
  ├ ボール停滞 → RESET（1.0秒）→ 全員とボールを初期位置へ → KICK OFF!
  └ 残り0秒 → TIME UP（笛・1.5秒）→ リザルト
```

* キックオフは常にセンター（ボール初期位置 `(0, 0)`）から。得点した側・された側による区別はない
* 残り時間は `Playing` 中だけ減り、ゴール・リセット・キックオフ演出中は止まる
* ボール停滞リセット: ボールの速さが 0.15 以下の状態が 4秒続いたら、ゴール時と同じ手順で仕切り直す（選手とボールが挟まって試合が止まるのを救済するため）

### 2.2 ゴール・得点

* ゴールラインの外側に奥行き 1.0 のゴールポケットがあり、その中の判定センサー（`GoalTrigger`、高さ = ゴール幅 4）にボールが入ったらゴール
* 得点は守っていたチームの逆側に1点。表示は `HOME 1 - 0 AWAY`（HOME / AWAY の表記はユーザー名に置き換わる。§8 スコア欄）
* `Playing` 以外（演出中など）のゴール侵入は無視する

### 2.3 勝敗

| 結果 | リザルトのタイトル | 詳細 |
| --- | --- | --- |
| 自分の得点が多い | VICTORY! | 勝利！ |
| 相手の得点が多い | GAME OVER | 敗北... |
| 同点 | GAME OVER | 引き分け |

リザルトからリトライ（Scene再読み込み）またはタイトルへ戻れる。延長・PK戦はない。

### 2.4 フィールドの境界

タッチライン・ゴールラインの外は壁で、ボールは跳ね返る（スローイン・ゴールキック・コーナーキックはない）。

* 四隅には長さ 0.6 の斜めの壁（面取り）を置き、直角の隅にボールが挟まらないようにする
* ゴールの左右の壁はゴールポケットの奥行き全体を塞ぎ、ポスト脇からポケットへ回り込めないようにする
* ボールの物理: 半径 0.25、`linearDamping = 1.5`、反発 0.75、摩擦 0.05

### 2.5 ゲーム状態

共通基盤の `MiniGameState`（`BaseMiniGameManager`）をそのまま使う。サッカー専用のenumは持たない。

| 状態 | サッカーでの意味 |
| --- | --- |
| Ready | 初期化・モード選択中 |
| Countdown | KICK OFF! 表示中 |
| Playing | プレイ中（時間が進み、AIがボールを追う） |
| Event | GOAL / RESET / TIME UP の演出中 |
| Paused | ポーズ中（CPU戦のみ。オンラインは§9.4） |
| GameOver → Result | 試合終了・リザルト表示 |

## 3. チーム構成

HOME（青）は左ゴールを守り右（+X）へ攻める。AWAY（赤）はHOMEの配置をX反転したもので、右ゴールを守り左へ攻める。

| 番号 | 役割 | HOMEの基準ポジション |
| --- | --- | --- |
| 0 | GK | (-15.8, 0) |
| 1〜4 | DF | x = -10.7、y = -6.9 / -2.4 / 2.4 / 6.9 |
| 5〜8 | MF | x = -3.5、y = -6.9 / -2.4 / 2.4 / 6.9 |
| 9 | FW | (-1.1, 0)。キックオフ時の操作選手。味方AIより先にボールへ触れるよう最もセンター寄り |
| 10 | FW | (-4.8, 5.6) |

* GKは操作の切り替え候補から外す（常にAI）。ゴールを空けないため
* フォーメーション変更・選手交代はない

## 4. 画面・ビジュアル

### 4.1 画面とカメラ

* 横画面固定（`ScreenOrientationApplier`）
* コート全体ではなく操作中の選手の周辺を映す（`CameraFollow`、`orthographicSize = 3.5`）。22人を全体表示すると小さすぎるため
* カメラはコート端から 1.5 の余白までに制限し、コート外を大きく映さない
* コートは 33 x 18 ワールド単位（`FieldHalfWidth = 16.5` / `FieldHalfHeight = 9`）

### 4.2 ビジュアル方針

```text
方針
  ・ドット絵（低解像度・Point フィルタ）
  ・はっきりした輪郭と彩度の高い色
  ・青チーム vs 赤チーム
  ・コート外に観客席を敷いてスタジアムらしさを出す

やらないこと
  ・横視点やアップのキャラクター表現
  ・細かい群衆表現
  ・高解像度イラスト
```

### 4.3 選手の見せ方

見下ろし視点で人型に見せるため、**やや斜め上から見たキャラクター** として描く。真上からの完全な俯瞰（頭と肩だけ）にはしない。

```text
    ○     頭
   ╱█╲    胴（チームカラーのユニフォーム）
    ╹╹    足
   ____   影（楕円・半透明）
```

| 項目 | 内容 |
| --- | --- |
| スプライト | 1体 16 x 16 px、PPU 16（表示 1.0 x 1.0 単位） |
| 原点 | 足元（下から1.5px）。足の位置とコライダー中心を合わせるため |
| 向き | 4方向。左右は右向きを `flipX` で反転するので画像は3方向分。速度の向きで切り替える |
| アニメ | 待機 1枚 + 走り 2枚のコマ切り替えのみ（`PlayerSpriteAnimator`、0.12秒/コマ） |
| 影 | スプライトの最下行に描き込む（GameObjectを増やさない） |
| 描画順 | Y座標が小さいほど手前（`YSortRenderer`）。ボールは同じYの選手より手前、操作マーカーは奥 |
| 当たり判定 | 半径 0.2 の円、質量 5 |

選手は回転させない。1枚絵を回転させると人が横倒しになるため、向きの表現はスプライトの差し替えだけで行う（`FacingDirection` はキック方向の計算にのみ使う）。例外はタックルを受けたときのよろけ演出（§6.5）。

| 対象 | 見た目 |
| --- | --- |
| HOME | 青 |
| AWAY | 赤 |
| GK | 緑（両チーム共通） |
| 操作中の選手 | 足元に敷く黄色い楕円リング |

ユニフォームは同じ人型スプライトの色違いで作る。背番号は描かない（22人が小さく表示されるため判別できず、素材数だけが増えるため）。

### 4.4 コート

| 要素 | 内容 |
| --- | --- |
| 芝 | 緑の横縞（明 / 暗の2色帯） |
| ライン | 白・2px相当 |
| 描く内容 | 外周ライン / センターライン / センターサークル / ペナルティエリア / ゴールエリア / コーナーアーク |
| 実装 | コート全体を **1枚のスプライト**（528 x 288 px）として置く |

ライン1本ずつをGameObjectにしない。Sceneが軽くなり、2人開発でのコンフリクトも減る。

### 4.5 ゴール

| 要素 | 内容 |
| --- | --- |
| 見た目 | 白いポストとネット。ゴールラインの外側に配置 |
| サイズ | 14 x 68 px（枠内 = 縦4単位、`GoalHalfHeight = 2`） |
| 左右 | 左ゴールの絵だけを用意し、右ゴールは `flipX` で反転 |
| 描画順 | コートより手前、選手より奥（固定値） |

### 4.6 コート外の背景

* カメラ背景は暗いグレー
* コートの四辺の外側に観客席タイル（1枚を繰り返し）を敷く
* 個別の観客・歓声アニメーション・スコアボードや照明などの立体物は作らない

### 4.7 素材の扱い

素材はエディタ拡張 `SoccerArtGenerator` がコードから生成する。外部素材の用意を待たずに絵を作り直せるようにするため。

* 生成先は `Assets/_Project/Games/01_Soccer/Sprites/`（通常のPNGアセット）
* `Tools > MiniGame > Rebuild Soccer` 実行時に毎回描き直す
* Import設定も自動で入る（`Filter Mode = Point` / `Compression = None` / `Pixels Per Unit = 16`）
* 選手のドット絵は1文字1ピクセルの文字列で定義してあり、色や形はその文字列を直せば変わる
* 手描きやAI生成のPNGへ差し替える場合は、同名ファイルを置き換えるだけで済む

## 5. 操作

### 5.1 操作対象と切り替え

プレイヤーは自チームのGK以外の10人のうち1人を操作し、それ以外はAIが動かす（`PlayerSwitcher` が `PlayerController` / `SlidingTackle` と `AIPlayerController` の有効・無効を入れ替える）。

| 種類 | 挙動 |
| --- | --- |
| 自動切り替え | 0.25秒ごとに、ボールに最も近い候補へ操作を移す。操作中の選手がボールから 1.2 以内にいる間は切り替えない（ドリブル中に勝手に外れないため） |
| 手動切り替え | 今の操作選手を除いて、ボールに最も近い候補へ移す |
| 共通 | 切り替え直後 0.5秒は自動切り替えしない。`Playing` 中のみ動く |

* キックオフ時・リセット時は FW（§3 の番号9）に戻す
* カメラと操作マーカーは操作選手を追う

### 5.2 入力

入力は共通基盤の `InputManager`（Unity Input System）が `IInputProvider` として提供し、キーボードと仮想UIは同じ経路で扱う。オンラインのホストではAWAY選手が `RemoteInputProvider` を入力元にする（§9）。

| 操作 | キーボード | タッチ（仮想UI） |
| --- | --- | --- |
| 移動 | W/A/S/D または 矢印キー | 仮想ジョイスティック |
| パス（Action1） | J / Z / Space | PASS |
| シュート（Action2） | K / X | SHOOT |
| 選手切り替え（Action3） | L / C | SWITCH |
| スライディングタックル（Action4） | 左Shift | TACKLE |
| ポーズ | Esc / P | 右上の「II」ボタン |

### 5.3 スマホの画面レイアウト

Canvasの参照解像度 1920x1080。仮想コントロールはPCでも表示し、マウスでタッチ操作を確認できる。

```text
┌──────────────────────────────────────┐
│           HOME 0 - 0 AWAY        [II]│
│               2:00                   │
│                                      │
│                       (TACKLE) (SWITCH)
│                                      │
│  ( ◉ )               (PASS)  (SHOOT) │
└──────────────────────────────────────┘
```

| 要素 | 位置（アンカーからの距離） | 大きさ |
| --- | --- | --- |
| ジョイスティック | 左下から (280, 280) | 直径 300 |
| SHOOT | 右下から (-220, 240) | 190（最大。使用頻度が高いので親指の手前） |
| PASS | 右下から (-450, 150) | 160 |
| SWITCH | 右下から (-200, 500) | 140 |
| TACKLE | 右下から (-450, 420) | 150 |
| PAUSE（II） | 右上から (-80, -70) | 90 |

## 6. ボール・キック

数値は操作選手（`PlayerController` / `SlidingTackle`）の既定値。AIのキックは§7.4。

### 6.1 パス

* 速度 7 で蹴る。キックできるのはボールが 0.7 以内にあるとき
* 向いている方向から ±60°・10 以内に味方がいれば、その味方へ方向を自動補正する（角度のずれが小さく近い味方を優先。`KickAim.PassDirection`）。入力方式を変えずに横や斜めへ出せるようにするため

### 6.2 シュート

* 速度 16 で蹴る
* 相手ゴール中央から 12 以内なら、ゴール枠内へ方向を自動補正する。スティックの上下成分でゴール中央から最大 ±1.2 ずらして狙う（`KickAim.ShotDirection`）
* 圏外なら向いている方向へそのまま蹴る

### 6.3 ドリブル（キープ方式）

操作選手がボールに触れると「保持」状態になり、ボールは向いている方向へ 0.4 ずれた足元について来る。物理の押し合いで運ぶとボールが体に弾かれて離れてしまうため、保持中は保持者とボールの衝突を切って追従させる（`PlayerController` / `Ball.Hold`）。

```text
ボールが 0.6 以内・速さ 5 以下
  ↓
保持（足元に追従）
  ↓
以下のいずれかで保持解除
  ・パス / シュート（誰が蹴っても保持は解除される）
  ・タックルを受けた（よろけ）
  ・相手選手がボールの 0.45 以内に 0.3秒 張り付いた（奪われた）
  ・選手切り替え / ゴール後リセット
```

* 手放した直後 0.5秒は保持し直さない（奪われた瞬間に奪い返す往復を防ぐ）
* 速いボール（パス・シュート）は保持しない。横取りしてしまうため
* AIは保持中のボールを蹴れない。奪うには張り付くかタックルを使う
* AIはドリブル（保持）をしない（§7.4）

### 6.4 スライディングタックル

操作選手が向いている方向へ突進し、ボールに触れたら弾き飛ばす（`SlidingTackle`）。ファウル判定・成否判定・カードはない。

| 項目 | 値 |
| --- | --- |
| 突進 | 速度 7 で 0.25秒 |
| 弾く | 半径 0.55 以内のボールを突進方向へ速度 7 で。1回のタックルで1回だけ |
| 狙い補正 | 2.5 以内・向きから ±60° 以内にボールがあれば、突進方向をボールへ向ける（空振り防止） |
| 硬直 | 突進後 0.4秒は移動速度 2.5 に落ちる（連発を防ぐリスク） |

### 6.5 よろけ（タックルを受けた側）

ボールを弾いた瞬間、ボールから 1.0 以内で最も近い相手選手を「奪われた側」としてよろけさせる（`TackleReaction`）。

* 0.5秒間、移動・キックができない
* 転倒用のドット絵は作らず、スプライトを Z軸 90° 回転・縦 0.5倍に潰して倒れたように見せる。§4.3「選手は回転させない」は向き表現の方針であり、横倒しに見える副作用をあえて演出に使っている

## 7. AI

操作選手以外は `AIPlayerController` で動く。移動速度は 3.8（操作選手 4.5 より遅い）。`Playing` 以外（キックオフ・ゴール演出中）は誰もボールを追わず、基準ポジションへ戻る。全員がボールへ殺到して操作選手が触れなくなるのを防ぐため。

### 7.1 目標位置の決め方（フィールドプレイヤー）

```text
① チーム内で自分が最もボールに近く、ボールとの距離が 8 以内
     → ボールの位置へ向かう
② それ以外
     基準 = 基準ポジション
     ボールが相手陣（攻撃方向側の半分）にある → 基準を攻撃方向へ 3.5 ずらす
     目標 = 基準 + (ボール位置 - 基準) × 追従ウェイト
```

追従ウェイトは基準ポジションの前後位置で線形に決まる。自陣ゴールライン上で 0.15、相手ゴールライン上で 0.5（前線ほどボールに反応し、守備ラインは崩れにくい）。現在の配置では DF ≈ 0.21、MF ≈ 0.29、FW ≈ 0.27〜0.31。ボールが動くたびに全員が少しずつ引っ張られるので、1人だけが動いて他が棒立ちに見えることがない。

### 7.2 GK

* 基準ポジションが自陣ゴールラインから 1.5 以内の選手をGKとみなす（専用フラグは持たない。既存Sceneのままでも動くように）
* X座標は基準ポジションに固定し、Y座標だけボールに合わせて基準から ±1.6 の範囲で動く
* ゴール前を離れてボールを追いかけることはない。ボールが 0.6 以内に来れば §7.4 のキック判断をする

### 7.3 攻守

攻守の切り替えは §7.1 の「ボールが相手陣なら 3.5 前へ」だけ。マーク・プレス・ゾーン守備などの戦術はない。

### 7.4 キック判断

チーム内で最もボールに近く、ボールが 0.6 以内・保持されていない・前回のキックから 1.0秒 経過しているときに判断する。

| 優先 | 条件 | 行動 |
| --- | --- | --- |
| 1 | 相手ゴール中央から 7 以内 | ゴール中央 ±0.8 のランダムな位置へ速度 12 でシュート |
| 2 | 9 以内に、自分より 1.5 以上攻撃方向へ前にいる味方がいる | その中で最も前の味方へ速度 7 でパス |
| 3 | どちらもない | 蹴らずにボールへ向かい続ける（体で押して運ぶ形になる） |

## 8. UI・演出・サウンド

### 8.1 UI

| 要素 | 内容 |
| --- | --- |
| スコア | 画面上部中央。`HOME 0 - 0 AWAY`。CPU戦は HOME を自分のユーザー名に（例 `たろう 0 - 0 AWAY`）。オンラインは HOME / AWAY を双方のユーザー名にし、自分側に `(YOU)`（例 `たろう(YOU) 1 - 0 はなこ`）。名前が届かなかった側は HOME / AWAY のまま |
| 残り時間 | スコアの下。`m:ss`、秒は切り上げ（残り0.1秒でも「0:01」） |
| 中央メッセージ | KICK OFF! / GOAL! (HOME) / RESET / TIME UP（黄色の太字。GOAL! の括弧内もスコアと同じ名前） |
| PAUSE | 共通ダイアログ（再開 / リスタート / タイトルへ） |
| リザルト | 共通ダイアログ（§2.3） |
| モード選択 | 試合前に表示（§9.1） |

タイトル画面は共通基盤のTitleSceneから「2D サッカー」で起動する。

### 8.2 ゴール演出

* 画面フラッシュ: 黄白色を不透明度 0.55 から 0.45秒でフェードアウト（`GoalEffect`）
* 中央メッセージを 1.7倍から 0.25秒で等倍へ縮める
* ゴール本体を横 1.25倍・縦 0.75倍に潰して 0.3秒で揺れ戻す（`GoalReaction`）。ネットだけを揺らす素材がないため、ゴール絵全体で手応えを出す
* アニメーションクリップやTweenライブラリは使わず、コルーチンで完結させる

### 8.3 サウンド

| タイミング | SE |
| --- | --- |
| キックオフ / TIME UP | 笛（`SeId.Whistle`） |
| ゴール | 歓声（`SeId.GoalCheer`） |
| キック | `SeId.Kick`。速度 10 以上はシュート扱いでピッチ 0.85、未満はパス扱いでピッチ 1.2。素材を増やさずに蹴り分けを表現する |
| 勝利 / 敗北・引き分け | 共通の `GameClear` / `GameOver` |

SE素材は未用意のため、`ProceduralSe` がコードで生成した仮の音を鳴らしている。

## 9. オンライン対戦

### 9.1 方針

卓球（`02_TABLE_TENNIS_SPEC.md` のオンライン対戦の章）と同じく、参加コードを共有して離れた2人が1対1で対戦する。

```text
Netcode for GameObjects（NGO）＋ Unity Multiplayer Services（Relay）
```

接続部分（`OnlineSession` / `ModeSelectPanel`）は卓球と共通で `Assets/_Project/Common/Scripts/Online/` にある。

```text
モード選択
 ├ CPUと対戦 → 試合（HOMEを操作）
 ├ 部屋を作る → 参加コード表示 → 相手の参加待ち → 試合（ホスト。HOME・青を操作）
 └ コードで参加 → 接続 → 試合（ゲスト。AWAY・赤を操作）
```

### 9.2 同期の考え方

ボールと22人が常に接触し合うため、各端末で物理を計算すると結果がずれる。そこで **ホストだけが試合を計算し、ゲストは入力を送って表示するだけ** にする。

```text
ゲスト：入力（移動・パス・シュート・切替・タックル）を送る
  ↓
ホスト：AWAYの操作選手をその入力で動かし、AI・物理・ゴール判定・得点・時間・停滞リセットをすべて計算
  ↓
ホスト：選手22人とボールの状態、スコア、残り時間を毎秒約30回送る
  ↓
ゲスト：届いた状態へ滑らかに寄せて表示（物理・AI・操作・切り替えは止める）
```

| 送る内容 | 向き | 配信 |
| --- | --- | --- |
| 選手22人の位置・速度・よろけ中か、ボールの位置・速度、スコア、残り時間、両チームの操作選手番号 | ホスト → ゲスト | 再送なし（古いものは捨てる）。約30回/秒 |
| 中央メッセージ、笛・歓声、キック音（速度つき）、ゴール、試合終了 | ホスト → ゲスト | 再送あり |
| 移動入力 | ゲスト → ホスト | 再送なし。約30回/秒 |
| ボタンを押した瞬間 | ゲスト → ホスト | 再送あり（取りこぼすと操作が効かないため） |

* NetworkObjectは使わず、名前付きメッセージだけで送る（Prefab登録などの準備を不要にするため）
* 選手は HOME 11人 → AWAY 11人 の並び順の番号で両端末を対応付ける
* ゲストは届いた速度で最大 0.12秒 先読みした位置へ補間する。3 以上離れていたら補間せず瞬時に合わせる（ゴール後のリセットなど）
* よろけは開始の瞬間だけ伝え、起き上がりはゲスト側の `TackleReaction` のタイマーに任せる
* 実装: `SoccerOnlineLink`（送受信）/ `SoccerGuestView`（ゲストの表示）/ `RemoteInputProvider`（ホストでゲスト入力を `IInputProvider` として渡す）。AWAYの切り替えは2つ目の `PlayerSwitcher` が担当し、ホストでだけ有効にする

### 9.3 視点

画面の左右反転はしない。ゲストはAWAY（赤）として右側のゴールを守り、左へ攻める。スコア表示の自分側に `(YOU)` を付ける。

### 9.4 その他のルール

* PAUSE：相手の端末は止まらないため、試合は止めずに自分の入力だけ止めてPAUSE画面を出す。ポーズキーをもう一度押すと閉じる
* 試合中に接続が切れたら、その時点で試合終了（リザルトは GAME OVER・「相手との接続が切れました」）
* 再戦はリトライでモード選択からやり直す

## 10. 既知の制限

* オンラインのゲストの操作は、通信の往復時間ぶん遅れて反映される
* ゲストの画面は約30回/秒の状態を補間して表示するため、ボールの細かい跳ね返りが少し丸まって見える
* 切断からの再接続はしない
* KICK OFF! 表示中、AIはボールを追わないが、操作選手は動けてボールも蹴れる（入力を止めていないため）
* SEは仮の生成音（§8.3）
