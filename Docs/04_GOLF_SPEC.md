# 第5弾ミニゲーム：2Dゴルフゲーム 仕様書

## 1. 概要

本ゲームは、「週末2人開発 2Dミニゲームプロジェクト」における第5弾ミニゲームとして開発する。

『みんなのGOLF』のような**気軽に遊べるゴルフ**を、真上視点の2Dで作る。
3タップのショットゲージで打ち、風・ライ（地面の種類）・グリーンの傾斜を読みながら、少ない打数でカップインを目指す。

モルック（§03）で作った以下の考え方を流用する。

* ロジックは地面の平面座標（X/Z）＋見た目用の高さH で計算する
* 入力・NPC・オンラインが同じリクエスト（`ShotRequest`）を作って打つ
* ルールは MonoBehaviour を使わない純粋クラスにして、EditModeテストで検証する
* オンラインは「打った人の端末で結果を確定し、最終結果を送る」ターン制の同期にする

本ゲームの中心となる体験は、**「風と曲がりを読んで、狙った場所にピタッと止める」**ことである。

# 3. MVP方針

最初から本格的なゴルフを目指さず、**ゴルフとして成立する最小限の機能**を実装する。

```text
✓ Tilemapで作ったホール（後から追加できる形式）

✓ インパクトのずれによるフック／スライス

✓ クラブ4種類（ドライバー／アイアン／ウェッジ／パター）
✓ 風（ホールごとに向き・強さが変わる）
✓ ライによる飛距離の変化（ラフ・バンカー）
✓ 池・OBの1打罰
✓ グリーンの傾斜（パットが曲がる）と傾斜表示
✓ カップイン判定
✓ 打数上限（パー×2で打ち切り）
✓ 1ホールモード／3ホールモード（登録ホールからランダム）
✓ スコアカード（パー・打数・合計）

✓ オンライン対戦（2〜4人・順番制）
✓ Android動作

```

## MVP対象外

```text
△ iPhone対応
△ スピン（バックスピン・トップスピン）
△ 木・崖などの高さのある障害物（当たり判定）
△ 高低差のある地形（打ち上げ・打ち下ろし）

△ パワーショット・必殺ショットなどの独自要素

```

必要性が確認できた場合のみ、MVP完成後に追加する。

# 4. 画面・視点

## 4.1 視点

**真上からコースを見下ろす視点**とする。縦持ちで、ティーが下、グリーンが上になるようにホールを作る。

```text
┌──────────────────┐
│ H1 PAR4  🌬→3m   │ ← ホール・パー・風
│ ▶P1 2打  P2 3打   │ ← 打数
│      ░⛳░        │
│     ░░░░░  ~~~   │ ← グリーン・池
│    ▒▒▒▒▒▒  ~~~   │
│   ▒▒▒▒▒▒▒        │ ← フェアウェイ
│  ::  ▒▒▒▒▒       │ ← バンカー
│      ▒▒▒ ◯       │ ← 着地予測
│       ▒ ╱        │ ← 打つ方向
│        ●         │ ← ボール
│ [1W] ▕████▏ 180y │ ← クラブ・ゲージ・飛距離
└──────────────────┘
```

## 4.2 座標と高さ

モルックと同じく、**ロジックは地面の平面座標で計算し、高さHは自前で計算する**。

```text
X：左右
Z：奥行き（Unityのワールド座標Y。ティー→グリーン方向が＋）
H：高さ（ボールの放物線。影との距離で見せる）
```

・1タイル＝1ユニット。画面の距離表示は `yardsPerUnit`（暫定：10ヤード）をかけて見せる
・空中のボールは、高さHに応じて**ボール本体を少し大きく・影を離して**表示し、高さを分からせる

## 4.3 カメラ

・狙っている間：ボールと着地予測の両方が入るように表示する
・飛んでいる間：ボールを追う
・止まった後：次に打つ人のボールへ移動する
・「全体」ボタンを押している間は、ホール全体を表示する

### 背後視点のショット演出

・狙っている間だけ、ゴルファーの背中越し（Perspective）に打つ方向を見る。コース・物理・入力は真上視点のまま、カメラだけ傾ける
・ゴルファーはボールの左横に立て、ゲージのマーカーに合わせてクラブを振る。打ったらフォロースルーを 0.3 秒見せて真上視点へ戻る
・スイングには緩急をつける（始動とトップはゆっくり、ダウンスイングは加速、打った角度から減速しながら振り抜く）。体は前傾で構え、トップ・フィニッシュで肩の回転（胴を細く）を見せ、フィニッシュで起き上がる。ゲージの速さ自体は変えない
・ゴルファーは上半身（シャツ＝プレイヤー色）・下半身（ズボン・靴）・頭（帽子・髪）・両腕（半袖）・グローブに分けて実行時に図形で描く。手元は肩の周りを弧を描いて動き、腕は両肩から手元へ伸ばす。トップでは肩を大きく・腰を少しだけ回して捻転を見せる
・パターのときはカメラを低く・近くして、グリーンの傾斜矢印を読みやすくする
・背後視点の間は、コース外の木を立て、背景を空の色にする（地面は林の色の板で地平線まで埋める）

# 6. ルール

## 6.1 基本

・ティーから打ち始め、カップに入るまでの打数を数える
・打数が少ないほど良い

## 6.2 モード

| モード     | 内容                          |
| ------- | --------------------------- |
| 1ホールモード | 登録ホールからランダムに1ホール            |
| 3ホールモード | 登録ホールから重複なしでランダムに3ホール、合計打数で競う |

・登録ホールが3つ未満のときは、3ホールモードを選べないようにする

## 6.3 打つ順番

| 場面        | 順番                          |
| --------- | --------------------------- |
| 各ホールの1打目  | 1ホール目は席順。2ホール目以降は前のホールの打数が少ない順（同じ打数なら前の順番を引き継ぐ） |
| 2打目以降     | **カップから遠い人から**（カップインした人は飛ばす）  |

・順番はボール位置だけで決まるので、オンラインでも全端末で同じ計算になる（順番そのものは送らない）

## 6.4 打数上限

・1ホールの打数が**パー×2**に達してもカップインしていなければ、そのホールは打ち切り
・打ち切りの打数は「パー×2」として記録する
・理由：パットを外し続けたときなどに試合が長引かないようにする

## 6.5 ペナルティ

| 状況   | 罰打  | 次に打つ場所                      |
| ---- | --- | --------------------------- |
| 池    | 1打  | 池に入る直前に通った池以外の地点（入った方向に戻る） |
| OB   | 1打  | 打つ前の場所                      |

## 6.6 勝敗

・全ホール終了時に、合計打数が少ない人が勝ち
・同じ打数なら同じ順位
・スコアはパーとの差（-1＝バーディー、0＝パー、+1＝ボギー）でも表示する

# 7. プレイヤー操作

## 7.1 ショットの流れ

```text
① 方向を決める（左右ドラッグ／◀▶ボタン）
② 必要ならクラブを変える
③ ゲージをタップして開始
④ パワーでタップ（飛距離が決まる）
⑤ インパクトでタップ（まっすぐ飛ぶかが決まる）
```

・マウス（ブラウザ）でもタッチ（Android）でも、同じ「クリック／タップ」で操作する
・ゲージの操作中は方向とクラブを変えられない

## 7.2 方向の決め方

・画面をドラッグすると、ボールを中心に打つ方向が回る
・細かく合わせたいとき用に、◀▶ボタン（押している間ゆっくり回る）も置く
・初期の向きは、ボールからカップへの方向

## 7.3 着地予測

・選んでいるクラブをフルパワーで打ったときの**着地点**を円で表示する
・風と曲がりは予測に含めない（読むのがプレイヤーの仕事になるようにする）
・パターのときは着地予測の代わりに、フルパワーで転がる距離の目安の線を表示する

## 7.4 3タップゲージ

```text
     インパクトゾーン
          ↓
 ├──┼─────────────────┤
 0% ▲                100%
   ここでタップ＝インパクト

 ① タップ：マーカーが右へ動き出す
 ② タップ：その位置がパワー（％）になる。マーカーは折り返して左へ戻る
 ③ タップ：インパクトゾーンからのずれで曲がりが決まる
```

| インパクトの結果    | 挙動                       |
| ----------- | ------------------------ |
| ゾーンの中心      | まっすぐ飛ぶ                   |
| ゾーン内で左右にずれた | ずれに比例してフック／スライス           |
| ゾーンの外       | ミスショット（大きく曲がり、飛距離も落ちる）   |
| タップしなかった    | ゾーンを通り過ぎた最後の位置で打ったことにする  |

・マーカーの速さは `gaugeSpeed` で調整する
・インパクトゾーンの幅はライによって変える（バンカーは狭い。§8.4）

## 7.5 クラブ

| クラブ    | 最大飛距離（暫定） | 弾道の高さ | 使う場面          |
| ------ | --------- | ----- | ------------- |
| ドライバー  | 22ユニット   | 低め    | ティーショット        |
| アイアン   | 15ユニット   | 中     | 2打目            |
| ウェッジ   | 8ユニット    | 高い（転がりが少ない） | グリーン周り・バンカー |
| パター    | 転がりのみ    | なし    | グリーン上          |

・ボールがグリーン上にあるときは、自動でパターになる（グリーン上では他のクラブを選べない）
・それ以外の場所では、カップまでの距離に合う一番短いクラブを初期値にする
・クラブの数値は ScriptableObject（`GolfClubData`）で定義する

## 7.6 入力とゲームロジックの分離

```text
┌──────────────┐
│ 入力処理      │ 方向・クラブ・ゲージ（マウス／タッチ）
└──────┬───────┘
       ↓  ShotRequest（方向・クラブ・パワー・インパクトのずれ）
┌──────────────┐
│ ゲームロジック │ 飛行・転がり・ライ判定・罰打・カップイン
└──────────────┘
```

NPC・オンラインの相手も同じ `ShotRequest` を使う。

# 8. ボールの物理

## 8.1 基本方針

**Rigidbody2D は使わず、自前の計算（`BallSimulator`）で動かす**。

```text
理由：
・高さH・風・曲がり・バウンドを、物理エンジンより簡単に思い通り調整できる
・同じ入力から同じ結果を計算できるので、着地予測とNPCの狙いにそのまま使える
```

・固定の時間刻み（`simulationStep`）で位置と速度を更新する
・`BallSimulator` は MonoBehaviour にしない。表示側（`BallView`）が毎フレーム結果を読んで描く

## 8.2 飛行

```text
・初速：クラブの最大初速 × パワー
・打ち出し角：クラブごとの固定値（弾道の高さ）
・高さH：重力で放物線を描く
・風：空中にいる間だけ、X/Z方向に風の加速度を足す
・曲がり：インパクトのずれ × クラブの曲がりやすさ で、進行方向の横向きに加速度を足す
```

## 8.3 バウンド・転がり

```text
着地（H が 0 になった）
 ↓
地面の種類で跳ね返りの強さを決めて、何回か小さくバウンド
 ↓
地面の種類ごとの減速で転がる
 ↓
速度が stopSpeed 以下になったら停止
```

## 8.4 地面の種類（ライ）

| 種類     | 転がりの減速 | 跳ね返り | 次のショットの飛距離 | インパクトゾーン |
| ------ | ------ | ---- | ---------- | -------- |
| ティー    | 普通     | 普通   | 100%       | 普通       |
| フェアウェイ | 普通     | 普通   | 100%       | 普通       |
| ラフ     | 強い     | 小さい  | 80%        | 普通       |
| バンカー   | とても強い  | なし   | 60%        | 狭い       |
| グリーン   | 弱い     | 小さい  | パターのみ      | 普通       |
| 池      | ―      | ―    | 罰打（§6.5）   | ―        |
| OB     | ―      | ―    | 罰打（§6.5）   | ―        |

・池・OBは「着地した瞬間」または「転がって入った瞬間」に判定し、ボールを止める
・数値は ScriptableObject（`GolfTerrainSettings`）にまとめる

## 8.5 グリーンの傾斜

・Tilemapの**傾斜レイヤー**に、向きと強さを持った矢印タイルを塗る
・ボールが転がっている間、いるマスの傾斜の向きに加速度を足す
・傾斜タイルがないマスは平ら

## 8.6 カップイン

以下をすべて満たしたらカップイン。

```text
・ボールとカップの距離が cupRadius 以下
・高さHが 0（転がっている）
・速度が cupInMaxSpeed 以下（速すぎるとカップを通り過ぎる）
```

・空中からの直接カップイン（ダイレクトイン）もMVPで扱う（高さが0になった瞬間にカップの上ならカップイン）

## 8.7 調整用パラメータ

ScriptableObject（`GolfPhysicsSettings`）にまとめる。

| パラメータ                 | 意味                  |
| --------------------- | ------------------- |
| simulationStep        | 計算の時間刻み             |
| gravity               | 高さ方向の重力             |
| stopSpeed             | 停止とみなす速度            |
| maxSimulationTime     | 1打の最大時間（止まらないときの保険） |
| windAccelerationScale | 風の強さ → 加速度          |
| curveAccelerationScale | インパクトのずれ → 曲がり      |
| slopeAccelerationScale | 傾斜の強さ → 加速度         |
| cupRadius / cupInMaxSpeed | カップインの判定          |
| gaugeSpeed            | ゲージのマーカーの速さ         |
| yardsPerUnit          | 画面表示用の距離換算          |

# 9. ホール・コースデータ

## 9.1 基本方針

**1ホール＝1プレハブ＋1データ（ScriptableObject）**にして、ホールを後から追加しやすくする。
ホールを追加するときに Scene を触らないので、2人で同時に別のホールを作ってもコンフリクトしない。

## 9.2 ホールのプレハブ

```text
Hole_01.prefab
 ├ Grid
 │  ├ Terrain（Tilemap）  地面の種類を塗る
 │  └ Slope（Tilemap）    グリーンの傾斜を塗る
 ├ Tee                    ティーの位置（空のGameObject）
 └ Cup                    カップの位置（空のGameObject）
```

・Tilemapの外側はすべてOB扱い
・タイルは種類ごとに1つずつ用意し（`GolfTerrainTile`）、塗った色がそのまま見た目になる

## 9.3 ホールデータ

```text
GolfHoleData（ScriptableObject）
 ・表示名
 ・パー
 ・ホールのプレハブ
 ・風の強さの範囲（最小〜最大）
```

```text
GolfHoleCatalog（ScriptableObject）
 ・遊べるホールの一覧（GolfHoleData のリスト）
```

・ホールを追加する手順：プレハブを作る → GolfHoleData を作る → GolfHoleCatalog に登録する

## 9.4 風

・ホールを始めるときに、向き（全方向）と強さ（ホールデータの範囲内）をランダムに決める
・そのホールの間は変わらない
・画面上部に矢印と強さ（m）で表示する

## 9.5 MVPで用意するホール

| ホール  | パー | 特徴                  |
| ---- | -- | ------------------- |
| ホール1 | 3  | まっすぐ。グリーン手前にバンカー    |
| ホール2 | 4  | 途中で曲がる（ドッグレッグ）。横に池  |
| ホール3 | 5  | 長い。OBが近く、グリーンの傾斜がきつい |

# 10. NPC

## 10.1 基本方針

NPCは「狙う地点を決める → `BallSimulator` で試し打ちして `ShotRequest` を決める → ブレを加える」だけにする。

## 10.2 狙いの決め方

```text
① カップまでの距離で、届く一番短いクラブを選ぶ
② 届くならカップを、届かないならカップ方向で飛距離いっぱいの地点を狙う
③ 狙う地点に池・OBがあれば、左右に少しずらした地点を試す（つよいのみ）
④ 風を考えて方向を補正する（ふつう・つよい）
⑤ パットは傾斜を考えて方向を補正する（つよいのみ）
```

・パワーは、`BallSimulator` で風・曲がりなしのショットを何回か試し、狙う地点に一番近く止まるものを選ぶ

## 10.3 難易度（3段階）

| 難易度 | 方向のブレ | パワーのブレ | インパクトのずれ | 使う判断    |
| --- | ----- | ------ | -------- | ------- |
| よわい | 大     | 大      | 大        | ①②のみ    |
| ふつう | 中     | 中      | 中        | ①②④     |
| つよい | 小     | 小      | 小        | ①〜⑤すべて |

難易度は ScriptableObject（`GolfNpcDifficulty`）で定義する。

## 10.4 NPCの手番

・「○○の番」表示は短く出して自動で進める

# 14. オンライン対戦

## 14.1 方針

モルックと同じ仕組み（NGO＋Relay、既存の `Common/Scripts/Online/`）を使う。

・2〜4人（人間のみ。オンラインではNPCを入れない）
・ホストが部屋を作り、参加コードで入る。ホストが「開始」を押す（2人以上）
・席番号は参加順（ホスト=0）
・ブラウザ版とAndroid版で対戦できる（`OnlineSession` が対応済み）
・クライアント同士は直接送れないので、ホストが中継する（モルック §19.6 と同じ）

## 14.2 同期の考え方

```text
試合開始時：ホストがモードとホールの並び、各ホールの風を決めて全員に送る
 ↓
打つ人の端末で ShotRequest を送る → 他の端末はボールが飛ぶ演出を再生
 ↓
止まった後、打った人の端末が「最終位置・ライ・打数・罰打・カップインしたか」を送る
 ↓
他の端末はその結果でボールの位置と打数を上書き
```

・`BallSimulator` は同じ入力からほぼ同じ結果になるが、端末ごとの小数の誤差でずれる可能性があるため、最終結果は必ず上書きする
・打つ順番（§6.3）はボール位置から全端末で同じ計算になるため、送らない
・送るデータが小さいので、名前付きメッセージだけで済ませる（NetworkObject は使わない）

## 14.3 その他のルール

・PAUSE：他の人の端末は止まらないため、自分のショット受付だけ止める
・試合中に1人でも接続が切れたら、全員その時点で試合終了
・再接続はしない

# 18. 開発上の基本方針

## 18.1 まず「打って気持ちいい」を確認する

Phase 1 は平らな地面だけで、飛び方・転がり方の手応えを確認する。コースは後回しにする。

## 18.2 物理演算を目的にしない

リアルさより「読めば狙える」「たまに予想外に転がる」バランスを優先する。パラメータは ScriptableObject で調整する。

## 18.3 ホールはデータとして作る

ホールをコードやSceneに直接書かない。プレハブと GolfHoleData を追加するだけで遊べるようにする。

## 18.4 フェーズごとにPlayableを維持する

各Phaseの終わりに必ず遊べる状態にしてからコミットする。
