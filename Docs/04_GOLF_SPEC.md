# 第5弾ミニゲーム：2Dゴルフゲーム 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第5弾ミニゲーム。『みんなのGOLF』のような **気軽に遊べるゴルフ** を真上視点の2Dで作る。3タップのショットゲージで打ち、風・ライ（地面の種類）・グリーンの傾斜を読みながら、少ない打数でカップインを目指す。

中心となる体験は、**「風と曲がりを読んで、狙った場所にピタッと止める」** こと。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 2Dゴルフ |
| 視点 | 真上視点＋狙っている間だけ背後視点（§3.3）・縦画面 |
| グラフィック | 2Dドット絵のTilemap＋実行時に作る図形 |
| プレイ人数 | 2〜4人（1台での交代プレイ。人間とNPCを自由に組み合わせ）/ オンライン2〜4人（§10） |
| 試合形式 | 1ホールモード／3ホールモード。合計打数が少ない人の勝ち |
| 対象プラットフォーム | Android / Windowsブラウザ（WebGL。マウスで同じ操作ができる） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/04_Golf/`、シーン名は `GolfScene`。Sceneは `Tools > MiniGame > Build Golf Scene`（`GolfSceneBuilder`）でコードから生成する。

モルック（§03）の以下の考え方を流用している。

* ロジックは地面の平面座標（X/Z）＋見た目用の高さH で計算する
* 入力・NPC・オンラインが同じリクエスト（`ShotRequest`）を作って打つ
* ルールや物理は MonoBehaviour を使わない純粋クラスにして、EditModeテストで検証する
* オンラインは「打った人の端末で結果を確定し、最終結果を送る」ターン制の同期にする

物理演算のリアルさは目的にしない。「読めば狙える」「たまに予想外に転がる」バランスを優先し、パラメータは ScriptableObject で調整する。ホールはコードやSceneに直接書かず、プレハブとデータを追加するだけで遊べるようにする（§6）。

## 2. ルール・試合の流れ

### 2.1 試合の流れ

```text
モード選択（1台で遊ぶ / 部屋を作る / コードで参加）
  ↓
モード・人数・人間/NPCの設定（1台で遊ぶときのみ。§8.1）
  ↓
キャラ選択（§9.4。オンラインは自分のキャラだけ）
  ↓
ホール開始（コース名を出しながらグリーン→ティーを流して見せる → ホール名・パー・風の表示）
  ↓
「○○の番」表示（前の人のカップイン・ギブアップの結果も出す）
  ↓
狙う（方向・クラブ・スピン）→ 3タップゲージで打つ
  ↓
ボールが飛んで転がって止まる（池・OBは1.2秒見せてから打ち直しの位置へ）
  ├ カップイン / 打ち切り → 演出メッセージ（1.8秒）
  └ それ以外 → 止まった場所を1秒見せる
  ↓
次の人の番 …全員カップインか打ち切りになるまで
  ↓
スコアカード（最終ホールは順位付き）→ 次のホール …最終ホールまで
  ↓
リザルト（共通の ResultDialog）
```

### 2.2 モード

| モード | 内容 |
| --- | --- |
| 1ホールモード | 登録ホールからランダムに1ホール |
| 3ホールモード | 登録ホールから重複なしでランダムに3ホール。合計打数で競う |

* 登録ホールが3つ未満のときは、3ホールモードを選べない
* オンラインはモードを選ばず、3ホール固定（登録ホールが足りなければその数）

### 2.3 打つ順番

| 場面 | 順番 |
| --- | --- |
| 各ホールの1打目 | 1ホール目は席順。2ホール目以降は前のホールの打数が少ない順（同じ打数なら前の順番を引き継ぐ） |
| 2打目以降 | まだティーショットを打っていない人がいればその人から。全員打った後は **カップから遠い人から**（カップインした人・打ち切りの人は飛ばす。同じ距離ならティーの順番が先の人） |

順番はボール位置だけで決まるので、オンラインでも全端末で同じ計算になる（順番そのものは送らない）。

### 2.4 打数上限

* 1ホールの打数（罰打を含む）が **パー×2** に達してもカップインしていなければ、そのホールは打ち切り（ギブアップ）
* 打ち切りの打数は、罰打で上限を超えていても「パー×2」として記録する
* パットを外し続けたときなどに試合が長引かないようにするため

### 2.5 ペナルティ

| 状況 | 罰打 | 次に打つ場所 |
| --- | --- | --- |
| 池 | 1打 | 池に入る直前に通った池・OB以外の地点（入った方向に戻る） |
| OB | 1打 | 打つ前の場所 |

### 2.6 勝敗・スコア

* 全ホール終了時に、合計打数が少ない人が勝ち。同じ打数なら同じ順位
* スコアはパーとの差（-1＝バーディー、±0＝パー、+1＝ボギー）でも表示する
* リザルトは共通の `ResultDialog`。詳細は「P1 パワー型 の優勝！」（同率なら「P1 パワー型・P2 バランス型 が同率1位」）＋「合計 12打（±0）」
* VICTORY! / GAME OVER の出し分けは、1台で遊ぶときは人間が1位にいれば VICTORY!、オンラインは自分が1位かどうか

### 2.7 ゲーム状態

進行は共通基盤の `MiniGameState`（`BaseMiniGameManager`）を使い、ゴルフ固有の区切りを `GolfPhase` で持つ（`GolfGameManager`）。

| GolfPhase | 意味 |
| --- | --- |
| Setup | モード・人数・人間/NPCの設定中 |
| CharacterSelect | キャラ選択中（オンラインは全員の選択待ちも含む） |
| HoleStart | ホール開始の演出・ホール名表示 |
| TurnStart | 「○○の番」表示中 |
| Aiming | 狙い中（方向・クラブ・ゲージ操作。NPCは自動で打つ） |
| BallMoving | ボールが飛んで転がっている |
| ShotResult | 止まった後の結果表示 |
| HoleResult | スコアカード表示中 |
| GameSet | リザルト |

方向・クラブ・ゲージの操作（狙う／スイング）は `ShotInput` の中で分かれているので、状態としては Aiming にまとめている。

## 3. 画面・ビジュアル

### 3.1 視点と座標

**真上からコースを見下ろす視点** とする。縦持ちで、ティーが下、グリーンが上になるようにホールを作る。

```text
┌──────────────────┐
│↑風3m         [Ⅱ]│ ← 風・PAUSE
│ H1/3 … PAR3 [全体]│ ← ホール・パー・全体ボタン
│ ▶P1 2打 P2 3打 [？]│ ← 打数・操作説明
│ フェアウェイ 残り80y │ ← ライ・残り距離
│      ░⛳░        │
│     ░░░░░  ~~~   │ ← グリーン・池
│    ▒▒▒▒▒▒  ~~~   │
│   ▒▒▒▒▒▒▒        │ ← フェアウェイ
│  ::  ▒▒▒▒▒       │ ← バンカー
│      ▒▒▒ ◯       │ ← 着地予測
│       ▒ ╱        │ ← 打つ方向
│        ●         │ ← ボール
│         [スピン]  │
│ ▕█████▏タップでスイング │ ← ゲージ
│ [◀] [ドライバー 220y] [▶] │ ← 方向・クラブ
└──────────────────┘
```

モルックと同じく、**ロジックは地面の平面座標で計算し、高さHは自前で計算する**。

```text
X：左右
Z：奥行き（Unityのワールド座標Y。ティー→グリーン方向が＋）
H：高さ（ボールの放物線。影との距離で見せる）
```

* 1タイル＝1ユニット。画面の距離表示は `yardsPerUnit`（10ヤード）をかけて見せる
* 空中のボールは、高さHに応じて **ボール本体を画面の上へずらして少し大きく** 描き、地面に残る影は高いほど小さく薄くして、高さを分からせる

### 3.2 カメラ

`GolfCameraFollower` が状況に応じて切り替える。

| 場面 | 見え方 |
| --- | --- |
| ホール開始 | 真上視点で、グリーンで0.8秒止めてからティーまで1.8秒かけて流す。これから攻めるコースの形とカップの位置を伝える |
| 狙っている間（ボールが止まっていてカップインしていない間） | 背後視点（§3.3） |
| 飛んでいる間 | 真上視点でボールの地面の位置を追う（高さでずれる本体ではなく地面の位置を追い、カメラが上下に揺れないようにする）。少し奥（打つ先）まで映す |
| 「全体」ボタンを押している間 | ホール全体を真上から表示する |

背後視点⇔真上視点・全体表示の切り替わりの瞬間は補間せずに切り替える。

### 3.3 背後視点のショット演出

* 狙っている間だけ、ゴルファーの背中越し（Perspective）に打つ方向を見る。コース・物理・入力は真上視点のまま、カメラだけ傾ける
* ゴルファーはボールの左横に立て（右打ち）、ゲージのマーカーに合わせてクラブを振る。打ったらフォロースルーを 0.3 秒見せて真上視点へ戻る
* スイングには緩急をつける（始動とトップはゆっくり、ダウンスイングは加速、打った角度から減速しながら振り抜く）。体は前傾で構え、トップ・フィニッシュで肩の回転（胴を細く）を見せ、フィニッシュで起き上がる。ゲージの速さ自体は変えない
* ゴルファー（`GolferRig`）は上半身（シャツ＝プレイヤー色）・下半身（ズボン・靴）・頭（帽子・髪＝キャラの色）・両腕（半袖）・グローブに分けて実行時に図形で描く。手元は肩の周りを弧を描いて動き、腕は両肩から手元へ伸ばす。トップでは肩を大きく・腰を少しだけ回して捻転を見せる
* パターのときはカメラを低く・近くして、グリーンを読みやすくする
* 背後視点の間は、コース外の木を立て、背景を空の色にする（地面は林の色の板で地平線まで埋める。`ShotViewBackdrop`）
* NPC・オンラインの相手も同じゲージを動かす／打った瞬間に通知が来るので、どの手番でも構え → フォロースルーを見せられる

### 3.4 表示物と素材

地面タイルの画像は `GolfTileArtBuilder` が手続き的に作るドット絵（1タイル＝16ピクセル。Scene生成時に無ければ作る）。同名のPNG（`Tiles/Art/`）を置き換えれば手描き素材へ差し替えられる。それ以外は `GolfShapeSprites` が実行時に作る図形で描く（画像アセットを増やさず、アセット競合を避けるため）。

| 対象 | 表現 |
| --- | --- |
| ティー | 明るい緑＋市松模様 |
| フェアウェイ | 明るい緑＋刈り目の縞 |
| ラフ | 濃い緑＋草の房 |
| バンカー | 砂色＋砂粒 |
| グリーン | 薄い黄緑＋細い縞 |
| 池 | 青＋波（4コマのタイルアニメーション） |
| OB | 林の色（コースの外側。カメラの背景色と揃えて境目を目立たせない） |
| コース外の木 | 地面の外側に実行時に並べる飾り（`CourseScenery`）。当たり判定なし |
| カップ・旗 | 白い縁の穴＋ポールと三角の旗（`CupView`） |
| ボール | プレイヤー色の縁取りをした白い円 |
| 影 | 半透明の黒い楕円 |
| 方向・着地予測 | ボールから伸びる線と円（`AimGuideView`） |
| 傾斜 | 傾斜タイルの画像（矢印）（§5.5） |

* 色の明るさは ラフ < フェアウェイ < ティー < グリーン の順にし、色だけでもライを見分けられるようにする
* プレイヤー色はモルックと同じ P1赤・P2青・P3黄・P4緑（`GolfPlayerColors`）
* 他のプレイヤーのボールも止まっている位置に常に表示する（`OtherBallsView`。ボール同士は当たらない）

### 3.5 UI

| 要素 | 内容 |
| --- | --- |
| 風 | 左上。矢印（風が吹いていく向き）と強さ「風 3m」（`WindView`） |
| HUD | 上部中央（`GolfHudView`）。「H1/3 コース名 PAR3」、全員の打数（手番の人に「▶」、名前はプレイヤー色、カップインした人は「(IN)」）、今のライとカップまでの残りヤード、直前のショットの結果（「ナイスショット 飛距離 180y」「池ポチャ +1打」など）、操作のヒント |
| 飛んでいる間のHUD | インパクトの結果（ナイスショット／スライス／フック／ミスショット）。ゾーンの中心付近（ずれ ±0.2 以内）はナイスショット |
| クラブボタン | 下部中央。クラブ名と最大飛距離（ヤード）。タップで切り替え（`ClubButtonView`） |
| ◀▶ボタン | クラブボタンの左右。押している間ゆっくり回る（`HoldButton`） |
| ゲージ | クラブボタンの上。ゲージ自体がボタンで、押すとスイング開始（`ShotGaugeView`） |
| スピンボタン | ゲージの右上（`SpinButtonView`） |
| 全体ボタン | PAUSEボタンの下。押している間ホール全体を表示 |
| ？ボタン | 全体ボタンの下。操作説明のパネルを開く（`GolfHelpView`）。ゲームは止めずに重ねて表示し、タップで閉じる。スイング中に開くとタップがゲージに伝わるので、構えている間だけ押せる |
| PAUSE | 右上。共通の `PauseButton` / `PauseDialog` |

* 押せない状況のボタン（飛んでいる間、グリーン上のクラブ、パターのスピンなど）は薄く表示する
* ボタンは SafeArea 内に置く。表示だけのUIはタップを奪わない（画面のどこでもドラッグ・タップできるように）

### 3.6 演出メッセージ

画面中央に「ポン」と弾んで出して、1.8秒見せてから消す（`GolfMessageView`）。

| 状況 | 表示 | 演出 |
| --- | --- | --- |
| カップイン | パーとの差の呼び名（アルバトロス！／イーグル！／バーディー！／パー／ボギー／ダブルボギー／トリプルボギー／+4 など） | バーディー以上は金色で大きく脈打たせる。パーは白、ボギー以下は青白 |
| 1打目でカップイン | 「ホールインワン！」 | バーディー以上と同じ |
| 池 | 「池ポチャ… +1打」 | 赤 |
| OB | 「OB +1打」 | 赤 |
| 打ち切り | 「ギブアップ（パー×2）」 | 青白 |
| ホール開始 | 「ホール 1/3」（1ホールモードは「1ホール勝負」）＋コース名 | カメラの流し見せの間ずっと出す |

### 3.7 スコアカード

各ホールの終わり（「ホール1 終了」→「次のホールへ」）と、最終ホールの終わり（「最終結果」→「結果を見る」）に表示する（`ScoreCardView`）。最終結果は順位を付ける。

```text
          H1  H2  H3  合計
PAR        3   4   5   12
1位 P1     3   5   4   12 (±0)
   パワー型
2位 P2     4   4   7   15 (+3)
   バランス型
```

* ホール数と人数で表の大きさが変わるので、セルは表示のたびに作る
* まだ終わっていないホールは空欄。パーとの差は終わったホールのパーだけで比べる

### 3.8 サウンド

ゴルフ固有のSEは `GolfAudio` がプログラムで生成して鳴らす。Inspector のクリップ欄に素材を差し込めばそのまま置き換わる。

| 音 | 鳴るとき |
| --- | --- |
| 「カキーン」 | パター以外で打った瞬間（毎回少し高さを変える） |
| 「コツン」 | パターで打った瞬間 |
| 「カラン、コロン」 | カップイン。パーなら小さな拍手、バーディー以上なら大歓声を重ねる |
| 「ボチャン」 | 池に入ったとき |
| 「ブブー」 | OBになったとき |
| 「ヒューン」（音程が下がる） | 打ち切り |

## 4. 操作

### 4.1 ショットの流れ

```text
① 方向を決める（左右ドラッグ／◀▶ボタン）
② 必要ならクラブ・スピンを変える
③ ゲージをタップして開始
④ パワーでタップ（飛距離が決まる）
⑤ インパクトでタップ（まっすぐ飛ぶかが決まる）
```

* マウス（ブラウザ）でもタッチ（Android）でも、同じ「クリック／タップ」で操作する（Input System の Pointer で読む。タッチ中はタッチを優先）
* ゲージは開始だけゲージのボタンで、以降は画面のどこをタップしてもよい
* ゲージの操作中は方向・クラブ・スピンを変えられない

### 4.2 方向の決め方

* 画面を左右にドラッグすると、ボールを中心に打つ方向が回る（画面の横幅ぶんで120°。右へドラッグで右へ回る）。ボタンなどUIの上から始めたドラッグは無視する
* 細かく合わせたいとき用に、◀▶ボタン（押している間 20°/秒 で回る）も置く
* 構えるたびに、向きはボールからカップへの方向に戻る

### 4.3 着地予測

* 選んでいるクラブをフルパワー・まっすぐで打ったときの **最初の着地点** を円で表示し、ボールからその点まで線を引く
* 風・曲がり・傾斜は予測に含めない（読むのがプレイヤーの仕事になるようにする）
* パターのときは円を出さず、フルパワーで転がって止まる位置までの線で距離の目安を見せる
* ライの飛距離の割合（§5.4）とキャラの飛距離（§9.2）は予測に含まれる
* 飛んでいる間は消して、ボールを見やすくする

### 4.4 3タップゲージ

```text
     インパクトゾーン
          ↓
 ├─┼┼──────────────────┤
 0%                   100%

 ① タップ：マーカーが右へ動き出す
 ② タップ：その位置がパワー（％）になる。マーカーは折り返して左へ戻る
 ③ タップ：インパクトゾーンからのずれで曲がりが決まる
```

| 値 | 初期値 | 意味 |
| --- | --- | --- |
| gaugeSpeed | 0.8 | 1秒あたりにマーカーが動く量（ゲージ全体＝1）。1往復で約2.5秒 |
| impactZoneCenter | 0.1 | インパクトゾーンの中心の位置（左端＝0） |
| impactZoneHalfWidth | 0.05 | インパクトゾーンの半分の幅（ライで変わる前の値） |

| インパクトの結果 | 挙動 |
| --- | --- |
| ゾーンの中心 | まっすぐ飛ぶ |
| ゾーン内で左右にずれた | ずれに比例してフック／スライス。右寄り（早め）でスライス、左寄り（遅め）でフック |
| ゾーンの外 | ミスショット（ゾーンの端の2.5倍曲がり、パワーは0.7倍） |
| ②をタップしなかった | 右端まで来たらパワー100%として折り返す |
| ③をタップしなかった | 左端まで戻ったところで打ったことにする |

* 飛距離はおおよそパワーの2乗に比例する（7割で約半分、5割で約1/4）
* インパクトゾーンの幅はライによって変える（バンカーは半分。§5.4）
* ずれの値（`ImpactOffset`）は ±1 がゾーンの端で、＋が右（スライス）、－が左（フック）

### 4.5 クラブ

| クラブ | 最大飛距離 | 初速 | 打ち出し角 | 曲がりやすさ | 使う場面 |
| --- | --- | --- | --- | --- | --- |
| ドライバー | 約22ユニット（220y） | 16.2 | 15°（低め） | 1.0 | ティーショット |
| アイアン | 約15ユニット（150y） | 10.4 | 28° | 0.8 | 2打目 |
| ウェッジ | 約8ユニット（80y） | 7 | 50°（高い・転がりが少ない） | 0.5 | グリーン周り・バンカー |
| パター | 転がりのみ（グリーンの端から端に届く強さ） | 6 | なし | 0.1 | グリーン上 |

* 最大飛距離は最初の着地までの距離（重力6で初速と打ち出し角を合わせている）。飛ぶクラブほど曲がりやすい
* ボールがグリーン上にあるときは、自動でパターになる（グリーン上では他のクラブを選べない）
* それ以外の場所では、カップまで届く一番短いクラブを初期値にする（届くクラブが無ければ一番飛ぶクラブ）。パターも切り替えで選べる
* 切り替えはドライバー → アイアン → ウェッジ → パター の順に回る
* クラブの数値は1本1アセットの ScriptableObject（`Data/Clubs/Club_xxx.asset`、`GolfClubData`）で定義する。`GolfClubAssetBuilder` が無ければ作る（調整済みの値は上書きしない）

### 4.6 スピン

* 構えている間、スピンボタンで なし → バック → トップ を切り替える（構え直すたびに「なし」へ戻り、前の人・前のショットの設定を引き継がない）
* 効くのは **最初の着地だけ**。着地点は変えず、その後の転がりだけを変える

| スピン | 最初の着地で地面方向の速さに掛ける倍率 | 使う場面 |
| --- | --- | --- |
| なし | 1.0 | ― |
| バック | 0.3（`BackSpinRollRate`） | グリーンに止めたいとき |
| トップ | 1.6（`TopSpinRollRate`） | ランで距離を稼ぎたいとき |

* パターには効かない（ボタンも押せない）
* `ShotRequest` にスピンを持たせ、オンラインでも送る。NPC はスピンを使わない

### 4.7 入力とゲームロジックの分離

```text
┌──────────────┐
│ 入力処理      │ 方向・クラブ・スピン・ゲージ（ShotInput）
└──────┬───────┘
       ↓  ShotRequest（方向・クラブ・パワー・インパクトのずれ・スピン）
┌──────────────┐
│ ゲームロジック │ 飛行・転がり・ライ判定・罰打・カップイン（BallSimulator）
└──────────────┘
```

NPC・オンラインの相手も同じ `ShotRequest` の形で打つ。

## 5. ボールの物理

### 5.1 方針

**Rigidbody2D は使わず、自前の計算（`BallSimulator`）で動かす**。

```text
理由：
・高さH・風・曲がり・バウンドを、物理エンジンより簡単に思い通り調整できる
・同じ入力から同じ結果を計算できるので、着地予測とNPCの試し打ちにそのまま使える
```

* 固定の時間刻み（`SimulationStep`）で位置と速度を更新する。表示側（`GolfBall`）はフレーム時間をため、固定の刻みぶんずつ進めるので、フレームレートが違う端末でも同じ飛び方になる
* `BallSimulator` は MonoBehaviour にしない（UnityEngine にも依存しない）。`BallView` / `ShadowView` が毎フレーム `GolfBall` を読んで描く

### 5.2 飛行

```text
・初速：クラブの最大初速 × キャラの飛距離倍率（パターは除く）× パワー × √(ライの飛距離の割合)
・打ち出し角：クラブごとの固定値（弾道の高さ）。パターは高さを持たせず転がす
・高さH：重力で放物線を描く
・風：空中にいる間だけ、X/Z方向に風の加速度を足す（滞空時間の長い高い球ほど流される）
・曲がり：インパクトのずれ × クラブの曲がりやすさ ÷ キャラの曲がりにくさ で、進行方向の横向きに加速度を足す
```

* 曲がりは速さを変えず向きだけ変える（曲がりで飛距離が伸び縮みしないようにする）
* 打ち上げたショットの曲がりは最初の着地まで、パットの曲がりは止まるまで効かせる
* 初速にライの飛距離の割合の平方根を掛けるのは、飛距離がおおよそ初速の2乗に比例するため（飛距離の割合が §5.4 の値になる）

### 5.3 バウンド・転がり

```text
着地（H が 0 になった）
 ↓
地面の種類で跳ね返りの強さと水平方向の速さの残り方を決める（最初の着地だけスピンの倍率も掛ける）
 ↓
跳ね返りが MinBounceSpeed より遅くなるまで小さくバウンド
 ↓
地面の種類ごとの減速で転がる
 ↓
速度が StopSpeed 以下になったら停止
```

1打が `MaxSimulationTime`（10秒）を超えたら、止まっていなくても止める（手番が進まなくなるのを防ぐ保険）。

### 5.4 地面の種類（ライ）

| 種類 | 転がりの減速 | 跳ね返り | 水平の速さの残り | 次のショットの飛距離 | インパクトゾーン |
| --- | --- | --- | --- | --- | --- |
| ティー | 4 | 0.35 | 0.7 | 100% | 100% |
| フェアウェイ | 4 | 0.35 | 0.7 | 100% | 100% |
| ラフ | 9 | 0.2 | 0.5 | 80% | 100% |
| バンカー | 25 | 0（跳ねない） | 0.2 | 60% | 50% |
| グリーン | 2.5（よく転がる） | 0.2 | 0.6 | ―（パターのみ） | 100% |
| 池 | ― | ― | ― | 罰打（§2.5） | ― |
| OB | ― | ― | ― | 罰打（§2.5） | ― |

* バンカーは跳ねずに砂に埋まる感じを出し、出すときは飛ばずゾーンも狭くして「入れたくない場所」にする
* 数値は ScriptableObject（`GolfTerrainSettings`）にまとめる

### 5.5 グリーンの傾斜

* ホールのプレハブの **傾斜レイヤー**（Slope の Tilemap）に、向きと強さを持った傾斜タイル（`GolfSlopeTile`）を塗る。タイルの画像（矢印）がそのまま傾斜の表示になる
* タイルは基準の下り方向と強さを持ち、Tilemap上で回転させると傾斜の向きも回る
* ボールが転がっている間だけ、いるマスの下り方向へ `SlopeAccelerationScale` を掛けた加速度を足す（止まった後は計算しないので、上りで止まったボールは止まったまま）
* 傾斜タイルがないマス、傾斜レイヤーが無いホールは平ら
* `SlopeAccelerationScale` はグリーンの転がりの減速より小さく保つ（超えると急な傾斜でボールが止まらない）

### 5.6 カップイン

以下をすべて満たしたらカップイン。

```text
・ボールとカップの距離が CupRadius（0.25）以下
・高さHが 0（転がっている）
・速度が CupInMaxSpeed（2.5）以下（速すぎるとカップを通り過ぎる）
```

空中からの直接カップイン（ダイレクトイン）も扱う。着地した瞬間にカップの上なら、速さに関係なくカップインにする。

### 5.7 池・OB

* 池・OBは「着地した瞬間」または「転がって入った瞬間」に判定し、ボールを止める
* 入った場所を1.2秒見せてから、打ち直しの位置（§2.5）へ移す（いきなり飛ぶと何が起きたか分からないため）。その間は狙えない
* 池の打ち直し位置は、空中で池の上を通った地点は覚えず、最後に通った池・OB以外の地点にする

### 5.8 調整用パラメータ

ScriptableObject（`GolfPhysicsSettings`）にまとめる。ボールの計算に使う値は、EditModeテストで検証できるよう UnityEngine に依存しない `BallPhysicsConfig` に入れ、インスペクタでは `GolfPhysicsSettings` の中に表示する（クラブ・地面・NPC難易度も同じ形）。

| パラメータ | 初期値 | 意味 |
| --- | --- | --- |
| SimulationStep | 0.02 | 計算の時間刻み（秒） |
| Gravity | 6 | 高さ方向の重力。小さいほどふわっと飛ぶ |
| SlopeAccelerationScale | 0.4 | 傾斜の強さ → 加速度 |
| CurveAccelerationScale | 3 | インパクトのずれ × 曲がりやすさ → 横向きの加速度 |
| WindAccelerationScale | 0.3 | 風の強さ（m）→ 空中での加速度 |
| MissShotCurve | 2.5 | ゾーンの外で打ったときの曲がり（ゾーンの端の何倍か） |
| MissShotPowerRate | 0.7 | ゾーンの外で打ったときに残すパワーの割合 |
| BackSpinRollRate / TopSpinRollRate | 0.3 / 1.6 | スピンの倍率（§4.6） |
| MinBounceSpeed | 0.8 | これより遅い跳ね返りはバウンドをやめて転がりに移る |
| CupRadius / CupInMaxSpeed | 0.25 / 2.5 | カップインの判定 |
| StopSpeed | 0.05 | 停止とみなす速さ |
| MaxSimulationTime | 10 | 1打の最大時間（秒） |
| yardsPerUnit | 10 | 画面表示用の距離換算 |
| gaugeSpeed / impactZoneCenter / impactZoneHalfWidth | 0.8 / 0.1 / 0.05 | ゲージ（§4.4） |

## 6. ホール・コースデータ

### 6.1 方針

**1ホール＝1プレハブ＋1データ（ScriptableObject）** にして、ホールを後から追加しやすくする。ホールは Scene に置かず、`HoleLoader` が実行時にカタログから生成する。ホールを追加するときに Scene を触らないので、2人で同時に別のホールを作ってもコンフリクトしない。

### 6.2 ホールのプレハブ

```text
Hole_01.prefab（HoleCourse）
 ├ Grid
 │  ├ Terrain（Tilemap）  地面の種類を塗る
 │  └ Slope（Tilemap）    グリーンの傾斜を塗る（任意。無ければ平ら）
 ├ Tee                    ティーの位置
 └ Cup                    カップの位置（穴と旗の表示 CupView）
```

* Tilemapの外側はすべてOB扱い
* 地面タイルは種類ごとに1つずつ用意し（`Tiles/Tile_xxx.asset`、`GolfTerrainTile`）、塗った種類がそのままライと見た目になる。ホールの形をコードに書かずに済む
* `HoleCourse` が、読み込んだホールの地面の種類・傾斜・ティー・カップを問い合わせる窓口になる（`BallSimulator` には `IGroundMap` / `ISlopeMap` として渡す）

### 6.3 ホールデータ

```text
GolfHoleData（ScriptableObject。Holes/Hole_xx/Hole_xx.asset）
 ・表示名（コース名）
 ・パー
 ・ホールのプレハブ
 ・風の強さの範囲（最小〜最大、m）

GolfHoleCatalog（ScriptableObject。Data/GolfHoleCatalog.asset）
 ・遊べるホールの一覧（GolfHoleData のリスト）
```

ホールを追加する手順：プレハブを作る → GolfHoleData を作る → GolfHoleCatalog に登録する

収録ホールの初期の形・タイル・データ・カタログは `GolfHoleAssetBuilder` が作る（Scene生成時に呼ばれる）。どれも「無ければ作る」だけで、Tilemap を塗り替えたホールや調整済みの値は上書きしない。タイルの見た目だけは毎回画像に揃え、塗り済みの Tilemap も見た目だけ最新のタイルに塗り直す。

### 6.4 風

* 試合開始時に、ホールごとに向き（全方向）と強さ（ホールデータの範囲内）をランダムに決める
* そのホールの間は変わらない
* 画面左上に矢印と強さ（m）で表示する

### 6.5 収録ホール

ホールの横幅はすべて16タイル。

| ホール | コース名 | パー | 大きさ（横×縦） | 風 | 特徴 |
| --- | --- | --- | --- | --- | --- |
| Hole_01 | はじまりの一本道 | 3 | 16×32 | 0〜3m | まっすぐ。グリーン手前にバンカー |
| Hole_02 | 池のほとり | 4 | 16×44 | 0〜5m | 左から右へ曲がるドッグレッグ。曲がり角の内側に池。カップへまっすぐ打つとスライスで池に入り、安全に打つと左の角に残る |
| Hole_03 | 崖っぷちロード | 5 | 16×60 | 2〜5m | 長い。両側すぐOB。フェアウェイの途中とグリーン手前にバンカー |
| Hole_04 | 浮島グリーン | 3 | 16×30 | 1〜4m | 池越え。届かないと池ポチャ。グリーンの左右にバンカー |
| Hole_05 | 砂の関所 | 4 | 16×44 | 0〜5m | フェアウェイを横切るバンカー列。手前に刻むか越えるか。グリーン手前にもバンカー |

## 7. NPC

### 7.1 方針

NPCは「狙う地点を決める → `BallSimulator` で試し打ちして `ShotRequest` を決める → ブレを加える」だけにする（`NpcShotPlanner`）。試し打ちは別の計算機で行うので、実際のボールの状態は変わらない。

### 7.2 狙いの決め方

```text
① カップまでの距離で、届く一番短いクラブを選ぶ（人間の初期クラブと同じ。グリーン上はパター）
② カップを狙う。届かなければパワーの探索で自然に飛距離いっぱいになる
③ 試し打ちの結果が池・OBなら、左右に 8°/16°/24° ずらした向きを近い方から試す（つよいのみ）
   それでも避けられなければ、パワーを 0.1 ずつ下げて手前に刻む（全難易度）
④ 風ありで試し打ちし、流された分だけ狙いを逆にずらす（ふつう・つよい。パター以外）
⑤ パットは傾斜ありで試し打ちし、曲がった分だけ狙いを逆にずらす（つよいのみ）
```

* パワーは、風・曲がり・傾斜なしの試し打ちを粗く（20段階）試してから、一番良かった値の前後を細かく（10段階）試し、狙う地点に一番近く止まるものを選ぶ
* ④⑤の補正は3回繰り返す（途中でカップインする狙いになったら止める）
* 手前に刻む処理を全難易度に入れるのは、同じ打ち直しの位置から毎回池へ打ち込み続けると試合が進まず見ていてつらいため

### 7.3 難易度（3段階）

| 難易度 | 方向のブレ（最大±） | パワーのブレ（最大±） | インパクトのずれ（最大±） | 使う判断 |
| --- | --- | --- | --- | --- |
| よわい | 10° | 20% | 1.3（ミスショットが出る） | ①②と刻み |
| ふつう | 4° | 8% | 0.7 | ①②④と刻み |
| つよい | 1.5° | 3% | 0.3 | ①〜⑤すべて |

難易度は ScriptableObject（`GolfNpcDifficulty`）で定義する。

### 7.4 NPCの手番

* 「○○の番」表示は1秒出して自動で閉じる（端末の受け渡しが要らないため）
* 狙いの線を0.8秒見せてから、人間と同じゲージを動かして打つ（`NpcGolfer`）。狙ったパワー・インパクトの位置でマーカーを止める
* 人間の入力は止めたまま方向とゲージだけを借りるので、線・ゲージ・HUD・ゴルファーの表示はそのまま使える

## 8. プレイヤー設定・手番交代

### 8.1 試合前の設定（1台で遊ぶとき）

1つのパネル（`GolfSetupPanel`）に、上から次の順で並べる。

```text
モード（1ホール／3ホール）
 ↓
人数（2人／3人／4人）
 ↓
各プレイヤーの種類（押すたびに 人間 → NPC よわい → NPC ふつう → NPC つよい）
 ↓
試合開始 → キャラ選択（§9.4）
```

* プレイヤー名は「P1〜P4」で固定（表示は「P1 パワー型」のようにキャラ名を付ける。§9.3）
* 全員NPCは不可（最低1人は人間。開始ボタンが押せない）
* 設定画面は前回の選択を覚えている（キャラ選択から戻ったときに選び直さなくてよい）
* パネルは `GolfMatchUiBuilder` が生成する

### 8.2 手番交代

* 1台で回して遊べるように、人間の番は「P2 パワー型 の番」→タップで開始 にする（`GolfTurnBannerView`。背景を手番の人の色に寄せる）
* 前の人のカップイン・ギブアップの結果（「P1 バーディー！（3打）」など）も一緒に出す
* ホール開始の「ホール 1/3」「コース名 PAR3 / 風 3m」表示も同じバナーで、タップで開始
* バナーを出す前に次の人のボールを置き直して構えておき、カメラが先にボールへ寄れるようにする
* ボールの実体は1つだけで、手番の人の止まっていた位置に置き直して打たせる（止まっている位置は `GolfPlayerSlot` に覚えておく）

## 9. キャラクター

### 9.1 方針

モルックのキャラ要素と同じ作り。

| 項目 | 内容 |
| --- | --- |
| キャラの差 | 見た目＋能力倍率（バランス型＝1.0） |
| 能力 | 飛距離・曲がりにくさ の2つ |
| キャラ数 | 3体（バランス型／パワー型／テクニック型）。能力が2つなので、4体目を作っても違いが分かりにくい |
| 同じキャラの重複選択 | 可。シャツとボールの色は P1〜P4 の色のままなので区別できる |
| 見た目の差 | ゴルファー（`GolferRig`）の帽子と髪の色＋選択画面用の正面の立ち絵。体のパーツは共通 |

* 倍率は `GolfPhysicsSettings` / `GolfClubData` の基準値を変えずに掛けて使う
* 1キャラ＝1アセット（`Data/Characters/GolfChar_xxx.asset`）、一覧は `GolfCharacterCatalog`。2人で同時に数値調整してもコンフリクトしないようにするため
* `GolfPlayerSlot` にはアセットではなく **カタログの番号（`CharacterIndex`）** だけを持たせる。オンラインで番号だけ送れば全端末で同じキャラになる
* アセット・カタログ・立ち絵は `Tools > MiniGame > Generate Golf Character Data`（`GolfCharacterGenerator`）で生成する（Scene生成時も未生成なら自動で作る。既にあれば調整済みの値を残す）。立ち絵はアセットの帽子・髪の色から毎回描き直すので、色を調整したらメニューを実行し直せば絵も揃う

### 9.2 能力とキャラ

| 能力 | 倍率の意味 | 反映先 |
| --- | --- | --- |
| 飛距離 | `ClubConfig.MaxLaunchSpeed` に掛ける。パターには効かせない（強さのさじ加減だけを競うため） | `BallSimulator.Launch`（初速） |
| 曲がりにくさ | `ClubConfig.CurveFactor` をこの値で割る。高いほどフック・スライスが小さい。パターにも効く | `BallSimulator.Launch`（曲がりの加速度） |

* 反映するのは **`BallSimulator` の1か所だけ**（倍率は純粋な struct の `CharacterAbility` で渡す）。`GolfBall.SetCharacter(...)` で手番のキャラの倍率を渡す
* そのため予測線（`PredictFullPower`）・NPCの狙い（`NpcShotPlanner` の試し打ち）・相手端末の再生（`HitRemoteShot`）がすべて自動でキャラの能力どおりになる
* `GolfGameManager` は手番開始（TurnStart）で手番のキャラを `GolfBall` と `GolferView` に渡すだけ（人間・NPC・相手端末のどの手番でも）

| キャラ | 飛距離 | 曲がりにくさ | 特徴 | 帽子／髪 |
| --- | --- | --- | --- | --- |
| バランス型 | 1.0 | 1.0 | 基準。初期選択 | 白／黒 |
| パワー型 | 1.15 | 0.75 | よく飛ぶが、ミスすると大きく曲がる | 赤／茶 |
| テクニック型 | 0.9 | 1.35 | 飛ばないが、多少ずれてもまっすぐ行く | 紺／金 |

数値はアセットで調整する（コードの変更は不要）。

### 9.3 見た目・名前の表示

* 背後視点のゴルファーの帽子と髪の色を、手番開始時に手番のキャラの色にする（シャツはプレイヤー色のまま）
* 名前は「P1 パワー型」の形で、ターンバナー・スコアカード（幅が狭いので2行）・結果画面の優勝者名に出す。キャラ名だけだと同じキャラを選んだ人を区別できないため、席番号も付ける
* オンラインでは自分の番を「P1 パワー型（あなた）の番」と出す。ボール・シャツの色と対応させるため、「あなた」に置き換えず席番号を残す

### 9.4 キャラ選択画面

```text
GolfSetupPanel（モード・人数・人間/NPC）
 ↓
GolfCharacterSelectPanel（P1 → P2 → … の順に1人ずつ）
 │  ┌──────────────────┐
 │  │  P2 のキャラを選んでね    │ ← 席の色
 │  │  ◀   [正面の立ち絵]   ▶  │
 │  │       パワー型             │
 │  │  飛距離     ■■■■□     │
 │  │  曲がりにくさ ■■□□□     │
 │  │     [ 決定 ]  [ 戻る ]      │
 │  └──────────────────┘
 ↓ 全員決まったら
HoleStart
```

* 人間は基準のバランス型から始める
* NPCはランダムで選ばれた状態で表示し（タイトルに「（NPC）」を付ける）、そのまま決定してもよいし◀▶で人間が代わりに変えてもよい
* 能力バー（`GolfStatBarView`）は倍率 0.8〜1.3 を 1〜5マスに変換して表示する（数値そのものは見せない。最低でも1マスは塗る）
* 「戻る」で1人前へ戻れる（P1で戻ると `GolfSetupPanel` へ）
* オンラインは自分の席の1人だけを選ぶ（§10.1）
* パネルは `GolfMatchUiBuilder` で生成する（シーンを手で編集せずコンフリクトを避ける）

## 10. オンライン対戦

### 10.1 方針

モルックと同じ仕組み（NGO＋Relay。接続部分の `OnlineSession` / `ModeSelectPanel` は `Assets/_Project/Common/Scripts/Online/`）を使う。

```text
ホストが「部屋を作る」（定員4人）
 ↓
参加コードで入る
 ↓
ホストが「開始」を押す（2人以上）
 ↓
参加順に席番号を配る（ホスト=0）
 ↓
ホストはホールの並びと各ホールの風を決めて送信（golf.setup）
各端末で自分のキャラだけ選ぶ（「戻る」は出さない）
 ↓ 決定
golf.character（席番号, キャラ番号）を送信
 ↓
ホールと風・全席のキャラが揃うまで「他のプレイヤーを待っています」
 ↓
HoleStart
```

* 2〜4人（人間のみ。オンラインではNPCを入れない）
* ホール数は3固定（登録ホールが足りなければその数）。ロビーにモード選択を増やさないため
* 席番号＝1ホール目のティーの順番なので、ホストから打つ
* ブラウザ版とAndroid版で対戦できる
* ホール開始・「○○の番」の表示はタップ待ちにせず1.5秒で自動で閉じる（端末を回さないため）。相手の番には「打つのを待っています」と出す

### 10.2 同期の考え方

```text
打つ人の端末で打った瞬間の入力（golf.shot）を送る → 他の端末は同じ入力でボールを飛ばして再生する
 ↓
止まった後、打った人の端末が最終結果（golf.result）を送る
 ↓
他の端末は再生が終わるのを待ってから、その結果でボールの位置と打数を上書き
```

| 送る内容 | メッセージ |
| --- | --- |
| 試合開始時のホールの並び（カタログの添字）と各ホールの風（向き・強さ） | `golf.setup` |
| 打った瞬間の入力（方向・クラブの添字・パワー・インパクトのずれ・スピン） | `golf.shot` |
| 止まった後の結果（位置〔池・OBなら打ち直しの位置〕・罰打を含む打数・カップインしたか） | `golf.result` |
| キャラ（席番号・キャラ番号） | `golf.character` |

* `BallSimulator` は同じ入力からほぼ同じ結果になるが、端末ごとの小数の誤差でずれる可能性があるため、最終結果は必ず上書きする。再生が終わるまで待ってから上書きするのは、ボールが途中で瞬間移動して見えないようにするため
* カップイン・打ち切りの判定と呼び名は、打数が確定してから各端末で出すので全端末で同じになる
* 打つ順番（§2.3）はボール位置から全端末で同じ計算になるため、送らない
* クラブはアセットなので送らず、クラブの並び（全端末で同じ）の添字で送る
* キャラは番号だけ送り、見た目・能力は各端末のカタログから引く。飛距離・曲がりにくさは全端末で手番のキャラを `BallSimulator` に渡すので、相手のショットも同じ能力で再生される
* すべて順序保証あり（`ReliableSequenced`）で送る。入力と結果の順番が入れ替わらないようにするため
* 届いた入力・結果はキューに溜め、相手の手番の処理で古い順に取り出す
* NGOではクライアント同士が直接送れないため **ホスト中継**：クライアントはホストへ送り、ホストは送り主以外の全員へ転送する
* 送るデータが小さいので、NetworkObject は使わず名前付きメッセージだけで済ませる（`GolfOnlineLink`）
* クライアントは部屋に参加した時点で受信を始める（ホストの開始の直後にホールと風が届くため）。そのためキャラ番号が試合開始の処理より先に届くことがあり、届いた番号は人数が決まる前から溜めておき、開始後に人数ぶん揃ったかで判断する
* 範囲外のキャラ番号はクランプする。範囲外の席番号は人数ぶんしか数えないので試合には使われない

### 10.3 その他のルール

* PAUSE：他の人の端末は止まらないため、時間は止めずに自分のショット受付だけ止める（1台で遊ぶときは時間ごと止め、ゲージ・ボール・NPCが止まる）
* 試合中（キャラ選択・待機中を含む）に1人でも接続が切れたら、全員その時点で試合終了（リザルトは GAME OVER・「他のプレイヤーとの接続が切れました」）

## 12. 既知の制限

* 木・崖など高さのある障害物はない（コース外の木は飾りで当たり判定なし）。高低差のある地形（打ち上げ・打ち下ろし）もない
* ボール同士は当たらない
* グリーンの傾斜の仕組み（§5.5）はあるが、収録5ホールには傾斜を塗っていない（どのグリーンも平ら）
* ホール・コースを選ぶ画面はない（登録ホールからランダム）。9ホール・18ホールのモードはない
* プレイヤー名は入力できない（席番号＋キャラ名）
* NPCはスピンを使わない
* 勝利演出はない（同率1位があり、モルックの勝者1人向けの演出をそのまま使えないため）
* オンラインはモードを選べず3ホール固定。NPCは入れられない
* 切断からの再接続はしない。途中で抜けた人を飛ばして試合を続けることもしない
* SEは仮の生成音
