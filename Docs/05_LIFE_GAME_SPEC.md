# 第5弾ミニゲーム：2D人生ゲーム 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第5弾ミニゲーム。ルーレットを回して車のコマを進め、就職・結婚・家の購入・保険・株などのイベントを経てゴールを目指す。**全員ゴールした時点の総資産** が一番多い人の勝ち。

最大の特徴は、**遊ぶたびにマスの並びが変わること** と、**見た目と文面が違う3つの世界（現代／ファンタジー／宇宙）** を選べること。道の形は3テーマで共通にし、バランス調整を1回で済ませる。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 2Dボードゲーム（すごろく型の人生ゲーム） |
| 視点 | 真上から見た2Dの盤面・縦画面。カメラは手番のコマを追う |
| グラフィック | 2Dドット絵 |
| プレイ人数 | 2〜4人（1台での交代プレイ。人間とNPCを自由に組み合わせ）/ オンライン2〜4人（§10） |
| 試合形式 | 全員ゴール後の総資産で順位を決める・1ゲームのみ |
| プレイ時間 | 4人で約10分（1人あたりルーレット平均約11回・1試合約43回。§7.8） |
| テーマ | 現代 / ファンタジー / 宇宙（§6） |
| 対象プラットフォーム | Android / iPhone（PCはマウスで同じ操作ができる） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/05_LifeGame/`。Sceneは `Tools > MiniGame > Rebuild LifeGame`（`LifeGameSceneBuilder`）でコードから生成する（素材も同時に描き直す）。

ルール計算（移動・マス効果・お金・精算）は Unity に依存しない純粋なC#（`Rules/`）にまとめる。NPC・オンライン・EditModeテストがすべて同じ計算を通るようにするため。

## 2. ルール・試合の流れ

### 2.1 試合の流れ

```text
テーマ選択（現代 / ファンタジー / 宇宙）
 ↓
プレイヤー設定（人数・人間/NPC）→ キャラ選択（§9）
 ↓
盤面生成（シードからマスをシャッフル §5.3）・全員スタートに置く・初期所持金を配る
 ↓
┌─ 手番開始「○○の番」
│   ↓
│  ルーレットを回す（§4）→ 株の配当（§7.4）
│   ↓
│  コマを進める（分岐では道を選ぶ・ストップマスで止まる・給料日は通過で受け取る・先頭が区間に入ると時代が変わる §7.12）
│   ↓
│  止まったマスの効果（§5.2）
│   ↓
└─ 次の人へ（ゴール済みの人は飛ばす・1回休みの人は1回飛ばす）
 ↓  全員ゴール
精算（§8）→ 称号発表 → 総資産レース（順位発表）→ 勝利演出
```

### 2.2 手番

* P1（オンラインはホスト）から席順に1人1回ずつルーレットを回す
* ゴールした人は以降の手番を飛ばす（観戦）
* 1回休みマス（§7.10）に止まった人は、次の自分の手番を1回飛ばす。飛ばされたら「P2 ○○ は1回休み」を短く出す
* 手番の計算は純粋クラス `LifeTurnOrder` にまとめ、EditModeテストで検証する（全員が休みでも無限ループしないこと）

### 2.3 勝敗

* 全員がゴールしたら精算（§8）し、総資産（称号ボーナス込み）の多い順に順位を決める
* 総資産が同じなら、先にゴールした人が上

### 2.4 ゲーム状態

進行は共通基盤の `MiniGameState`（`BaseMiniGameManager`）を使い、人生ゲーム固有の区切りを `LifePhase` で持つ（`LifeGameManager`）。

| LifePhase | 意味 |
| --- | --- |
| ThemeSelect | テーマ選択中 |
| PlayerSetup | 人数・人間/NPCの設定中 |
| CharacterSelect | キャラ選択中（オンラインは全員の選択待ちも含む） |
| TurnStart | 「○○の番」表示中 |
| Spinning | ルーレット待ち・回転中 |
| Moving | コマが移動中（分岐の選択を含む） |
| CellEvent | 止まったマスの効果・選択（職業・家・保険・株・賭け・相手選び・宝くじ） |
| Settlement | 「けっさん！」・1人ずつの精算・称号発表 |
| GameSet | 総資産レース（順位発表）・勝利演出・リザルト |

## 3. 画面・ビジュアル

### 3.1 盤面とカメラ

* 真上から見た盤面。道は左右にうねりながら上へ伸び、スタートが下、ゴールが上
* 区間ごとに通過点を決めてなめらかな曲線でつなぎ、マスを曲線の上に等間隔（約1.3〜1.8）で並べる。x は ±3 以内にして縦画面の横幅に収める
  * 分岐①の3ルートは左（就職）・中（大学）・右（フリーター）、分岐②は左（安全）・右（ギャンブル）に分け、道同士が交差しないようにする
  * ルートの性格を見た目でも分かるようにする：大学は大きく蛇行する遠回り、安全はなめらかなカーブ、ギャンブルは角ばったジグザグ
  * 道はマスとマスを直線でつなぐ（区間をまたぐところも直線）
* 節目のマス（スタート・就職・卒業・結婚・ゴール）の横に建物を建てる（`BoardScenery`）。正面にマスのアイコンを看板として描き、屋根の形はテーマごと（現代＝平屋根・ファンタジー＝三角屋根・宇宙＝ドーム）。置き場所はマスの周り8方向から、マス・道・他の建物から一番離れた所を自動で選ぶ
* 道の外には飾り（現代＝木・茂み／ファンタジー＝針葉樹・キノコ／宇宙＝岩・輪のある星）を散らす。試合の乱数は使わず固定のシードで置く（出目や盤面の並びをずらさないため）
* 建物と飾りは道とマスより奥に描く。建物はカメラの範囲（盤面の範囲）に含める
* カメラは手番のコマを追う。移動中はコマに追従する。横方向は、盤面が画面に収まれば中央固定、縦長の端末で収まらないときだけはみ出さない範囲でコマを追う
* 画面右上の「全体」ボタンで盤面全体を表示（もう一度押すと戻る）。ピンチ操作は入れない（PCでも同じ操作にするため）
* マスは種類ごとの色＋アイコン＋下に1行（金額が決まっていれば金額、なければマスの名前）。マスと道は白地で描いてテーマの色を掛ける
* 背景タイルは色を掛けずにテーマの背景色で直接描く（宇宙の星は背景より明るく、掛け算では出せないため）。盤面の外側20単位まで敷き詰める
* マスの文字（TextMesh）はイベント表示の Text からフォントを借りる（ブラウザ版で WebFontApplier が日本語フォントに差し替えた後のものを使うため）
* 分岐では、選べる道の先頭に矢印ボタンを出す

### 3.2 コマ

* コマの形はテーマごと（現代＝車・ファンタジー＝馬車・宇宙＝宇宙船）。車体を席の色に染め、窓・車輪・馬などは染めない別の絵を重ねる
* コマは上向き固定（進む向きに回さない）
* 運転席（右前）にキャラの顔、結婚すると助手席に結婚相手、子供が生まれると後部座席に2人まで載る（計4人。3人目以降の子供は表示しない）
* 同じマスに複数台いるときは少しずらして並べる
* お金の増減・給料日・結婚・出産・ゴール・保険・手形は、コマの上に文字を浮かべて音を鳴らす（止まらずに進める。続けて出るときは0.35秒ずつ空ける）。係やご祝儀で受け取った人のコマにも「+」を出す

### 3.3 UI

```text
┌──────────────────┐
│ P1 1,240  P2 980  P3 …  │ ← 全員の所持金（手番の人を強調）
│                [全体]│
│                        │
│       （盤面）          │
│                        │
│ [財布]    ◯ルーレット   │ ← 下部にルーレット
└──────────────────┘
```

| 部品 | 内容 |
| --- | --- |
| 所持金バー | 全員の所持金（「P1」の表記。幅の都合でキャラ名は出さない）。手番の人を強調。約束手形があれば枚数を小さく表示。0.6秒かけて数え、増えたら緑・減ったら赤 |
| 時代ラベル | 所持金バーの下に今の時代と効果（「時代：好景気（収入・指名マス ×1.5）」）を出しっぱなしにする。最初の時代が来るまでは空（§7.12） |
| ルーレット | 1〜10。フリックで回す（§4） |
| 財布ボタン | 自分の持ち物一覧（職業・給料・家・保険・株・約束手形・家族）。ここから約束手形を返済できる |
| イベント表示 | 1回の操作で起きたこと（移動中の給料・配当も含む）を、移動し終えてから1つのポップアップにまとめて出す。手番が変わる前に閉じるので、端末を渡す前に結果を読める。自分の手番はタップで閉じる。NPC・オンラインの相手は0.8秒で自動で閉じる（タップでも閉じられる） |
| 選択パネル | 分岐・職業カード・家・保険・株・賭け・相手選び・宝くじの番号の選択（ボタンを並べる） |

* イベント表示はカード風（`EventPopupView`）。上から順に次の欄を並べ、中身が無い欄は隠す
  * 名札：席の色の帯に顔と「P1 らっきー」。誰の操作の結果かを文字を読む前に分かるようにする。名札の人の行は名前を省く
  * マス：盤面と同じアイコン（マスの色の枠）と、マス名を大きく。その下にテーマの一言（「スマホの画面を割った」など。§6.1）
  * 行：給料・配当・お金の増減など。増えたら緑・減ったら赤・結婚/出産はピンク・ゴールは黄色
  * 右下の「▼」が点滅（自分の手番だけ）
* 文字の大きさ（1080×1920基準）：マス名 96 ＞ 行 52 ＞ 一言・名前 46。マス名と名前は1行に収まるまで縮める
* 出るときは 0.6倍 → 少し大きく → 等倍 と弾ませる（0.25秒）。弾んでいる間のタップは数えない（前の操作の連打で読み飛ばさないため）。SEは各出来事の演出（§3.4）で鳴らしているので、表示のときは鳴らさない
* マスを押したときの効果の説明は、時代の倍率込みの額と「（好景気）」のような時代名を出す（盤面のマスに書いた金額は元の額のまま。時代が変わるたびに描き直さないため）

### 3.4 サウンド

生成SE（`LifeAudio`・他のミニゲームと同じ `ProceduralSe`）。

| 場面 | 音 |
| --- | --- |
| ルーレット | 区画の境目を越えるたびにカチカチ、止まったら「ピンポン」 |
| 精算演出（§8） | 「ジャン！」（けっさん・1位の発表）・所持金のカウントアップ（増えるときは高く、減るときは低く）・称号の顔と順位の札のポップ・1位の前のドラムロール |
| その他 | コマの移動・お金を得る／払う・給料日・結婚/出産（鐘）・ゴール・宝くじの大当たり・勝利 |

## 4. ルーレット

* 1〜10の10等分。下部のルーレットを **フリック** すると回り、減速して止まる
* **出目はルールクラスの乱数で先に決め、回転の演出だけを出目に合わせる**（フリックの強さは回る速さと時間だけに影響する）。オンラインで全端末の出目を一致させるため（§10.2）
* フリックが弱すぎる場合は回さない（誤タップ対策）
* NPC・オンラインの相手は自動で回す演出を出す（フリックの強さは送らず、固定の強さ `_remoteFlickStrength` で回す）
* 賭け・宝くじ（§7.11）、家の売却（§8）も同じルーレットを使う（どれも出目はルールが先に決め、ルーレットをその出目で止めて見せる）
* 盤は PNG にせず実行時に描く（縁と中心の軸を付ける）

## 5. 盤面

### 5.1 道の形（3テーマ共通）

```text
            ゴール
              │
        区間C（共通 14マス）
              │
       ┌──── 合流 ────┐
  安全ルート       ギャンブルルート      ← 分岐②
  （10マス）        （10マス）
       └──── 分岐 ────┘
              │
        区間B（共通 16マス）
              │
   ┌────── 合流 ──────┐
 就職ルート   大学ルート    フリーター    ← 分岐①
 （8マス）   （12マス）    （6マス）
   └────── 分岐 ──────┘
              │
            スタート
```

1人が通るマス数は約46〜52マス。ストップマスで歩数を捨てるので、1人のルーレットは平均約11回（§7.8）。

| ルート | 特徴 |
| --- | --- |
| 就職 | 先頭の「就職マス」（ストップ）で一般職のカードを2枚引いて1枚選ぶ |
| 大学 | 遠回り。途中に学費マスが2つ。出口の「卒業マス」（ストップ）で一般職＋上級職から2枚引いて1枚選ぶ |
| フリーター | 近道。分岐①でこの道を選んだ時点でフリーターになる（給料が低い）。途中に給料日があり、転職マスで職に就ける |
| 安全 | お金のマスの金額が小さく、災難マスが少ない |
| ギャンブル | お金のマスの金額が2倍。災難マスも多い |

* 分岐ではコマが止まって道を選び、残りの歩数で進み続ける。分岐マスにちょうど止まったときは何も起きず、次の手番の最初に道を選ぶ
* 道の形（区間・分岐・固定マス・シャッフルの表）は `LifeBoardShape.CreateDefault()` にコードで持つ（ルールは Unity に依存しない asmdef で、テストもこれを使うため）
* マスの座標だけ `LifeBoardLayout`（`Data/LifeBoardLayout.asset`・マス番号 → 座標）に持つ。マスの並びはシードで変わらないので番号で引ける。`LifeBoardLayoutGenerator` は `Tools > MiniGame > Rebuild LifeGame` のたびに作り直す

**区間ごとのマス**（固定マスの位置は区間の先頭を0とした番号）

| 区間 | 長さ | 固定マス | シャッフルするマス |
| --- | --- | --- | --- |
| 就職 | 8 | 0: 就職 | 収入2・出費1・事故1・保険1・株1・指名1 |
| 大学 | 12 | 2, 7: 学費 / 11: 卒業 | 収入1・出費1・病気1・事故1・保険1・株1・出産1・宝くじ1・進む1 |
| フリーター | 6 | 3: 給料日 | 収入1・事故1・転職2・賭け1 |
| 区間B | 16 | 5: 給料日 / 10: 結婚 / 15: 分岐② | 収入2・出費1・家2・保険1・株1・出産1・病気1・火事1・転職1・指名1・入れ替え1 |
| 安全 | 10 | 5: 給料日 | 収入2・出費1・家1・出産1・株1・病気1・プレゼント1・進む1 |
| ギャンブル | 10 | 5: 給料日 | 収入2・出費1・病気1・事故1・火事1・株1・賭け1・戻る1（金額2倍） |
| 区間C | 14 | 3, 10: 給料日 | 収入2・出費1・出産2・家1・保険1・火事1・事故1・転職1・宝くじ1・1回休み1 |

* 賭け〜宝くじのマスは、収入・出費の枠と入れ替えて足した（区間の長さとマスの座標を変えずに済むため）

### 5.2 マスの種類

**固定マス**（毎回同じ位置）

| マス | 止まり方 | 効果 |
| --- | --- | --- |
| スタート | - | 初期所持金を受け取る |
| 分岐 | 通過時に選ぶ | 道を選ぶ |
| 就職 / 卒業 | ストップ | 職業カードを2枚引いて1枚選ぶ（§7.1） |
| 学費 | 止まったとき | 学費を払う（大学ルートに2か所） |
| 給料日 | 通過で受け取る | 給料を受け取る。フリーター・区間B・分岐②の各ルート・区間Cに計6か所（1人が通るのは4〜5か所） |
| 結婚 | ストップ | 結婚する。他の全員からご祝儀（§7.5） |
| ゴール | ストップ | ゴール順位ボーナス（§8） |

**シャッフルマス**（残りの枠に毎回ランダムに並べる）

| マス | 効果 |
| --- | --- |
| 収入 | お金をもらう |
| 出費 | お金を払う |
| 病気・ケガ | 出費。生命保険で無効。治療係の職業の人がいればその人に払う |
| 事故 | 出費。自動車保険で無効。取締係の職業の人がいればその人に払う |
| 火事 | 家あり：家の価格の半分を払う（火災保険で無効。修理係の職業の人がいればその人に払う）／家なし：小額の出費 |
| 出産 | 子供が1人増える。他の全員からご祝儀 |
| 家の購入 | 家を買える（§7.2） |
| 保険 | 保険に入れる（§7.3） |
| 株 | 株を買える（§7.4） |
| 転職 | 一般職（今の職業を除く）から2枚引いて、どちらかに替えるか今の職業のままにする。上級職は卒業マスでしか就けない |
| 指名 | 自分以外を1人選び、その人からお金をもらう（§7.9） |
| プレゼント | 自分以外で所持金が一番少ない人にお金を渡す（§7.9） |
| 入れ替え | 職業を持っている人を1人選んで職業を交換する。交換しなくてもよい（§7.9） |
| 進む／戻る | マスに書いた歩数（2〜4）だけ進む／戻る（§7.10） |
| 1回休み | 次の自分の手番を1回飛ばす（§7.10） |
| 賭け | 賭けるならルーレットを回し、5以上で賭け金をもらう・4以下で没収（§7.11） |
| 宝くじ | 番号を選び、ルーレットで当たった人が大金をもらう（§7.11） |

* 職業の手数料：払う人自身が該当する係なら、他に同じ係の人がいても銀行に払う
* 家なしの火事は保険・手数料の対象外
* マスの色は既存の8グループに割り振り、アイコンは `LifeArtPatterns` に文字列で持つ（`LifeCellType` はアイコンの番号順なので、新しいマスは末尾に足す）

### 5.3 シャッフルのしかた

* **区間ごと** にマスの種類と数の表（`LifeSectionDeck`）を持ち、その区間のシャッフル枠に並べ替えて配る。区間ごとに分けるのは、家や保険のマスが盤面の片側に偏らないようにするため
* 同じ種類のマスが3つ以上連続しないように並べ直す
* 金額はマスの種類ごとの範囲（`LifeRuleConfig`・§7.7）から10刻みでランダムに決める。ギャンブルルートは金額を2倍にする
* 進む／戻るの歩数も盤面生成で決めて `LifeCell.Amount` に入れる（マスに「3マス進む」と書けるように）。歩数はギャンブルルートでも倍にしない
* 各マスの文面は、盤面生成で決めた `LifeCell.TextVariant` をテーマの文面の数で割った余りで選ぶ（盤面はテーマより先に作るため）
* 盤面はシード1つから決まる（`LifeBoardGenerator`）。オンラインではホストがシードを配り、全端末で同じ盤面にする
* 盤面生成・出目・職業カード・賭けと宝くじの出目・宝くじの他の人の番号・時代・精算の家の売却ルーレットは、すべて `LifeGameState.Random` の1本から引く。NPCの乱数は別にする（NPCの考える回数で出目がずれないように）

## 6. テーマ

### 6.1 方針

3テーマは **道の形・ルール・金額が共通** で、見た目と文面だけが違う。1テーマ＝1アセット（`Data/Themes/LifeTheme_Modern / Fantasy / Space.asset`）。2人で別々のテーマを同時に書いてもコンフリクトしないようにするため。

| テーマが持つもの | 内容 |
| --- | --- |
| 表示名・通貨単位 | 「現代」「万円」／「ファンタジー」「G」／「宇宙」「クレジット」 |
| 職業名・家の名前・ルート名 | 共通の枠（§7.1・§7.2・§5.1）に対する名前 |
| マスの一言 | マスの種類ごとに数個の文面（§3.3・§5.3） |
| 見た目 | 背景・道・マスの色（8グループ）、コマの形（車／馬車／宇宙船）と背景タイルの絵 |

* マスの名前（給料日・病気など）と保険の名前は3テーマ共通で `LifeTexts` に置く
* テーマ選択はボタンを押したら即決定し、その時点で背景色を変える。選び直しはプレイヤー設定の「戻る」
* テーマのアセットは `LifeDataGenerator` が初期値（`LifeThemeDefaults`）で作る。既にあれば上書きしない
* そのため、後から足したマス（賭け〜宝くじ）の一言は既存のテーマのアセットには入らない。テーマに一言が無いマスは `LifeTexts` の共通文面を出す（各テーマの文面は手で足す）

## 7. お金とイベント

### 7.1 職業と給料

* 就職マスでは一般職5種から、卒業マスでは一般職＋上級職の8種から、2枚引いて1枚選ぶ
* 給料日を通過するたびに職業の給料をもらう
* 同じ職業を複数人が持ってもよい（係の手数料は、払う人以外で席番号の若い人が受け取る）

| 職業枠 | 給料 |
| --- | --- |
| フリーター | 80 |
| 一般1 / 一般2（取締係）/ 一般3（修理係）/ 一般4 / 一般5 | 180 / 130 / 130 / 160 / 150 |
| 上級1（治療係）/ 上級2 / 上級3 | 200 / 230 / 260 |

* 係の職業は手数料が入るぶん給料を低めにしている

### 7.2 家

| 家 | 価格 | 売却倍率（精算時のルーレット） |
| --- | --- | --- |
| 小さい家 | 300 | 1〜3: ×0.9 / 4〜7: ×1.1 / 8〜10: ×1.3 |
| 普通の家 | 600 | 1〜3: ×0.8 / 4〜7: ×1.2 / 8〜10: ×1.6 |
| 豪邸 | 1,000 | 1〜3: ×0.6 / 4〜7: ×1.2 / 8〜10: ×2.0 |

* 家の購入マスで3種から選ぶ（買わなくてもよい）。1人1軒まで。持っていればマスは何も起きない
* 所持金が足りなくても約束手形で買える

### 7.3 保険

| 保険 | 価格 | 効果 |
| --- | --- | --- |
| 生命保険 | 50 | 病気・ケガの出費を無効。精算時に払った額の半分が返ってくる |
| 自動車保険 | 30 | 事故の出費を無効 |
| 火災保険 | 40 | 火事の出費を無効。家を持っている人だけ買える |

* 保険マスで、まだ入っていない保険を好きなだけ選んで入る。一度入れば最後まで有効

### 7.4 株（番号株）

* 株マスで1〜10の番号株を1枚買える（1枚100。1人最大3枚。同じ番号を他の人と重ねて持ってよく、自分で2枚以上持ってもよい）
* **誰かの移動のルーレットがその番号で止まったら**、その番号の株の持ち主全員が配当50を受け取る（1枚ごと）。賭け・宝くじ・家の売却のルーレットでは配当を出さない
* 精算時に買値で売却する

### 7.5 結婚・出産・ご祝儀

| イベント | ご祝儀（他の全員から1人ずつ） |
| --- | --- |
| 結婚 | 30 |
| 出産（子供1人ごと） | 20 |

* 子供は最大4人。それ以上は出産マスで何も起きない
* 結婚は結婚マス（ストップ）で全員する。未婚のまま出産マスに止まっても子供は増える（簡略化）

### 7.6 約束手形（借金）

* 払うお金が足りないと、足りない分を自動で約束手形にする（1枚100単位で切り上げ）
* 利子はない。精算時に1枚125で返済する
* 財布から1枚100で途中返済できる。返済できるのは自分の手番でルーレットを回す前だけ（移動や選択の途中で状態が変わって表示とずれないように）
* ご祝儀が払えないときも同じ（ご祝儀を払う人の手番でなくても自動で手形になる）

### 7.7 金額

`LifeRuleConfig`（ルールアセンブリ内のプレーンなクラス）のフィールド初期値で持つ。ルールは Unity に依存しないので ScriptableObject にはしない。単位はテーマの通貨。

| 項目 | 値 |
| --- | --- |
| 初期所持金 | 300 |
| 給料 | フリーター 80 / 一般職 130〜180 / 上級職 200〜260（§7.1） |
| 学費（大学ルート） | 200 × 2か所（止まったときだけ） |
| 収入マス | 安全・共通 30〜150 / ギャンブル 60〜300 |
| 出費マス | 安全・共通 30〜150 / ギャンブル 60〜300 |
| 病気・事故 | 50〜150（ギャンブル 100〜300） |
| 家なしの火事 | 30 |
| ゴール順位ボーナス | 1位 300 / 2位 200 / 3位 100 / 4位 0 |
| 賭け金（§7.11） | 100（ギャンブル 200）。出目5以上で勝ち |
| 指名・プレゼント（§7.9） | 50〜150（ギャンブル 100〜300） |
| 進む・戻る（§7.10） | 2〜4マス |
| 宝くじ（§7.11） | 当たり 500 / 誰も当たらなければ止まった人に 50 |
| 時代の倍率（§7.12） | 好景気 ×1.5 / 不況 収入×0.5・出費×1.5 / 株ブーム ×2 / ベビーブーム ×2 / 平和 ×0.5 |
| 称号ボーナス（§8） | 1つにつき 100 |

### 7.8 バランス調整

NPC同士の大量試合で、分岐①・②のどのルートも勝率が極端に偏らないように金額を決めた。分岐・賭ける／賭けない・指名と入れ替えの相手・宝くじの番号はNPCの判断（負けている人がギャンブル、お金持ちを指名など）ではなく等確率で選ばせて比べる。

| 集計（4人・3,000試合） | 結果（基準 25%） |
| --- | --- |
| 分岐①の勝率 | 就職 24% / 大学 27% / フリーター 25% |
| 分岐②の勝率 | 安全 26% / ギャンブル 24% |
| 能力の勝率 | バランス 27% / がんばり屋 26% / らっきー 23% / しっかり者 23% |
| ルーレット回数 | 1人 平均10.7回（6〜20）/ 1試合 平均43回 |
| 総資産（称号ボーナス込み） | 平均 約1,310（10%点 820 / 90%点 1,830） |

* 調整前は大学 44% / 就職 21% / フリーター 12%、能力はバランス 31% / しっかり者 21% だったので、上級職の給料・学費・フリーターの給料を変え、フリーターの道に給料日を置き、バランスの初期所持金を +100 → +50、しっかり者の減額を 10% → 20% にした
* 大学を少し有利に残しているのは、遠回りと学費の見返りがあると感じられるようにするため
* 賭け〜宝くじのマス・時代・称号を足した後も金額は変えずに済んだ。1回休み・戻るを足しても1試合のルーレット回数は約43回のまま。入れ替えで上級職を取られることがあっても、大学の勝率は 30% → 27% に下がった程度（基準に近づいた）
* 賭けの勝ち目（5以上＝60%）・入れ替えに相手の同意がいらないこと・称号ボーナス 100 は、この集計で偏りが出なかったのでそのままにした。2人のときは大学 54% / フリーター 48%（基準 50%）
* 金額を変えたら `LifeSimulationTests.バランス集計`（Explicit・Test Runner で手動実行）で再集計する。集計は `LifeBalanceSimulator`（NUnit に依存しないので dotnet のコンソールからも回せる）

### 7.9 人に関わるマス（指名・プレゼント・入れ替え）

| マス | 効果 |
| --- | --- |
| 指名 | 自分以外を1人選び、その人からマスの金額をもらう。相手が払えなければ手形 |
| プレゼント | 自分以外で所持金が一番少ない人に、マスの金額を渡す（選ばない。同額なら席番号の若い人） |
| 入れ替え | 自分以外で職業を持っている人を1人選び、職業を交換する。交換しなくてもよい。対象がいなければ何も起きない |

* ゴールした人も選べる（ゴール後もお金は動くので。ご祝儀と同じ）
* 入れ替えでフリーターと交換してもよい（上級職を奪われる・押し付けるのが見せ場）
* 選ぶのは手番の人だけ（`LifePending.ChooseTarget`）。どちらのマスで選んでいるかは `state.CurrentCell.Type` で見分ける。選択肢は「P2 がんばり屋（所持金 500 / 医者）」のように並べる

### 7.10 コマが動くマス（進む・戻る・1回休み）

| マス | 効果 |
| --- | --- |
| 進む | マスの歩数だけ進む。途中の給料日はもらえる。分岐に来たら道を選ぶ |
| 戻る | マスの歩数だけ戻る。区間の先頭より前には戻らない（分岐・合流を逆走させないため）。通った給料日はもらえない |
| 1回休み | 次の自分の手番を1回飛ばす |

* 進む／戻るで着いたマスの効果は **出さない**（「進む → 戻る → 進む」の連鎖や、ストップマスの二重発動を避けるため）
* ただし進むは普通の移動と同じく必ず止まるマス（就職・卒業・結婚・ゴール）で止まり、そのときは効果を出す（大学ルートの「進む」で卒業を素通りして職業なしになるのを避けるため）
* 戻るでストップマス（結婚など）を通り越して戻ることがある。もう一度止まることになるが、それも見せ場として許す
* 進むの途中で分岐に止まっている間も「着いたマスの効果なし」を覚えておくため、`LifeGameState.IsWarping` を持つ。戻る用に `LifeBoard` の各マスは1つ前のマス（`Prev`。区間の先頭は自分自身）を持つ
* コマは1マスずつ動かす（戻るときも向きはそのまま）

### 7.11 賭け・宝くじ

**賭け**

* 止まったら「賭ける／賭けない」を選ぶ。賭けたらルーレットを回し、5以上で賭け金をもらう（差し引き +賭け金）、4以下で賭け金を払う
* 所持金が足りなくても賭けられる（約束手形になる。ほかの支払いと同じ）

**宝くじ**

* 止まった人が1〜10の番号を1つ選ぶ。他の人の番号はルールの乱数で、止まった人と重ならないように自動で配る（他の人に選ばせると手番以外の人の操作が必要になり、オンラインの送受信の作りを変えることになるため）。ゴールした人も番号をもらう
* 全員の番号を並べて見せてからルーレットを回し、番号が当たった人が 500 もらう（「大当たり！」とゴールと同じ音）。誰も当たらなければ止まった人が 50 もらう
* 全員の番号は `LifeEventType.LotteryTicket`（席ごと）で出目より先に送り、出目は `LotteryDrawn`（OtherSeat = 当たった人、-1 = はずれ）

### 7.12 時代イベント

**先頭のプレイヤーが区間B・分岐②の道・区間C に初めて入ったとき**、時代が1つ引かれる（1試合に3回）。次の時代が来るまで続く。給料日のたびだと1試合に約20回変わって覚えきれないため、区間の切り替わりに合わせる。

| 時代 | 効果 |
| --- | --- |
| 好景気 | 収入マス・指名マスの金額 ×1.5 |
| 不況 | 収入マス ×0.5、出費マス ×1.5 |
| 株ブーム | 株の配当 ×2 |
| ベビーブーム | ご祝儀（結婚・出産）×2 |
| 平和な時代 | 病気・事故・火事の支払い ×0.5（家なしの火事も含む） |

* 5つから乱数で引く。同じ時代は2回続かない
* 時代を引くのは区間をまたいで入ったときだけ。段階（区間B = 1、分岐②の道 = 2、区間C = 3）を `LifeGameState.EraStage` に持ち、段階が進んだときだけ引く（後続が手前の区間に入っても引き直さない）
* 倍率の計算は `LifeEras.Multiply(state, type, amount)` の1か所にまとめ、支払い・ご祝儀・配当と効果の説明が同じ式を通る（表示と金額がずれないように）。倍率は % の整数（`LifeRuleConfig.Era*Percent`）
* 学費・プレゼントは時代の影響を受けない。しっかり者の割引は時代の倍率の後にかける
* 変わったときは全画面のバナー（「時代が変わった！」＋時代名＋効果）を出す。人間の番でもタップ待ちにせず2秒で自動で閉じる。イベント表示の行には出さない（バナーと時代ラベルで足りるため）

## 8. 精算

全員ゴールしたら、1人ずつ順に精算を演出する。

```text
① 家を売る（ルーレットを回して売却倍率を決める §7.2）
② 株を買値で売る
③ 生命保険の満期返戻（払った額の半分）
④ 約束手形を返済（1枚125）
 ↓  （全員分）
⑤ 称号ボーナス（1つにつき +100）
 ↓
総資産 = 所持金（マイナスもありうる）
 ↓
総資産レース（順位発表）→ 1位の勝利演出 → ResultDialog（共通）
```

* ゴール順位ボーナスはゴールした瞬間にもらう（精算より前）
* ResultDialog の勝敗：1台では1位が人間なら勝利、NPCなら負け。オンラインは自分が1位のときだけ勝利

### 8.1 称号

全員の手形の返済の後に称号を判定し、1つにつき +100。同点なら全員がもらう。全員 0 のとき（例: 誰も手形を切っていない）はその称号を出さない。称号は順位に影響する（ボーナスを足した後の総資産で順位を決める）。

| 称号 | 条件 |
| --- | --- |
| 子だくさん賞 | 子供が一番多い |
| 株王 | 受け取った配当が一番多い |
| 波乱万丈賞 | 切った約束手形が一番多い（返済済みも含む） |
| ギャンブラー賞 | 賭け・宝くじで勝って受け取った額が一番多い（宝くじの残念賞は含めない） |
| お人よし賞 | 他の人に払ったお金（ご祝儀・係の手数料・指名・プレゼント）が一番多い |

* 集計用のカウンタは `LifePlayerState.DividendTotal / NotesIssued / GambleWinnings / PaidToOthers`。お人よし賞は `LifeMoney.Pay` で相手が銀行以外のときをすべて数える
* `LifeSettlementEntry.Total` は称号ボーナス込み。もらった称号は `Titles`、ボーナスの合計は `TitleBonus`

### 8.2 演出

テンポとメリハリを付け、どの段階もタップで飛ばせるようにする（2回目以降のプレイで待たされないように）。精算はルールの結果だけで決まるので、オンラインでも各端末で同じ演出を流すだけ（タップ待ちは各端末で独立）。

```text
① 「けっさん！」のバナー（ジャン！・1.2秒で自動で閉じる）
② 1人ずつ精算（SettlementView）。所持金はカウントアップし、増えたら緑・減ったら赤で揺らす
③ 称号発表（TitleRevealView）：カードが1枚ずつめくれて、もらった人の顔が「+100」付きで飛び出す
④ 総資産レース（RankingRaceView）：全員の棒が同じ速さで伸び、自分の総資産に着いた棒から止まって順位の札が出る（最下位から順）
⑤ 上位2人が残ったところで止めてドラムロール → 1位の札（ジャン！）と紙吹雪（ConfettiView）
⑥ 勝利演出（VictoryShowView §9.4）→ ResultDialog
```

* ② 席順に1人ずつ。精算前の所持金は内訳から逆算して見せ、家を持っていれば画面下のルーレットをルールの出目で止めてから1行ずつ足す。称号ボーナスは後でまとめて発表するので、ここでは除いた総資産を見せる。途中でタップすると残りの行を待たずに出し切り（家の売却ルーレットも回さない）、もう一度タップで次の人へ
* ③ 演出の途中でタップするとそのカードの最後の状態まで飛ばし、もう一度タップ（または1.5秒）で次のカードへ。誰も称号をもらわなければ出さない
* ④⑤ 途中でタップすると最後の状態（全員の札・紙吹雪）まで飛ばし、もう一度タップ（または2秒）で勝利演出へ。総資産がマイナスの人は棒を伸ばさず金額だけ見せる
* 紙吹雪はパーティクルを使わず UI の Image を数十個ばらまくだけ。勝利演出より手前に置き、勝利演出の間も降り続ける
* 各部品は Scene 生成（`LifeGameSceneBuilder`）で別々の GameObject として作る（Scene はコードから作り直すので、2人で同時に触ってもコンフリクトしない）

## 9. キャラクター

### 9.1 方針

| 項目 | 内容 |
| --- | --- |
| キャラの差 | 見た目＋小さな能力（運のゲームなので差は小さく） |
| キャラ数 | 4体（3テーマ共通） |
| 同じキャラの重複選択 | 可。席の色で区別できる |
| 追加演出 | キャラ別の勝利演出（立ち絵＋セリフ） |

* 1キャラ＝1アセット（`Data/Characters/LifeChar_xxx.asset`）、一覧は `LifeCharacterCatalog`
* 席（`LifePlayerSlot`）にはカタログの番号だけを持たせる（オンラインで番号だけ送れば済むようにするため。モルックと同じ）

### 9.2 能力

| キャラ | 能力 | 勝利セリフ |
| --- | --- | --- |
| バランス | 初期所持金 +50 | 堅実な人生だった！ |
| がんばり屋 | 給料 +10% | 働いた分だけ報われる！ |
| らっきー | 移動のルーレットを1試合に1回だけ振り直せる | 運も実力のうち！ |
| しっかり者 | 出費・学費・病気・事故・火事の支払い −20% | 節約は最強！ |

* 値は `LifeRuleConfig`（`AbilityStartMoney` / `AbilitySalaryPercent` / `AbilityThriftPercent`）。割合は端数切り捨て。値は §7.8 の集計で決めた
* しっかり者の減額は家なしの小額の火事にも効く。係へ払うときも減った額を払う。家・保険・株の購入とご祝儀には効かない
* らっきーの振り直しは、出目を見せてから「振り直す／このまま」を選ぶ（`LifePending.Reroll`）。「このまま」を選んでも能力は残る。振り直すときはもう一度フリックする。振り直す前の出目では株の配当を出さない（振り直した後の出目だけで判定）

### 9.3 キャラ選択画面

モルック（§03 8.4）と同じ形。P1から1人ずつ ◀▶ で選び、立ち絵・名前・能力の1行の説明文を見せる。NPCはランダムで選ばれた状態で表示する。

* 表示名は「P1 らっきー」（席番号＋キャラ名）
* 顔・立ち絵はキャラ（`LifeCharacterData`）、乗り物・背景タイルはテーマ（`LifeThemeData`）が参照を持つ。Scene生成時に空の欄だけ埋める（手描きに差し替えた参照を消さないため）

### 9.4 勝利演出

モルックと同じ形（背景を勝者の席の色で暗転 → 立ち絵スライドイン → セリフ → `ResultDialog`「P1 がんばり屋 の勝ち」）。共通化はせず人生ゲーム側に `VictoryShowView` を置く。立ち絵はバンザイの2頭身。

## 10. プレイヤー設定・NPC・オンライン

### 10.1 試合前の設定（1台で遊ぶとき）

```text
テーマ選択 → 人数選択（2〜4人）→ 各プレイヤーを「人間」か「NPC」に設定 → キャラ選択 → 開始
```

* 初期状態は「2人・P1人間・P2 NPC」
* 全員NPCは不可
* 人間の手番は「P2 らっきー の番」を画面全体に出し、タップで開始（端末を回すため。モルックの `TurnBannerView` と同じ）

### 10.2 NPC

難易度はない（運のゲームで強弱の差が出にくいため）。選択を単純なルールで決める（`LifeNpcPlanner`・純粋クラス）。

| 場面 | NPCの選び方 |
| --- | --- |
| 分岐① | 大学 45% / 就職 40% / フリーター 15%（乱数） |
| 職業カード | 給料の高い方 |
| 転職 | 今より給料が高ければ替える |
| 分岐② | 所持金が全員の平均未満ならギャンブル、以上なら安全 |
| 家 | 手形なしで買える一番高い家。買えなければ買わない |
| 保険 | 買った後に所持金が200以上残るものを、生命 → 自動車 → 火災の順に買う |
| 株 | 買った後に所持金が200以上残れば、持っていない番号をランダムで1枚 |
| 振り直し（らっきー） | 出目が3以下なら使う |
| 手形の返済 | 所持金が500以上なら、ルーレットを回す前に返せるだけまとめて返す |
| 賭け | 所持金が賭け金の2倍以上あれば賭ける（負けても手形を切らずに済むときだけ） |
| 指名 | 所持金が一番多い人 |
| 入れ替え | 自分より給料が高い人の中で一番高い人。いなければ交換しない |
| 宝くじ | ランダムな番号（どの番号でも当たる確率は同じなので） |

* 「○○の番」表示・イベント表示は0.8秒で自動で閉じる（タップでも閉じられる）。選択の前に0.8秒の間を置く

### 10.3 オンライン対戦

離れた2〜4人が参加コードを共有して対戦する（人間のみ。NPCは参加しない。チーム戦はなし）。接続部分（`OnlineSession` / `ModeSelectPanel`）は共通基盤を使い、部屋作成〜開始の流れはモルック（§03 9.1）と同じ。

```text
モード選択（「1台で遊ぶ」／部屋を作る／参加）
 ↓
部屋を作る（定員4人）→ 参加コードで入る → ホストが「開始」（2人以上）
 ↓
ホストがテーマを選び、テーマ番号とシードを全員へ送る（参加者は「ホストがテーマを選んでいます」）
 ↓
各端末で自分の席のキャラだけ選ぶ（「戻る」なし）→「他のプレイヤーを待っています」→ 全員揃ったら開始
```

* 待機表示はキャラ選択パネルのボタンを隠して文面だけ出す
* 表示名は自分の席だけ「P2 らっきー（あなた）」。所持金バーとイベント表示は P番号のまま

**同期は決定論ロックステップ**（カードゲームの ADR-0002 と同じ考え方）。物理がないので、同じシード・同じ操作列を渡せば全端末で同じ結果になる。

```text
全端末が同じシードでルールクラス（盤面生成・ルーレットの出目・職業カード）の乱数を初期化
 ↓
手番の人の操作（コマンド）だけを送る
 ↓
全端末が同じ順番で同じコマンドをルールクラスに渡す
```

| 送る内容 | メッセージ |
| --- | --- |
| テーマ番号・シード（ホストから1回だけ） | `life.setup` |
| キャラ（席番号・キャラ番号） | `life.character` |
| 手番の操作（回す／分岐／職業／家／保険／株／振り直し／返済／賭け／相手／宝くじの番号 のどれか＋選んだ値） | `life.command` |

* 出目もフリックの強さも送らない。出目はルールクラスの乱数で決まるので全端末で同じになる
* NGOではクライアント同士が直接送れないため **ホスト中継**（モルックと同じ）。すべて `ReliableSequenced`
* `life.setup` はホストからのものだけ採用する（クライアントから届いても中継しない）
* 相手の手番のコマンドはキューにためて届いた順に再生する（自分がイベント表示をタップするまで待っている間に次の人のコマンドが届いても取りこぼさないため）
* 手番以外の人から届いたコマンド・範囲外の値は、再生時に `LifeRules.IsValid` で捨てる
* 相手の手番の「○○の番」表示・イベント表示は0.8秒で自動で閉じる。自分の手番の結果はタップで閉じる
* 相手の手番の選択（分岐／職業／転職／家／保険／株／振り直し／賭け／相手／宝くじの番号）は、同じ選択肢を「P1 ○○ が選んでいます」付きで押せない表示にし、コマンドが届いたら選ばれた選択肢を0.8秒色付けしてから閉じる。選択肢は各端末の同じ状態から作るので、通信は増やさない
* PAUSE：時間は止めずに自分の操作受付だけ止める
* 試合中に誰か1人でも接続が切れたら、全員その時点で試合終了（GAME OVER・「他のプレイヤーとの接続が切れました」）

## 12. 既知の制限

* ルーレットの出目は乱数で先に決まり、フリックの強さでは変わらない
* プレイヤー名は入力できない（席番号＋キャラ名）
* 1台で遊ぶときの先攻は常にP1
* 株の売買はできない（買うだけ。精算時に買値で売却）。株価の変動はない
* 宝くじの番号を選べるのは止まった人だけ（他の人の番号は自動で配る）
* 後から足したマス（賭け〜宝くじ）のテーマごとの一言は未作成（共通文面を出す）
* 未婚でも子供が増える
* 学費マスは止まったときだけ払う（通過では払わない）
* キャラの見た目・名前は仮のまま
* 途中セーブ・再接続はしない
* チーム戦はない
* SEは仮の生成音
