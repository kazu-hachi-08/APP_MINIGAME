# 第6弾ミニゲーム：2D人生ゲーム 仕様書

## 1. 概要

「週末2人開発 2Dミニゲームプロジェクト」の第6弾ミニゲーム。ルーレットを回して車のコマを進め、就職・結婚・家の購入・保険・株などのイベントを経てゴールを目指す。**全員ゴールした時点の総資産** が一番多い人の勝ち。

最大の特徴は、**遊ぶたびにマスの並びが変わること** と、**見た目と文面が違う3つの世界（現代／ファンタジー／宇宙）** を選べること。道の形は3テーマで共通にし、バランス調整を1回で済ませる。

| 項目 | 内容 |
| --- | --- |
| ジャンル | 2Dボードゲーム（すごろく型の人生ゲーム） |
| 視点 | 真上から見た2Dの盤面・縦画面。カメラは手番のコマを追う |
| グラフィック | 2Dドット絵 |
| プレイ人数 | 2〜4人（1台での交代プレイ。人間とNPCを自由に組み合わせ）/ オンライン2〜4人（§10） |
| 試合形式 | 全員ゴール後の総資産で順位を決める・1ゲームのみ |
| プレイ時間 | 4人で約10分（1人あたりルーレット約10回） |
| テーマ | 現代 / ファンタジー / 宇宙（§6） |
| 対象プラットフォーム | Android / iPhone（PCはマウスで同じ操作ができる） |
| エンジン / 言語 | Unity / C# |

ソースは `Assets/_Project/Games/05_LifeGame/`。Sceneは `Tools > MiniGame > Rebuild LifeGame`（`LifeGameSceneBuilder`）でコードから生成する（素材も同時に描き直す）。

ルール計算（移動・マス効果・お金・精算）は Unity に依存しない純粋なC#（`Rules/`）にまとめる。NPC・オンライン・EditModeテストがすべて同じ計算を通るようにするため。

## 2. ルール・試合の流れ

### 2.1 試合の流れ

```text
テーマ選択（現代 / ファンタジー / 宇宙）
 ↓
プレイヤー設定（人数・人間/NPC）→ キャラ選択（§9）
 ↓
盤面生成（シードからマスをシャッフル §5.3）・全員スタートに置く・初期所持金を配る
 ↓
┌─ 手番開始「○○の番」
│   ↓
│  ルーレットを回す（§4）→ 株の配当（§7.4）
│   ↓
│  コマを進める（分岐では道を選ぶ・ストップマスで止まる・給料日は通過で受け取る）
│   ↓
│  止まったマスの効果（§5.2）
│   ↓
└─ 次の人へ（ゴール済みの人は飛ばす）
 ↓  全員ゴール
精算（§8）→ 順位発表・勝利演出
```

### 2.2 手番

* P1（オンラインはホスト）から席順に1人1回ずつルーレットを回す
* ゴールした人は以降の手番を飛ばす（観戦）
* 手番の計算は純粋クラス `LifeTurnOrder` にまとめ、EditModeテストで検証する

### 2.3 勝敗

* 全員がゴールしたら精算（§8）し、総資産の多い順に順位を決める
* 総資産が同じなら、先にゴールした人が上

### 2.4 ゲーム状態

進行は共通基盤の `MiniGameState`（`BaseMiniGameManager`）を使い、人生ゲーム固有の区切りを `LifePhase` で持つ（`LifeGameManager`）。

| LifePhase | 意味 |
| --- | --- |
| ThemeSelect | テーマ選択中 |
| PlayerSetup | 人数・人間/NPCの設定中 |
| CharacterSelect | キャラ選択中（オンラインは全員の選択待ちも含む） |
| TurnStart | 「○○の番」表示中 |
| Spinning | ルーレット待ち・回転中 |
| Moving | コマが移動中（分岐の選択を含む） |
| CellEvent | 止まったマスの効果・選択（職業・家・保険・株） |
| Settlement | 精算中 |
| GameSet | 順位発表・勝利演出・リザルト |

## 3. 画面・ビジュアル

### 3.1 盤面とカメラ

* 真上から見た盤面。道はつづら折りに上へ伸び、スタートが下、ゴールが上
* カメラは手番のコマを追う。移動中はコマに追従する
* 画面右上の「全体」ボタンで盤面全体を表示（もう一度押すと戻る）。ピンチ操作は入れない（PCでも同じ操作にするため）
* マスは種類ごとの色＋アイコンで表示する。お金のマスは金額も表示する（シャッフル後に決まった値）
* 分岐では、選べる道の先頭に矢印ボタンを出す

### 3.2 コマ

* 車のコマ（席の色）。運転手としてキャラの顔を載せる
* 結婚すると助手席に1人、子供が生まれると後部座席に1人ずつ増える（最大4人）
* 同じマスに複数台いるときは少しずらして並べる

### 3.3 UI

```text
┌──────────────────┐
│ P1 1,240  P2 980  P3 …  │ ← 全員の所持金（手番の人を強調）
│                [全体]│
│                        │
│       （盤面）          │
│                        │
│ [財布]    ◯ルーレット   │ ← 下部にルーレット
└──────────────────┘
```

| 部品 | 内容 |
| --- | --- |
| 所持金バー | 全員の所持金。手番の人を強調。約束手形があれば枚数を小さく表示 |
| ルーレット | 1〜10。フリックで回す（§4） |
| 財布ボタン | 自分の持ち物一覧（職業・給料・家・保険・株・約束手形・家族）。ここから約束手形を返済できる |
| イベント表示 | 止まったマスの文面と金額をポップアップ表示（タップで閉じる。NPC・オンラインの相手は自動で閉じる） |
| 選択パネル | 分岐・職業カード・家・保険・株の選択 |

### 3.4 サウンド

生成SE（他のミニゲームと同じ `ProceduralSe`）。ルーレット回転・停止、コマの移動、お金を得る／払う、給料日、結婚・出産、ゴール、勝利。

## 4. ルーレット

* 1〜10の10等分。下部のルーレットを **フリック** すると回り、減速して止まる
* **出目はルールクラスの乱数で先に決め、回転の演出だけを出目に合わせる**（フリックの強さは回る速さと時間だけに影響する）。オンラインで全端末の出目を一致させるため（§10.2）
* フリックが弱すぎる場合は回さない（誤タップ対策）
* NPC・オンラインの相手は自動で回す演出を出す
* 家の売却（§8）も同じルーレットを使う

## 5. 盤面

### 5.1 道の形（3テーマ共通）

```text
            ゴール
              │
        区間C（共通 14マス）
              │
       ┌──── 合流 ────┐
  安全ルート       ギャンブルルート      ← 分岐②
  （10マス）        （10マス）
       └──── 分岐 ────┘
              │
        区間B（共通 16マス）
              │
   ┌────── 合流 ──────┐
 就職ルート   大学ルート    フリーター    ← 分岐①
 （8マス）   （12マス）    （6マス）
   └────── 分岐 ──────┘
              │
            スタート
```

1人が通るマス数は約46〜52マス。ルーレットの平均5.5で1人約9〜10回。

| ルート | 特徴 |
| --- | --- |
| 就職 | 先頭の「就職マス」（ストップ）で一般職のカードを2枚引いて1枚選ぶ |
| 大学 | 遠回り。途中で学費を払う。出口の「卒業マス」（ストップ）で一般職＋上級職から2枚引いて1枚選ぶ |
| フリーター | 近道。職業はフリーター（給料が低い）。転職マスで職に就ける |
| 安全 | お金のマスの金額が小さく、災難マスが少ない |
| ギャンブル | お金のマスの金額が2倍。災難マスも多い |

* 分岐ではコマが止まって道を選び、残りの歩数で進み続ける
* 道の形は `LifeBoardLayout`（ScriptableObject・マスの座標・次のマス・区間・固定/シャッフル枠）で持ち、`LifeBoardLayoutGenerator` がコードから生成する

### 5.2 マスの種類

**固定マス**（毎回同じ位置）

| マス | 止まり方 | 効果 |
| --- | --- | --- |
| スタート | - | 初期所持金を受け取る |
| 分岐 | 通過時に選ぶ | 道を選ぶ |
| 就職 / 卒業 | ストップ | 職業カードを2枚引いて1枚選ぶ（§7.1） |
| 給料日 | 通過で受け取る | 給料を受け取る。区間B・分岐②の各ルート・区間Cに計5か所 |
| 結婚 | ストップ | 結婚する。他の全員からご祝儀（§7.5） |
| ゴール | ストップ | ゴール順位ボーナス（§8） |

**シャッフルマス**（残りの枠に毎回ランダムに並べる）

| マス | 効果 |
| --- | --- |
| 収入 | お金をもらう |
| 出費 | お金を払う |
| 病気・ケガ | 出費。生命保険で無効。治療係の職業の人がいればその人に払う |
| 事故 | 出費。自動車保険で無効。取締係の職業の人がいればその人に払う |
| 火事 | 家あり：家の価格の半分を払う（火災保険で無効。修理係の職業の人がいればその人に払う）／家なし：小額の出費 |
| 出産 | 子供が1人増える。他の全員からご祝儀 |
| 家の購入 | 家を買える（§7.2） |
| 保険 | 保険に入れる（§7.3） |
| 株 | 株を買える（§7.4） |
| 転職 | 職業カードを2枚引いて、どちらかに替えるか今の職業のままにする |

* 職業の手数料：払う人自身が該当する係なら銀行に払う
* 家なしの火事は保険・手数料の対象外

### 5.3 シャッフルのしかた

* **区間ごと** にマスの種類と数の表（`LifeSectionDeck`）を持ち、その区間のシャッフル枠に並べ替えて配る。区間ごとに分けるのは、家や保険のマスが盤面の片側に偏らないようにするため
* 同じ種類のマスが3つ以上連続しないように並べ直す
* 各マスの文面はテーマの文面リストからランダムに選び、金額はマスの種類ごとの範囲（`LifeRuleSettings`）からランダムに決める。ギャンブルルートは金額を2倍にする
* 盤面はシード1つから決まる（`LifeBoardGenerator`）。オンラインではホストがシードを配り、全端末で同じ盤面にする

## 6. テーマ

### 6.1 方針

3テーマは **道の形・ルール・金額が共通** で、見た目と文面だけが違う。1テーマ＝1アセット（`Data/Themes/LifeTheme_Modern / Fantasy / Space.asset`）。2人で別々のテーマを同時に書いてもコンフリクトしないようにするため。

| テーマが持つもの | 内容 |
| --- | --- |
| 表示名・通貨単位 | 「現代」「万円」／「ファンタジー」「G」／「宇宙」「クレジット」 |
| 職業名 | 共通の職業枠（§7.1）に対する名前 |
| マスの文面 | マスの種類ごとに3〜5個の文面 |
| 見た目 | 背景・道・マスの色、コマの形（車／馬車／宇宙船） |

| 一般3（修理係） | 大工 | 鍛冶屋 | 整備士 |
| 一般4 | 料理人 | 吟遊詩人 | 配信者 |
| 一般5 | 保育士 | 農夫 | プラント員 |

## 7. お金とイベント

### 7.1 職業と給料

* 就職マスでは一般職5種から、卒業マスでは一般職＋上級職の8種から、2枚引いて1枚選ぶ
* 給料日を通過するたびに職業の給料をもらう
* 同じ職業を複数人が持ってもよい（係の手数料は、払う人以外で席番号の若い人が受け取る）

### 7.2 家

| 家 | 価格 | 売却倍率（精算時のルーレット） |
| --- | --- | --- |
| 小さい家 | 300 | 1〜3: ×0.9 / 4〜7: ×1.1 / 8〜10: ×1.3 |
| 普通の家 | 600 | 1〜3: ×0.8 / 4〜7: ×1.2 / 8〜10: ×1.6 |
| 豪邸 | 1,000 | 1〜3: ×0.6 / 4〜7: ×1.2 / 8〜10: ×2.0 |

* 家の購入マスで3種から選ぶ（買わなくてもよい）。1人1軒まで。持っていればマスは何も起きない
* 所持金が足りなくても約束手形で買える

### 7.3 保険

| 保険 | 価格 | 効果 |
| --- | --- | --- |
| 生命保険 | 50 | 病気・ケガの出費を無効。精算時に払った額の半分が返ってくる |
| 自動車保険 | 30 | 事故の出費を無効 |
| 火災保険 | 40 | 火事の出費を無効。家を持っている人だけ買える |

* 保険マスで、まだ入っていない保険を好きなだけ選んで入る。一度入れば最後まで有効

### 7.4 株（番号株）

* 株マスで1〜10の番号株を1枚買える（1枚100。1人最大3枚。同じ番号を他の人と重ねて持ってよい）
* **誰かの移動のルーレットがその番号で止まったら**、その番号の株の持ち主全員が配当50を受け取る（1枚ごと）
* 精算時に買値で売却する

### 7.5 結婚・出産・ご祝儀

| イベント | ご祝儀（他の全員から1人ずつ） |
| --- | --- |
| 結婚 | 30 |
| 出産（子供1人ごと） | 20 |

* 子供は最大4人。それ以上は出産マスで何も起きない
* 結婚は結婚マス（ストップ）で全員する。未婚のまま出産マスに止まっても子供は増える（簡略化）

### 7.6 約束手形（借金）

* 払うお金が足りないと、足りない分を自動で約束手形にする（1枚100単位で切り上げ）
* 利子はない。精算時に1枚125で返済する
* 財布から1枚100でいつでも（自分の手番中）途中返済できる
* ご祝儀が払えないときも同じ（ご祝儀を払う人の手番でなくても自動で手形になる）

### 7.7 金額（初期値・調整前提）

`LifeRuleSettings`（ScriptableObject）で持つ。単位はテーマの通貨。

| 項目 | 値 |
| --- | --- |
| 初期所持金 | 300 |
| 給料 | フリーター 60 / 一般職 120〜180 / 上級職 250〜350 |
| 学費（大学ルート） | 100 × 2か所 |
| 収入マス | 安全・共通 30〜150 / ギャンブル 60〜300 |
| 出費マス | 安全・共通 30〜150 / ギャンブル 60〜300 |
| 病気・事故 | 50〜150（ギャンブル 100〜300） |
| 家なしの火事 | 30 |
| ゴール順位ボーナス | 1位 300 / 2位 200 / 3位 100 / 4位 0 |

## 8. 精算

全員ゴールしたら、1人ずつ順に精算を演出する。

```text
① 家を売る（ルーレットを回して売却倍率を決める §7.2）
② 株を買値で売る
③ 生命保険の満期返戻（払った額の半分）
④ 約束手形を返済（1枚125）
 ↓
総資産 = 所持金（マイナスもありうる）
 ↓
順位発表 → 1位の勝利演出 → ResultDialog（共通）
```

* ゴール順位ボーナスはゴールした瞬間にもらう（精算より前）

## 9. キャラクター

### 9.1 方針

| 項目 | 内容 |
| --- | --- |
| キャラの差 | 見た目＋小さな能力（運のゲームなので差は小さく） |
| キャラ数 | 4体（3テーマ共通） |
| 同じキャラの重複選択 | 可。席の色で区別できる |
| 追加演出 | キャラ別の勝利演出（立ち絵＋セリフ） |

* 1キャラ＝1アセット（`Data/Characters/LifeChar_xxx.asset`）、一覧は `LifeCharacterCatalog`
* 席（`LifePlayerSlot`）にはカタログの番号だけを持たせる（オンラインで番号だけ送れば済むようにするため。モルックと同じ）

### 9.2 能力

| キャラ | 能力 | 勝利セリフ |
| --- | --- | --- |
| バランス | 初期所持金 +100 | 堅実な人生だった！ |
| がんばり屋 | 給料 +10% | 働いた分だけ報われる！ |
| らっきー | 移動のルーレットを1試合に1回だけ振り直せる | 運も実力のうち！ |
| しっかり者 | 出費・病気・事故・火事の支払い −10%（家・保険・株の購入には効かない） | 節約は最強！ |

* らっきーの振り直しは、出目が出た直後に「振り直す」ボタンを出す（押さなければそのまま進む）。振り直す前の出目でも株の配当は出さない（振り直した後の出目だけで判定）

### 9.3 キャラ選択画面

モルック（§03 8.4）と同じ形。P1から1人ずつ ◀▶ で選び、能力は数値ではなく1行の説明文で見せる。NPCはランダムで選ばれた状態で表示する。

### 9.4 勝利演出

モルックと同じ形（背景を勝者の席の色で暗転 → 立ち絵スライドイン → セリフ → `ResultDialog`「P1 がんばり屋 の勝ち」）。

## 10. プレイヤー設定・NPC・オンライン

### 10.1 試合前の設定（1台で遊ぶとき）

```text
テーマ選択 → 人数選択（2〜4人）→ 各プレイヤーを「人間」か「NPC」に設定 → キャラ選択 → 開始
```

* 初期状態は「2人・P1人間・P2 NPC」
* 全員NPCは不可
* 人間の手番は「P2 らっきー の番」を画面全体に出し、タップで開始（端末を回すため。モルックの `TurnBannerView` と同じ）

### 10.2 NPC

難易度はない（運のゲームで強弱の差が出にくいため）。選択を単純なルールで決める（`LifeNpcPlanner`・純粋クラス）。

| 場面 | NPCの選び方 |
| --- | --- |
| 分岐① | 大学 45% / 就職 40% / フリーター 15%（乱数） |
| 職業カード | 給料の高い方 |
| 転職 | 今より給料が高ければ替える |
| 分岐② | 所持金が全員の平均未満ならギャンブル、以上なら安全 |
| 家 | 手形なしで買える一番高い家。買えなければ買わない |
| 保険 | 買った後に所持金が200以上残るものを、生命 → 自動車 → 火災の順に買う |
| 株 | 買った後に所持金が200以上残れば、持っていない番号をランダムで1枚 |
| 振り直し（らっきー） | 出目が3以下なら使う |
| 手形の返済 | 所持金が500以上なら全部返す |

* 「○○の番」表示・イベント表示は0.8秒で自動で閉じる。選択の前に0.8秒の間を置く

### 10.3 オンライン対戦

離れた2〜4人が参加コードを共有して対戦する（人間のみ。NPCは参加しない。チーム戦はなし）。接続部分（`OnlineSession` / `ModeSelectPanel`）は共通基盤を使い、部屋作成〜開始の流れはモルック（§03 9.1）と同じ。

```text
部屋を作る（定員4人）→ 参加コードで入る → ホストが「開始」（2人以上）
 ↓
ホストがテーマを選び、テーマ番号とシードを全員へ送る
 ↓
各端末で自分のキャラだけ選ぶ → 全員揃ったら開始
```

**同期は決定論ロックステップ**（カードゲームの ADR-0002 と同じ考え方）。物理がないので、同じシード・同じ操作列を渡せば全端末で同じ結果になる。

```text
全端末が同じシードでルールクラス（盤面生成・ルーレットの出目・職業カード）の乱数を初期化
 ↓
手番の人の操作（コマンド）だけを送る
 ↓
全端末が同じ順番で同じコマンドをルールクラスに渡す
```

| 送る内容 | メッセージ |
| --- | --- |
| テーマ番号・シード（ホストから1回だけ） | `life.setup` |
| キャラ（席番号・キャラ番号） | `life.character` |
| 手番の操作（回す／分岐／職業／家／保険／株／振り直し／返済 のどれか＋選んだ値） | `life.command` |

* 出目は送らない。ルールクラスの乱数で決まるので全端末で同じになる
* NGOではクライアント同士が直接送れないため **ホスト中継**（モルックと同じ）。すべて `ReliableSequenced`
* 手番以外の人から届いたコマンド・範囲外の値は無視する
* 「○○の番」表示・イベント表示は0.8秒で自動で閉じる
* PAUSE：時間は止めずに自分の操作受付だけ止める
* 試合中に誰か1人でも接続が切れたら、全員その時点で試合終了（GAME OVER・「他のプレイヤーとの接続が切れました」）

```text
Assets/_Project/Games/05_LifeGame/
 ├ Scenes/LifeGameScene.unity   LifeGameSceneBuilder で生成
 ├ Data/                        ルール金額・盤面レイアウト（ScriptableObject）
 │  ├ Themes/                   テーマ3つ
 │  └ Characters/               キャラ4体とカタログ
 ├ Sprites/                     LifeGameArtGenerator が生成するドット絵
 ├ Scripts/
 │  ├ Rules/                    ルール計算・盤面生成・NPC（独立した asmdef。MonoBehaviour に依存しない）

 │  ├ Online/                   コマンドの送受信

```

| 場所 | クラス | 役割 |

| | RouletteInput | フリック → 回す操作 |
| | LifeAudio | 生成SE |

| | LifeRules | コマンドを受けて状態を進め、起きたこと（イベント列）を返す |
| | LifeCommand / LifeEvent | 操作の種類と値／起きたこと（表示用） |
| | LifeBoard / LifeBoardGenerator | 生成済みの盤面／シードからシャッフルして盤面を作る |
| | LifeTurnOrder | 手番計算（ゴール済みを飛ばす） |

## 12. 既知の制限

* ルーレットの出目は乱数で先に決まり、フリックの強さでは変わらない
* プレイヤー名は入力できない（席番号＋キャラ名）
* 1台で遊ぶときの先攻は常にP1
* 株の売買はできない（買うだけ。精算時に買値で売却）。株価の変動はない
* 「1回休み」「◯マス戻る」などのマスはない
* 未婚でも子供が増える
* 途中セーブ・再接続はしない
* チーム戦はない
* SEは仮の生成音
