### 章の方針（叩き台。中身は実装時にユーザーと相談して決めてよい）

| 章 | 名前（仮） | 戦場 | 主な敵 | ギミックの使い方 | ボス（6番目） |
| --- | --- | --- | --- | --- | --- |
| 1 | こおりの海岸 | 短め（18〜24）・白 | 壁・アタッカー中心。数で押す | 1-4 で開始さかな多め（速攻を体験）、1-5 で初めての遠距離の敵 | 大型1体。敵城HP 50% で出る |
| 2 | ゆきやまの奥 | 長め（24〜30）・青み | 遠距離・妨害が混ざる | なだれ、働きペンギン上限、編成制限（大型禁止）を1回ずつ | 大型＋取り巻き。敵のペンギン砲あり |
| 3 | オーロラ要塞 | 30・紫〜緑 | 大型が途中から何度も出る。倍率高め | 2つのギミックの組み合わせ（なだれ＋砲など） | 最終ボス: 敵城HP 70%・40%・10% の3段階で大型が出る |

* 敵は「ステージのテーマ」を1つ決めて組む（例: 「止める妨害がたくさん」「遠距離が壁の後ろに隠れる」）。テーマはステージの `Description` に書き、ステージ詳細で読めるようにする
* そのステージで解放されるキャラを、次のステージで役に立つように選ぶ（例: 1-4 で範囲攻撃を解放 → 1-5 は数で押してくる）

### 解放の割り振り（叩き台）

* 初期10体（Phase 3 で決めたもの）＋ 18ステージで40体
* 通常ステージ: 2体ずつ（15ステージ → 30体）
* ボスステージ: 3〜4体ずつ（3ステージ → 10体）。大型はここで配る
* 章が進むほどコストの高いキャラ・能力持ちを解放する

### 敵の強さの目安

* 倍率（`StatMultiplier`）: 第1章 1.0〜1.2 / 第2章 1.2〜1.6 / 第3章 1.6〜2.2。ボスはさらに高めでよい
* 敵城HP: 第1章 1500〜3000 / 第2章 3000〜5000 / 第3章 5000〜8000（目安。検証ツールの結果で直す）

## 進め方

1. 第1章の6ステージを書く → 検証ツールを回す → 基準（Phase 5 の実装メモ）に合うまで数値を直す → ユーザーに通しで遊んでもらう
2. 第2章・第3章も同じ順で進める（1章ずつユーザーに確認してもらう）
3. 最後に全18ステージを検証ツールで回し、勝率が章の中でおおむね下がっていく並びになっているかを見る

## 実装メモ

* 1ステージの定義は30行程度に収める。同じ敵の出方を何度も書くなら、`StageDefinitions` 内に小さいヘルパー（`Stream(no, start, interval, mult)` など）を作る
* ステージIDは一度決めたら変えない（セーブが ID で記録しているため）。並び替えたくなったら ID はそのままで `All` の順だけ変える
* 数値を変えたら検証ツールの表を引き継ぎメモに貼る（後で「なぜこの値か」を追えるようにする）

* 計画から変えた点:
  * **bot を直した（Phase 5 の物差しの変更）。** 「うまい」bot は「出せる見込みのある大型（再生産済み・さかな上限以内）がいれば、壁以外を出さずにさかなを貯める」ようにし、働きペンギンの目標を Lv5 → Lv7 にした（`BotSkill.SavesForLarge`）。前のままだと安いキャラにさかなを使い続けて大型を一度も出さず、大型を使う人間より大幅に弱い物差しになって、3章が人間には簡単すぎる調整になるため。「ふつう」は今までどおり（大型を使いこなせない初心者の目安）
  * **3章は「うまい」bot を基準にした。** 「ふつう」は大型を出さないので3章では勝ちにくい（3-2・3-5・3-6 は 0〜1/5）。3章は「うまい」が通常ステージ 5/5・ボス 4/5 になるように合わせた
  * **倍率は目安（1章 1.0〜1.2 / 2章 1.2〜1.6 / 3章 1.6〜2.2）どおりにならなかった。** 実際の値は 1章 1.0〜1.3（ボスの取り巻き 2.0） / 2章 1.0〜1.6 / 3章 0.6〜1.05。敵はお金を使わず湧くので、後半の章の高い敵（かまくら・ねむり・まほうつかい・大型）を目安の倍率で出すと、こちらの収入（ふつうで毎秒50）を大きく上回って誰も勝てなかった。難しさは倍率ではなく「出てくる敵の顔ぶれ」で上げている
  * 敵城HPも目安より低い所がある（1-1 は1500）。城HPは「大群が城に着くと10秒ほどで落ちる」ので難しさにほとんど効かず、検証ツールでも差が出なかった
  * 1-6 のボスは「城HP50%」ではなく「城HP90%」で出す。50%だと大群が城に張り付いた後に出て、ボスが暴れる前に城が落ちていた（倍率を3倍〜8倍にしても結果が変わらなかった）
  * 敵の砲は Phase 5 の注意どおり弱めた（ダメージ100・`MinTargets` 5。2-6 だけ4）
  * 敵の出方のヘルパー: `Stream(no, start, interval, mult)` / `OnCastle(no, castleRatio, interval, mult, count)` / `Boss(no, castleRatio, mult)`。キャラ No は `StageDefinitions.Units.cs` の名前付き定数で書く
* 次フェーズへの注意:
  * **自城HPがほぼ全ステージで100%。** bot は「にらみ合い → 大群で押し切る」か「押し負ける」かのどちらかで、敵が自城まで届くことがほとんどない。★2（自城HP50%以上）は人間が遊んで難しさを確かめるしかない
  * 1-5・2-4・2-5・3-6 は「うまい」でも3〜7分かかる。遊んで長すぎると感じたら敵城HPより先に敵の湧き間隔（`Stream` の3番目）を広げるほうが効く
  * ボスが3体いる 3-6 は `IsBoss` の行が3つある。ボスHPバー・ボス登場（Phase 7 の演出）は「ボスが何度も出る」前提で作ること
  * 調整の確かめ方は Phase 5 と同じ（`Tools > MiniGame > PenguinWars > Simulate Stages`）。Unity を開かずに確かめるときは、一時プロジェクトで `dotnet build` → `StageSimReport.Build` を呼ぶ小さい exe を使った
  * Unity 側のコードは一時プロジェクトで `dotnet build`（Battle・Tests・Assembly-CSharp・Editor）が通り、EditMode テストは簡易ランナーで 153 件すべて通過（Ignore 0）を確認した（エディタでの Rebuild・再生確認はまだ）
