# スキルカタログ (skill-catalog)

このプロジェクトにどんなスキルがあり、それぞれが何をするものかをユーザーに案内するスキル。
「一覧はSKILL.md本文を読まずに軽く」「詳細は対象のSKILL.mdだけ全文読んで深く」の2段階に
分けることで、無関係なスキルの本文でコンテキストを埋めないようにする。

## 1. 一覧表示

`.claude/skills/` 直下1階層（`.claude/skills/*/SKILL.md`）が対象。それより深い階層
（各スキルの `scripts/` や `agents/` など）は一覧の対象にしない。

以下のスクリプトを実行して、frontmatterだけを抽出したJSONを取得する。

```bash
python .claude/skills/skill-catalog/scripts/list_skills.py
```

出力は `[{"name": ..., "description": ..., "path": ...}, ...]` で、name のアルファベット順
にソート済み。このJSONを自分でパースし直す必要はなく、そのまま内容を使ってよい。

ユーザーには **name と description だけ** を、以下のように整形して見せる（JSONをそのまま
貼らない）。

```markdown
- 📦 **`<name>`**
  > <description>

- 📦 **`<name>`**
  > <description>

- 📦 **`<name>`**
  > <description>
...
```

一覧の最後に、「詳しく知りたいスキルがあれば名前を教えてください」のように、詳細説明に
進めることを一言案内する。

## 2. 詳細説明

ユーザーがスキル名を指定した場合、そのスキルの `SKILL.md` を **全文** 読み込む
（一覧取得時のスクリプトは使わない — 対象を絞ってから読むことでトークンを節約する）。

読んだ内容から、必要に応じて次の観点を過不足なくまとめる。無理に全項目を埋めようとせず、
そのスキルにとって説明する価値がある項目だけでよい。

- **概要**: 何をするスキルか、一言で
- **主な動作**: 実際にどう振る舞うか（手順、出力形式など）
- **使いどころ**: どんな場面・どんな発言で使うべきか
- **使い方**: ユーザー側が何をすれば起動するか（自動トリガーか、`/コマンド名` か）
- **内部的な仕組み**: スクリプトやサブエージェントを使うか、参照ファイルがあるかなど
- **関連スキル**: 下記「3. 関連スキル」参照
- **注意点**: 制約や誤用しやすい点があれば

## 3. 関連スキル

詳細説明の対象になったSKILL.md本文中で、他のスキル名（例:
「grilling/grill-meとの使い分け」のように言及されているもの）が見つかったら、
「関連スキル」として名前とひとことだけ紹介する。

関連スキルとして言及するだけで、そのSKILL.md本文を自動で読みには行かない。ユーザーが
そのスキル自体の詳細を知りたいと言ったときだけ、あらためて2の手順でそのSKILL.mdを読む。

## 4. どのスキルを対象にするか

- スキル名が明示されている（「spec-suggestの詳細教えて」など） → そのスキルを対象にする。
- 名前は出ていないが直前の会話や一覧表示の文脈から明らかに1つに絞れる（一覧を見せた直後に
  「一番上のやつ詳しく」など） → 文脈から対象を特定する。
- 曖昧で複数の候補があり得る、または一覧に存在しない名前が指定された → 推測で進めず、
  ユーザーに確認する。
- 複数のスキル名が同時に指定された場合は、それぞれについて2の手順で詳細をまとめ、
  違いを比較できるように並べて示す。

## 5. エラー・エッジケース

- `list_skills.py` は不正な `SKILL.md`（frontmatterがない、`name`/`description`が
  欠けている等）を自動でスキップし、標準エラー出力にスキップ理由を出す。個々の不正な
  スキルについてユーザーに逐一報告する必要はない。
- スキルが1件も見つからない場合、一覧表示の結果は空配列になる。その場合は
  「利用可能なスキルはありません」とだけ伝える。
- `.claude/skills/` ディレクトリ自体が存在しない、権限エラーなど、スキップでは済まない
  エラーが起きた場合は、スクリプトのエラーメッセージを踏まえて人間にわかる言葉で説明する
  （スタックトレースをそのまま貼らない）。
